# Commands

Every npm script and dev command, with details. `CLAUDE.md` keeps a short list of the everyday ones and points here.

Node is installed via nvm and is already on `PATH` in Claude Code shells (the user settings `env` pins `~/.nvm/versions/node/v24.21.0/bin`), so don't source nvm first. If `node` isn't found (for example after a Node upgrade), run `source ~/.nvm/nvm.sh` and tell the user the pinned path is stale.

- `npm install`: install all workspaces (npm workspaces: `shared`, `server`, `web`, `tools`, plus `Mush` as `@mush2/assets`).
- `npm run dev`: wrangler on :8787 plus Vite on :5173, via concurrently. Vite proxies `/parties`, `/auth` and `/api` to wrangler, so the client uses one origin as in production (sign-in setup: `docs/ops/sign-in.md`). It applies D1 migrations to the local database first. In a git worktree the ports are offset per worktree (`npm run ports` prints them) so it can run beside the main checkout's servers.
- `npm run test:browser`: the real-browser tests in `tools/tests/browser/` (Playwright and Vite in-process, about 50s), kept out of `npm test` and `verify` for their cost. Run it after changing the lobby's layout.
- `npm run test:slow`: the long random-game checks in `shared/tests/replay.test.ts` on five seeds, with every seat's view checked at every step (about 2 minutes, #382). `npm test` and `verify` run them on one seed and check one seat per step, in turn. The seed count is the `REPLAY_SEEDS` env var (`shared/tests/randomGame.ts`); CI runs this after `npm test` on every push. Run it by hand after changing `viewFor`, `fullView.ts`, `replay.ts` or the view history.
- `npm test`: Vitest in `shared`, `tools`, `web`, and `server`. Single file or test: `npm test -w shared -- rules.test.ts -t "advances the cycle"`.
- `npm run typecheck`: `tsc --noEmit` in every package (TypeScript 7). `web`'s first emits the server's API type (`npm run api-types -w server`, #324) for its typed client.
- `npm run build`: production build of `web`.
- `npm run preview`: build `web` for production, then serve it with `vite preview` beside wrangler (same ports as `npm run dev`, so stop that first). Unlike the dev server, it sends the security headers from `web/public/_headers` (CSP and friends; `securityHeaders()` in `web/vite.config.ts`), so a CSP break shows up here before a deploy.
- `npm run ship-layout`: regenerate `Mush/derived/ship-art.json` and `ship-rooms.json` from `ship-map.json` (see `web/src/iso/CLAUDE.md`, "The ship map"). A test fails if either is stale.
- `npm run webp-sheets`: regenerate `Mush/derived/webp/*.webp` (lossless WebP copies of the 7 largest PNG spritesheets, verified pixel-identical on visible pixels; run after `npm run ship-layout` if `BigFill` pages change).
- `npm run ship-check`: report-only checks on `ship-map.json` (overlaps, misaligned doors, gaps).
- `npm run layout-query -- <regex>`: search `ship-art.json` and `ship-map.json` (reading them directly is denied), capped at 60 lines.
- `npm run art-align [-- --slice NAME --each]`: how the wall, door and floor art sits on the grid, in pixels, per slice (`tools/src/play/artAlign.ts`; see `web/src/iso/CLAUDE.md`, "Directions"). Use it before judging alignment from screenshots.
- `npm run ship-render`, `npm run ship-top`, `npm run ship-view`: the ship drawn offline, from above, or in the browser; options in `web/src/iso/CLAUDE.md`, "Looking at the whole ship".
- **A finished game in dev** (for the games list and its replay, `/replay/:id`): `npm run dev`, board a multiplayer ship, then Settings > Cheats > "Return to Sol now" (`solCheat` in `shared/src/rules.ts`; dev and test only, like the other cheats). The game ends as Return to Sol ends it. For a replay with several cycle chunks, let a few cycles pass first with a short cycle: run the server with `--var CYCLE_SECONDS:20` (`server/src/cycleClock.ts`).
- `npm run screenshot`: headless Chromium screenshots as a desktop and a 360px phone player, to `.screenshots/` (gitignored). Needs `npm run dev`. The other tooling commands are in the `play` and `asset` skills.
- `npm run a11y`: headless accessibility check (`tools/src/a11y/a11y.ts`). Needs `npm run dev`. Joins a match and asserts no raw i18n keys, a "Room" region listing the room's people, equipment, items and exits, the room log as a `role="log"` with the announcer's polite and assertive live regions, no Tab stops in the license footer, and every visible control a Tab stop. Exits non-zero on failure. axe-core is not added (it needs a dependency; ask first).
- `npm run deploy:production`: build `web`, then `wrangler deploy` the server with the client as static assets (one Worker, one origin; `/parties/*` goes to the Worker). Live at <https://mush2-server.nearbearnearbear.workers.dev> since 2026-10-24 (manual deploys; test can also be deployed from CI by a manual trigger, #121, `docs/ops/deploy.md`). A bare `npm run deploy` only prints the targets and fails, so every deploy names its target. Each deploy applies that environment's D1 migrations (`server/migrations/`, append-only) before `wrangler deploy`; see `docs/ops/d1-runbook.md`. `npm run deploy:staging` and `npm run deploy:test` go to their own Workers; test is the only deployment with cheats (`ALLOW_CHEATS`), and no deployment sets `DEV_SERVER` (bot fill, looser rate limits, the dev model key). Both flags come from `--var` in the server's `dev` script, not `server/.dev.vars`.
- `npm run model-trial -w server -- --model <openrouter id> --cycles N --ledger <file> --cap <usd>`: plays a single-player game headless with real model bots on the dev key (`MODEL_API_KEY` in `server/.dev.vars`) and reports tokens, latency, cost and reply quality (#224; `server/scripts/model.trial.ts`, runs under Vitest, never in `npm test`). Costs money: always pass a ledger and cap. `--fake` checks the harness for free.
- `npm run survival -w server -- --seeds 1-50 [--days 30] [--crew 16] [--no-incidents] [--no-oxygen] [--no-hunters] [--report] [--out run.json] [--compare base.json] [--jobs N] [--verbose <seed>]`: the survival harness (`docs/plans/bot-goals.md`, "Direction", point 1). Scripted bots on every seat, no Mush, no model calls (free); prints how long each ship lasted, how it ended, death causes and when oxygen, fuel and hull ran out. A bot change is better if ships last longer on the same seeds: save a run with `--out`, then `--compare` against it. Runs under Vitest like `model-trial`, never in `npm test`; seeds run in parallel processes (`--jobs`, half the cores by default). `--verbose <seed>` traces one seed cycle by cycle. `--report` adds the loss report (hunters arriving against removed, hull lost per hunter, shots, patches, where the AP went under attack, hull by cycle); `--no-oxygen`, `--no-hunters` and `--no-incidents` each take one killer out to study another alone. The `bot-strategy` skill says how to use them.
- `npm run sim-readings -w tools`: a quick headless model of False Eden readings at the fork where True and False Eden split, printing how often the crew picks each (`tools/src/sims/readings.ts`; results and assumptions in `docs/plans/balance.md`).
- `npm run dev-state`: prints the local dev server's newest game (cycle, phase, human seats, crew with roles, titles, ship, navigation, broken equipment, fires), read-only from wrangler's Durable Object SQLite files in `server/.wrangler` (`tools/src/dev/devState.ts`). `--path players.0` prints any part of the state, `--list` shows recent rooms, `--room <prefix>` picks one, `--key <storage key>` prints a raw stored value. It shows every seat's hidden information: debugging only (the `dev-state` skill).
- `npm run ships -- --env <production|staging|test>`: the ships running now in that deployment, per language and mode, with signed-in players aboard against seats and launch time (#431, `tools/src/ops/ships.ts`, `docs/ops/observability.md`). One fixed read-only query through `wrangler d1 execute --remote` with your own wrangler login; prints room IDs, never account IDs or names. Needs `0005_ships.sql` applied there (any deploy since it landed).
- `npm run retire-ships -- --env <test|staging|production|dev> [--yes]`: retires every running ship in that deployment, as a `MIN_STATE_VERSION` bump would, without a deploy (`tools/src/ops/retireShips.ts`, `server/src/adminRoutes.ts`). Players aboard go back to the lobby, free to board; the next join launches a fresh ship; each ship's record stays for its replay; the open ship's vote round closes. Asks first unless `--yes`. Once per deployment, `--init` makes a random token, sets it as the Worker's `ADMIN_TOKEN` secret with your wrangler login and saves it to `~/.config/mush2/admin-token-<env>` (for `dev`, appends it to `server/.dev.vars`; restart `npm run dev`). A deployment without the secret has no `/admin/` routes.
- `npm run verify`: typecheck, lint and the full test suite in one call (`tools/src/dev/verify.ts`). A passing step prints one line; a failing one prints the tail of its output. The test step runs each workspace with Vitest's JSON reporter too and, after a pass, prints `slow` lines for tests over 1s and files over 3s not covered by the allowlist (warnings only; see `testing.md`, "Test cost"). Run it once, at the end of a change.
- `npm run lint`: Biome, lint only (rules in `biome.json`). Import limits: `shared` has no I/O, UI, or sibling-package imports; `web` never imports `server`, except the site API's type from `@mush2/server/api` (types only, #324). No `console.*` in `server/src` outside `log.ts` (`docs/ops/observability.md`). typescript-eslint was rejected (no TypeScript 7 support). Intentional exceptions use `biome-ignore` with a reason.
- `npm run lint:md`: markdownlint (`markdownlint-cli2`, rules in `.markdownlint-cli2.jsonc`) on the repo's Markdown, skipping `docs/scratchpad/`, the append-only `docs/process/ai-workflow.md` and the vendored PixiJS and Durable Objects skills. Separate from `npm run lint` so a doc nit doesn't block a code lint.

npm 11 blocks dependency install scripts by default. `esbuild` and `workerd` are approved in the root `package.json` `allowScripts`; new packages with install scripts need `npm install-scripts approve <pkg>`.
