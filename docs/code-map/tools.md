# Code map: tools

All under `tools/src/`.

- `shipLayout/` (`npm run ship-layout`): build-time converter. `convert.ts` turns `tiles.xml` into `ship-art.json` and writes `ship-rooms.json` from the hand-edited `ship-map.json`; `shipMap.ts` reads and writes the map (`readShip` gives art and map together; `formatShipMap` keeps one tile per line); `png.ts` (a decoder and an RGBA encoder), `xml.ts`, `haxe.ts` are hand-written decoders; `pages.ts` repacks sheets over 4096 px (`BigFill`, `BigFill2`) into `Mush/derived/pages/` so phone GPUs can load them; `check.ts` (`npm run ship-check`) prints overlaps, misaligned doors and gaps in the map (the checks themselves are in `web/src/editor/checks.ts`, shared with the editor); `validate.ts` (`validateMap`) is what a map must pass before the editor saves it (a test runs it on the committed map); `shipPlan.ts` writes `ship-plan.json`. `query.ts` (`npm run layout-query -- <regex>`) prints only the slices, tiles and bindings that match, capped at 60 lines, since reading the JSON directly is denied.
- `play/screenshot.ts`: `npm run screenshot`. `play/shipView.ts`: `npm run ship-view`. `play/shipRender.ts`: `npm run ship-render`, the iso scene drawn offline from the atlases (imports `placeScene` from `web/src/iso/placement.ts`), with wall ends that touch nothing marked. `play/shipTop.ts`: `npm run ship-top`, the same scene from above as plain shapes (floor, walls on cell edges, doors, furniture, room names, a numbered grid). `play/shipScene.ts`: what both share: loading the scene on the ship plan, and walls as cell edges with their free ends. `play/isoProbe.ts`: finding and pointing at things in the iso room through IsoRoom's dev-only probe, and waiting for the art, with either renderer.
- `contactSheet/contactSheet.ts`: `npm run contact-sheet`.
- `sims/`: headless balance models, not wired to `config.ts`. `readings.ts` (`npm run sim-readings -w tools`): honest readers against liars at the False Eden fork (`docs/plans/balance.md`).
- `assetIndex/assetIndex.ts`: `npm run asset-index`.
- `pipBar/pipBar.ts`: `npm run pip-bar`, regenerates `Mush/derived/pip-bar/*.svg` from the original pip bar sprite (a test fails if they are stale).
- `wiki/wiki.ts`: `npm run wiki`, reads eMushpedia (see the `wiki` skill).
- `odsData/`: `npm run ods-data` (`odsData.ts`; `ods.ts` reads the spreadsheets).
- `dev/`: `npm run dev` (`dev.ts`), `npm run preview` (`preview.ts`) per-worktree ports (`ports.ts`) and `npm run verify` (`verify.ts`: typecheck, lint and tests, quiet unless something fails).
- `i18n/`: catalog checks (`catalog.ts`) and the hardcoded-text ratchet (`hardcoded.ts`, `baseline.json`).
- `editor/vitePlugin.ts`: the ship map editor's save, a Vite dev-server plugin (`web/vite.config.ts`): `PUT /__editor/map` checks the map, writes `ship-map.json` and `ship-rooms.json`, and keeps its own writes from reloading pages (the editor would lose its undo history).

Tests not tied to a tool: `tools/tests/docs/docPaths.test.ts` fails if any `docs/<path>.md` named in a tracked file (CLAUDE.md files, skills, code comments, docs) or any relative Markdown link between docs points at a missing file. It skips `docs/scratchpad/` and the append-only `docs/process/ai-workflow.md`. `tools/tests/a11y/noTitleAttr.test.ts` fails on any `title=` in the client (`web/CLAUDE.md`). `tools/tests/death/hpWrites.test.ts` fails if any file outside its allowlist (`death.ts`, `cheats.ts`, `actions/heal.ts`, `actions/consume.ts`, `hunters.ts`) writes `.hp`. They live in tools because shared and web tests don't read source files.
