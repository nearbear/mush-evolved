# Code map: shared

Other packages import from `@mush2/shared` (`shared/src/index.ts`, the barrel). Inside `shared`, import types from `types.ts`.

## Engine

- `rules.ts`: `createGame`, `newPlayer` and `startInventory` (also used by `joinShip`), `applyAction` (at once, no timing), `performAction` (its mutating core), `legalActions`, `viewFor` (without log ids), `seatViewFor` (with them, a `SeatView`, replay only; Biome forbids it in `server/src`), `affordable` and `legalIn` (read a view's `actions`), `dayOf` (re-exported from `helpers.ts`), `setCheat`, `setActopiCheat`; private `advanceCycle` and `grantCarePoints`. `viewFor` is the single place hidden info is stripped.
- `actions.ts`: the action registry (`ACTIONS`), `ActionDef` / `ActionCost`, and the `Action` union, derived from the registry (`types.ts` re-exports it). `actionVisibility` and `actionInTerminal` read fixed per-type flags. A new action is a file in `actions/` registered here.
- `actions/action.ts`: the `Action` base class (`getCandidates`, `validate`, `getCost`, `apply`, optional `getSuccessChance` and `fail`; `check` is `validate` then the price, never overridden). The constructor takes a check per field (`Fields`, `isString`, `isBoolean`), which `parse` uses to rebuild an action from untrusted client input; `terminal` marks actions done in a terminal's window.
- `actions/capsule.ts`: `carriedCapsule` and `combustionLevel`, for the fuel and oxygen actions.
- `blueprints.ts`: `BLUEPRINTS` recipes (ingredients and resulting equipment) and the `blueprint` item type name.
- `actions/<type>.ts`: one class per action: `reset_skills`, `accommodate` (+ `accept_accommodation`, `stop_accommodation`), `access`, `bond`, `build`, `check_combustion`, `consume`, `cook`, `express_cook`, `water`, `treat`, `sow`, `dismantle`, `dispense`, `play_arcade` (the Dynarcade), `examine`, `consume_spore` (the Mush skill Phagocytosis), `tube_transfer` (the pneumatic tube), `extract_spore`, `heal`, `use_bandage` (a consumable heal), `install`, `jettison`, `lie_down` (+ `get_up`), `uninstall`, `move`, `pick_skill`, `apprenticeship` (the Apprentice skill), `become_genius` (the Genius skill), `read_book`, `tear` (destroys a document, #394), `snoop` (the Scrapper's Snoop), `check_spores` (the MycoScan's spore check), `warp_to_planet` (development-only, the `easyTravel` cheat), `project`, `repair_pilgred`, `return_to_sol`, `contact_sol`, `decode_rebel`, `contact_xyloph`, `update_neron`, `set_bios`, `scan_planet`, `analyze_planet`, `delete_planet`, `turret_attack`, `patrol_attack`, `collect_scrap`, `renovate` (a docked patrol ship back to full armor), `open_capsule` (the space capsule), `repair_hull`, `turn_ship`, `travel`, `leave_orbit`, `take_fuel` (+ `load_fuel`, `unload_fuel`, `return_fuel`), `take_oxygen` (+ `return_oxygen`), `punch`, `attack` (weapons), `ready`, `research`, `share` (`dtt`, `stt`), `shower`, `spike`, `body_transfer` (the Mush skill Transfer), `transfer` (`take`, `drop`), `upgrade_drone` (a Robotics Expert fits a drone upgrade, #412).
- `modifiers.ts`: the modifier registry and its hooks (numeric ones go through `fold`; `moveCost` is the one place a move's price is computed).
- `modifiers/<id>.ts`: one file per modifier: `paranoid` (one camera item on pick), `observant` (cheaper Search; its covert-reveal roll is in `log.ts` `logCovert`), `green_thumb` (two hydropots on pick), `robotics` (a support drone blueprint on pick), `astrophysician` (cheaper scan, extra analysis sector), `antic_perfume`, `caffeinomaniac`, `cold_disease` (1-in-3 chance to lose MP each cycle), `computer`, `cook` (+4 Cook points on pick and each day), `pilot` (clean patrol-ship manoeuvres), `engineer` (doubled renovation odds), `gunner`, `gunman` (Shoot points), `persistent` (`failureStreakMultiplier`), `space_tactics` (`crewWaveShrinkChance`), `polymath` (channels, Computer points and cap), `designer` (Designer points), `sprint`, `physicist` (PILGRED points), `botanic` (garden points), `creative`, `first_aid`, `expert` (+20% success, dirt and injury chances), `logistics` (AP gifts each cycle), `maintenance_agent` (+1 Engineer, Garden, and Cook point a day and 1 of each on pick), `lying_down`, `lethargy` (doubled AP cap, +1 AP a cycle from the 4th cycle change in bed, counted from `PlayerState.lyingSince`), `immunity`, `mankind_only_hope` (a crew-wide `crewMoraleLoss` effect), `medic`, `mycologist` (`onHeal` contamination removal), `opportunist` (`onTitleGained` AP bonus), `pacifist` (a room cost effect), `bodyguard` (+2 AP surcharge on aggressive actions targeting the VIP in the same room), `sturdy`, `wheelchair` (no hooks; marks who can be pushed); `careSkill.ts` is the factory behind `first_aid`.
- `setups.ts`: setups (#227, #233): the knobs and `parseSetupKnobs`, `Setup` (a name and description per language, the owner's display name, version chain), `validateSetup`, `setupOverrides` for a game's config, `knobsDiff`; and for posting, `moderateSetupTexts` (chat moderation per field, caps checked again after), `parsePostSetup`, the caps (`MAX_SETUPS_PER_ACCOUNT`, `MAX_SETUP_POSTS_PER_ACCOUNT`) and the `/api/setups` response types; for the vote round (#236), `countVotes` and `tallyVotes` (most votes, a tie drawn with an injected random number, standard when none count).
- `finishedGames.ts`: the finished games list's types (#155): `FinishedGame`, `FinishedCrewMember` (start and end character and role), `FinishedGamesResponse` (`GET /api/games`), `MAX_GAMES_PAGE`, and `crewRoleLabel` (alpha Mush, beta Mush or Human, by the role at the end).
- `replay.ts`: `Input`, `GameSetup`, `applyInput` (the only entry point for changing a game), `replayGame`; `RecordedInput` (an input with its server time), `stampEntries` (the server's timestamps on new log and chat entries), and `rebuildGame` (the exact stored state from `setup` and the record, stamps included; #167).
- `spot.ts`: where you stand in your room: the free `walk` input, `standUp` (a public action gets you off a chair), `arrive` (in front of the door you came in by), `occupy` (opening a terminal sits you on a free chair there, #192) and `terminalChairs`.
- `actionTarget.ts`: what an action's fields name (`namedTarget`, which the inspect panel uses too), what it is done to (`actionTarget`, which the client walks you up to), and `endsAccommodation` (a public action on equipment or another person ends a wheelchair push).
- `queue.ts`: timed actions: `queueAction`, `actNow` (an action at once with the untimed path's hooks), `clearQueue` (optionally telling the player, through `queueCore.ts`), `dropQueues` (every player's, the server input a restart records, #384), `tick` (also runs expedition steps due), `nextDue` (when the server's alarm should fire, expedition steps included); cancels a queued action whose modifier adjustment changed (`repriced`).
- `mycoalarm.ts`: the `myco_alarm` item, `ringMycoAlarms` (called by `performAction` for `spore`-tagged actions) and `dropMycoAlarms` (research yield).
- `actions/hide.ts`, `actions/search.ts`: hiding a carried item in the room (`ItemState.hiddenBy`) and searching the room for hidden items.
- `research.ts`: `RESEARCH_IDS` (the researches with card art), `RESEARCH_COMPLETE`, and `RESEARCH_REQUIRES` (items, Chun, post-selection each research needs; checked by `researchAllowed` in `actions/research.ts`).
- `planets.ts`: the Astro terminal's planets: `PLANET_TAGS` (weights, seek, max and expedition `explo` weight from the original), `generatePlanet` (the original's `getPlanet`, seeded), `pickSeekSector` (what an analysis reveals), `planetsOf`, `astroTerminalsHere`, `planetPicture` (cosmetic picture index, from the name). Actions `scan_planet`, `analyze_planet`, `delete_planet` (docs/plans/astro.md).
- `sharedPlanets.ts`: sharing planets in the Astrophysics feature: `sharePlanet` (the `sharePlanet` input), `canSharePlanets`, `markSharedPlanetsStale` (called by `jump` in `actions/travel.ts` and by `leave_orbit.ts`), `MAX_SHARED_PLANET_LENGTH`/`LINES`.
- `sharedReports.ts`: sharing expedition reports in the Expeditions feature: `shareReport` (the `shareReport` input; the first share makes the entry, later ones append to its thread), `canShareReports`, `REPORTS_FEATURE`.
- `botany.ts`: plants in hydropots: `isBotanistRole` (who sees sickness), `isPlanted`/`isEmptyPot`/`isFruit`, `potRoom`, `paidWithGardenPoint`, `plantView` (strips `sick`), `growCyclesFor` (alien fruits from `state.fruits`, else `config.botany.growCycles`), `botanyCycle` and `botanyDay` (called from `advanceCycle`). Actions `water`, `treat`, `sow`.
- `navigation.ts`: steering at the Command terminal: `turned` (a quarter turn), `canSteer` (the Commander, through `hasTitleAccess`), `planetAt`, `orbitPicture` (the public `navigation.orbitPicture`). `jump` in `actions/travel.ts` is a jump without the fuel, shared with `warp_to_planet`. Actions `turn_ship`, `travel`, `leave_orbit`; state `GameState.navigation` (heading, orbited planet id).
- `relay.ts`: relay progress (`docs/plans/relay-tokens.md`): relay tokens (`RelayToken`, `RelayPool`, `Sample`, `ResearchPool`, `tokenBase`, `makeToken`, `arrangeTokens`, `poolProgress`, `contributionGain`, `contribute`) shared by research and PILGRED (`GameState.relay.research`, `pilgred.pool`), and direct streak relay (`RelayStreak`, `relayGainRange`, `rollRelayGain`, `touchRelay`) used by NERON projects (`GameState.relay.projects`).
- `assay.ts`: research samples and assays (`docs/plans/research-sabotage.md`): `researchProgress` (verified and pending), `nextMark`, `assayDue`, `runAssay` (noise rolls, survivors verified), `contaminationCandidates` and `contaminate` (Saboteur). The research action's `addSample` (`actions/research.ts`) runs them and completes the research; `actions/spoil_research.ts` (own spoil) and `actions/contaminate.ts` (Saboteur) are the Mush actions.
- `relayView.ts`: `relayView`, the view's `research`, `projects` (completed + `offeredProjects`), `pilgred`, `relay` and `yourTokens` (`research` and `pilgred`), gated to the target's room.
- `dispense.ts`: coffee and dispenser regeneration helpers: `coffeeRegenCycles`, `lastCoffeeRegenCycle`, `isDispenserReady`.
- `pilgred.ts`: PILGRED's repair: `PILGRED_COMPLETE`, `PILGRED_SKILLS`, `isPilgredRepaired`, `pilgredTerminalsHere`, `commandTerminalsHere`, `canReturnToSol`. Actions `repair_pilgred`, `return_to_sol`.
- `comms.ts`: the communication center: `REBEL_BASES` (call order), `XYLOPH_ENTRIES` (weights), `newComms`, `callNextRebel` / `commsCycle` (daily rebel calls), `endRebelCalls` (travel and leaving orbit), `solChance` (Radio Expert), `loseLink`, `rollRebelGain`, `rebelReached`, `rationApBonus` (Sirius), `noITrackieNeeded` (Luyten-Ceti), `drawXyloph` / `applyXyloph`, `advanceNeron`, `commsTerminalView`. Actions `contact_sol`, `decode_rebel`, `contact_xyloph`, `update_neron`.
- `hunters.ts`: hunters and turrets: `newHunter`/`newHunters`, `spawnWave` (the weighted draw of kinds), `hunterAction` (one pick-or-shoot), `arackAround`, `shootingHunters` (everything but asteroids), `asteroidImpact`, `startHunters` (at the game's start), `huntersCycle` (called from `advanceCycle`: hunter turns, turret and docked patrol-ship recharge (`rechargePatrolShips` in `patrol.ts`), shield regeneration, the wave pool and roll, hull 0), `damageHunter` (drops debris into `state.space`), `huntersFollow` and `loseShipsInFlight` (from `travel` and `leave_orbit`), `destroyPatrolShip` and `retargetHunters` (patrol ships shot down or landing), `huntersPerCyclePoints`, `turretsHere`/`allTurrets`/`turretCharges`, `rollRange`. Actions `turret_attack`, `repair_hull`; `ship.ts` has `damageShip` and `shieldAbsorbPercent`.
- `expeditions.ts`: expeditions, phases 1 and 2 and phases 3 and 4's slices A to D (docs/plans/expedition.md): `canLaunchExpedition` (Pilots, the one place to widen it), `orbitedPlanet`, `hasUnexplored`, `pickCrew`, `pickSectors` (by `explo` weight), `runExpedition` (the takeoff: the crew into the Icarus room, the report, `GameState.expedition`; all at once with `instantExpeditions`), `expeditionStep` (the landing or one sector, from `tick` in queue.ts; events, fights against `config.expedition.creatures`, damage, loot), `winChance` (a fight's odds), the return (living crew and the Icarus's floor back to the bay, dirt), `strandExpedition` (a jump with a crew out: Magnetic return, or the crew dies and the Icarus is lost, `icarusLost`), getting lost and finding the lost (`getLost`, `find`; `lostPlayers` the living lost, `withCrew` alive and in the Icarus), the lost dying when the ship leaves (`abandonLost`), gear (`needsSpacesuit`, `explores` the members who take part, `cancelled` and `eventWeight` for gear and skills), `expeditionReturnAt` (the public return time), skills (Shooter and Centauri in `fight`, Sprinter at takeoff, `turnBack` for U-turn, `sabotage` for the Traitor, `onExpedition`). Actions `icarus_takeoff` (`actions/icarus_takeoff.ts`), `u_turn` (`actions/u_turn.ts`) and `sabotage_expedition` (`actions/sabotage_expedition.ts`).
- `actions/land_on_planet.ts`: a pilot lands their flying patrol ship on the orbited planet alone (expeditions, phase 5, #359): an expedition through `runExpedition(state, pilot, ship)`, with the ship's room as its craft (`expeditionCraft`); `dock` in `actions/land.ts` brings it home, `loseShipOnPlanet` in `death.ts` loses it with its pilot.

- `patrol.ts`: patrol ships and the Pasiphae (data and lookups only, so `config.ts` can import it): `PATROL_SHIPS`, `interfaceId`/`commandId`, `patrolRooms`/`patrolEquipment` (their door-less rooms in the config), `ICARUS_CRAFT` (the Icarus's room while away) and `inCraft` (a patrol ship's or the Icarus's room), `lostPlace`/`isLostPlace` (a lost member's own place, `LOST:<playerId>`) and `offShip` (a craft or a lost place: no build, install or ignite), `newPatrolShips`, `shipsInFlight`, `canFly` (Pilots), `dockedHere`, `shipAboard`. Actions `takeoff` (also exports `board` and `manoeuvre`, the clean-or-rough roll through `cleanManoeuvreChance`), `land` (unloads the ship's room) and `collect_scrap`; `modifiers/pilot.ts` (docs/plans/patrol.md).

- `breakage.ts`: broken equipment: `isBreakable`, `workingBreakable`, `breakEquipment` (NERON's chat notice, Com center link), `leakOxygen`. `isBrokenIn` is in `equipment.ts`, read by `Action.check` (`BROKEN`). Action `repair` (`actions/repair.ts`).

- `mind.ts`: minds and bodies: `bodyOf` (the body a seat plays; the server resolves every token through it), `swapMinds` (a Transfer), `acknowledgeTransfer` (the victim's pop-up input).
- `rng.ts`: the seeded RNG (its state is part of `GameState`): pair functions `nextFloat`, `nextInt`, `rollRange`, `shuffle` return `[value, next]`; the `roll`, `rollInt`, `rollFloat`, `rollShuffle` helpers advance a `HasRng` holder (a `GameState`) in place, so a draw can't drop the next state. Rule code that draws from `state.rng` uses the helpers; the pair functions are for seeded generators that take a bare seed (`planets.ts`, `createGame`'s seed, `singlePlayerGame`). `streamFor(seed, name)` hashes the game seed and a name into the start of a stream of its own, for setup draws that must not move `state.rng` (`createGame`'s `"drugs"`, `"fruits"` and `"medlab-stock"`).
- `helpers.ts`: `ActionResult`, `fail`, `clone`, `findPlayer`, `dayOf`.
- `paths.ts`: `shortestPath` (deterministic BFS over `config.rooms`, taking a target room or predicate; null for the door-less patrol craft), for the summons walk and Sensor drones.
- `situation.ts`: where things are and what reaching them costs, from one player's own view and the public `SHIP_ROOMS` (`doorCount`, `travelAp`, `canAfford`, `nearest`, `roomsWith`). Shared by the bot goals and the tips.
- `tips.ts`: the tips catalog (#351): `tipsFor(view)` lists the tips that apply, highest priority first, each with the nearest room to go to; `ONCE_TIPS` are dismissed for good. Computed on the client from the player's own view; text only states implemented rules.
- `queueCore.ts`: the queue parts action classes may import without a cycle: `emptyQueue` (with `actionDropped` lines on request) and `dropped`.
- `normalizeState.ts`: normalizing a stored snapshot on load (#384, docs/plans/normalize-state.md): helpers (`AllKeys`, `need`, `added`, `stripUndefined`, `dict`, `mapValues`, `NormalizeError`) and one normalizer per stored type, up to `normalizeCore` (the `GameCore` a game and a replay frame share) and `normalizeGame` (a stored game plus its overrides back to a `GameState`; drops every action under way and queued), `normalizeFullView` (a replay frame, its config rebuilt through `overridesOf`; keeps the queues), then `STATE_VERSION` (116), `MIN_STATE_VERSION` (older snapshots are dropped on load) and the upgrade steps (`UPGRADE_STEPS`, currently `upgradeTo116`; `upgrade` runs those after a snapshot's version, in order, and throws `TooNewError` for a newer one; `normalizeFrame` does the same for a replay frame, on a copy, then `normalizeFullView`). `hasQueues` says whether a load drops any action, so `GameRoom.onStart` records a `dropQueues` input. The header holds the file's rules.
- `fullView.ts`: the full-state view for replays (#334): `fullViewFor(state, starts)` (the state without its RNG, plus each seat's role and character when the Mush were chosen, `seatStarts`) and `perspective(full, seat)`, a `SeatView`: `viewFor` plus each log line's id (Biome forbids it in `server/src`; tested at every step of a random game in `replay.test.ts`). It shows every hidden thing: only for an ended game, through the replay route (#337); nothing sends one yet.
- `viewDiff.ts`: the replay history's JSON diff (#335), no dependency. `diffView(prev, next)` describes objects by changed and deleted keys and arrays as removals (chat's per-channel trim, a body's action history), in-place patches and an append (log and chat only grow); `applyDiff` builds a new value, sharing what didn't change; `jsonEqual` (undefined keys count as missing).
- `viewHistory.ts`: `HistoryStep`, each input's part of the replay history (`RecordedInput.history`): a full copy at each `cycle` input, the loaded view (`base`) plus a change for the first input after a room start, otherwise a change; copies carry `HISTORY_VERSION` and the `BuildStamp` of the build that recorded them (`stateVersion`, `rulesVersion`; #384). `historyStep` builds one, `rebuildHistory` rebuilds the full view after each step (`HistoryError` for another format version), each frame with its copy's stamp (`build`, null before stamps), and `readFrame` brings the frame on screen to this build's shape (`normalizeFrame`, memoized; anything unreadable is a `HistoryError`). `perspective` and `revealFor` take its result; `stepMarks` and `lineStep` read frames as recorded. The replay index also records `stateVersion`.
- `replayChunks.ts`: a finished game's history as copied to R2 (#336, `docs/ops/r2.md`): `ChunkBuilder` (splits the record at each full copy as it is read, so the server can page), `chunkHistory`, `replayIndex` (`ReplayIndex`: format version, room, rules version, end time, `realTime` (cycles ran on a clock: multiplayer, so the replay shows a countdown), seats' start roles and characters, `ChunkInfo` per chunk), `ReplayModeration` / `BlockedText` (`moderation.json`: `raw` by `chatId`, `rawByInput` by input sequence, `blocked`, `rateLimited`, #339, #157) and `replayKeys`. A chunk entry is only `{ at, history }`.
- `replayView.ts`: the replay page's helpers (#367, `docs/plans/replay-viewer.md` story 1). Shows every hidden thing by design; Biome forbids it in `server/src`. `revealFor(full, seat, streams?)`: all-seeing, the seat's `perspective` plus every hidden line of its room, its own lines elsewhere and every channel, with a separate `Reveal` (each body's own `you`, statuses, inventory and contamination; who saw each non-public line and message). `streamsOf` / `mergeStreams`: log and chat collected by id across frames. `stepMarks` (event marks with a kind, by highest id, never on a restart's base), `lineStep` (the step that first holds a line or message), `seatsAt` (who plays whom, Transfers marked).
- `plans.ts`: channel plans (docs/plans/on-call.md): `postPlan`, `openPlan`, `findPlan`, `finishPlan` (keeps `config.plans.finishedKept`), hooks `leavePlans` and `dropChannelPlans` (from `removeFromChannel`), `strikeSlots` (after actions, cycles and deaths), `expirePlans` (day tick), `plansView`. Posting arrives as the `postPlan` message (`protocol.ts` calls `parsePlanDraft` here, which rebuilds the draft with known keys only; an `applyInput` case in `replay.ts`). Actions in `actions/plan_slots.ts` (`claim_slot`, `withdraw_slot`, `mark_done`, `cancel_plan`) and `actions/summon.ts` (`summon` and its `walk`; `performAction` bound by rules.ts).

## Rule areas

- `chat.ts`: chat storage in fixed pages (`CHAT_PAGE`, `pushChat` seals a full page into `chatOutbox` for the server to store as `chatPageKey`, #355), checklist ticks kept beside the chat (`chatMarks`, `taskLines`, `markedText`; `messageView` in `rules.ts` draws them into the text; `chatPageSource`/`chatPageView` there answer a `chatPage` request), channels (`chatChannels` to post, `readChannels` to read), `sendChat`, threads under global chat (`createThread`), private channels, limits.
- `death.ts`: `damage` (the one way HP goes down) and `killPlayer`, both taking a `DeathCause` (`DEATH_CAUSES`, #177).
- `infection.ts`: `contaminate` (the one way contamination rises), conversion, `contaminationSeenBy`.
- `items.ts`: item types, containers, capacity and reach helpers, `produceItem`, `removeItem`, `newItemId`.
- `fruits.ts`: the 12 seeded alien fruit species (`ALIEN_FRUIT_ITEMS`, `FRUIT_BUFF_IDS`, `FRUIT_LORE_SKILLS`): `drawFruits` (budget-filtered draw on the `"fruits"` stream), `fruitEffectsSeenBy` (living Botanist, Skilful, Chef and Mush), and `applyFruit` (AP/morale/HP bonuses, non-stacking buff timers, delayed diseases).
- `itemIds.ts`: dependency-light IDs used by item definitions and the default config.
- `equipment.ts`: room equipment types, `SUPER_CALC_EQUIPMENT`, and `equipmentHere` (equipment of a type in the player's room).
- `log.ts`: room log helpers (`pushLog`, the one writer, which gives each line its `LogEntry.id` from `nextLogId`; `logPublic`, `logPrivate`, `logSecret`, `logCovert`, `hasCamera`; the room-log window `seesLine`, `logWindowOf`, `inLogWindow`, `pruneLog`, and `logSeen` counting, #365; each writer sets `LogEntry.kind` and `leaked`, #366, tested in `logKind.test.ts`).
- `history.ts`: each body's action history (`recordAction`, called from `performAction`) and `revealHistory`, the private reveal lines Interrogate and Chitchat write.
- `resources.ts`: per-player skill point pools.
- `skills.ts`: the human skills, each character's pickable list (`CHARACTER_SKILLS`), `SKILL_SLOTS`, the Mush skills (`MUSH_SKILLS`, `MUSH_SKILL_SLOTS`), and `skillsOf`/`hasSkill` (picked skills, the book slot, and Mush skills).
- `titles.ts`: `TITLE_IDS`, each title's line (`SUCCESSION`), `successor` (pure), `assignTitles` (at creation) and `refreshTitles` (after a death, going inactive or coming back).
- `statuses.ts`: stored and derived statuses.
- `inactivity.ts`: inactive and super inactive (#145): `isInactive`, `isSuperInactive`, `inactivityOf`, `inactivityCycle` (from `advanceCycle`, given the clock cycle's server time), `markSeen`, and the server's `seen` and `inactivate` inputs.
- `morale.ts`: `hopelessCycle`, death at 0 morale (Hopeless humans die when a cycle ends; each death costs every living player morale). `isHopeless` is in `statuses.ts`.
- `adjustStats.ts`: capped morale, AP and MP changes and max-value updates.
- `diseases.ts`: `DiseaseTracker`, `addDisease` (updates both the modifier and private status), `removeDisease`, `treatDisease` and the per-cycle tracker countdown.
- `cheats.ts`: development cheats (issue #148), gated by `ALLOW_CHEATS`. Flag-only cheats are read where they apply: `instantActions` in `queue.ts`, `noRelayPenalty` in `relay.ts` (`makeToken` and `touchRelay`), `freeHacking` ("Unrestricted terminals") in `titles.ts` (`bypassesTitles`), `actions/research.ts` (`researchAllowed`), and `projectEffects.ts` (`offeredProjects`), `anySkill` in `actions/pick_skill.ts`, `easyTravel` in `actions/warp_to_planet.ts` and `actions/leave_orbit.ts`. `alwaysClean` strips `dirty` in `applyCheats`. `fastExpeditions` is ship-wide (anyone with it on): `expeditions.ts` steps every 2 s (`FAST_EXPEDITION_STEP_MS`), and switching it on mid-expedition pulls the next step in. Two cheats are calls rather than flags: `setRoleCheat` and `solCheat` (in `rules.ts`; the ship returns to Sol now, a dev route to a finished game).
- `cheatRoom.ts` and `cheatStock.ts`: the cheat room (#170, dev ships only). `cheatRoom.ts` is data only, so `config.ts` can import it: `CHEAT_ROOM`, `SUPERKUBE`, `cheatRoomEquipment` (only the Superkube; the room starts with no items, owner 2026-11-14). `resolveConfig` adds the room with no doors when `ConfigOverrides.cheatRoom` is set (`GameRoom.launch` sets it wherever cheats are allowed). `cheatStock.ts` has `cheatItem`, the Superkube's spawned item (a blueprint or skill book gets the first recipe or skill). Its layout is `Mush/derived/cheat-room.json`, not in `ship-map.json` (see `web/src/iso/shipLayout.ts`). `daedalusRooms` (`fire.ts`) leaves it out, so incidents, fires and breakdowns never pick it. The `cheatRoom` input (`cheatRoomCheat` in `rules.ts`, gated by the server like `solCheat`) takes the sender there: free, no log line, out of bed first, refused off the ship or in a push.
- `kube.ts`: the Superkube's options (#170), each a `kube` cheat input, never an action. `KUBE_OPS` is the one table (group, argument kind, apply): ailment, cure, hp, morale, ap, mp, dirty, contaminate, spawn, teleport. `applyKube` refuses without the room, from a bot, the dead, or anyone outside the cheat room, and checks the argument against `kubeChoices` (the ship's ailments, `ITEM_TYPES`, or the Daedalus rooms with the Laboratory first). `teleport`/`teleportBlocked` are the no-door, no-log room change that `cheatRoomCheat` also uses. The server gate (`GameRoom.onMessage`) also refuses bot seats and senders outside the room. It replaced the old `selfDisease` cheat and its Self Disease and Self Injury actions (`upgradeTo117` drops the flag from stored games). The window is `web/src/hud/Superkube.tsx`.

## Types, config, and data

- `types.ts`: the small shared vocabulary; re-exports `types/`.
- `types/config.ts`: `GameConfig`, `MovementRules`, `Equipment`. Tuning is nested by feature (`config.punch.cost.ap`, `config.punch.effect.damage`, a [min, max] range).
- `types/player.ts`: `PlayerState`, `ResourceId`.
- `types/chat.ts`: channel and message types (`ChatLine` is a message as a live view carries it: `seq`, never the game-wide `id`).
- `types/plan.ts`: `Plan`, `PlanSlot`, `PlanTask`, `PlanDraft`, `PLAN_PURPOSES`.
- `types/state.ts`: `GameState` (server-only).
- `types/view.ts`: `PlayerView`, `OtherPlayerView`, `ItemView`: the only game data a client or bot receives.
- `config.ts`: `DEFAULT_CONFIG` and `PRESELECTION` (a multiplayer ship's pre-selection rules: 16 seats, day 3). The map comes from `@mush2/assets/derived/ship-rooms.json`.
- `protocol.ts`: wire message types and `parse*` validators for untrusted client input; actions go through `ACTIONS[type].parse`.
- `moderation.ts`: `moderateChat`, called by the server, not the rules; `moderateName`, called by `viewFor` for the end screen's names.
- `characters.ts`: cosmetic crew identities, no rules effect.
- `names.ts`: room, equipment, item and skill display names per ship language (`NAME_CATALOGS`, from `locales/names.{en,fr,es}.json`; `roomName`, `itemName`, ...). Web merges them into its i18next catalogs; the server's bot prompts use them so bots say what players see.
- `shipLayout.ts`: types for `Mush/derived/ship-art.json` and `ship-map.json` (`ShipLayout` is the two together) and `placedEquipment`.
- `actions/speech.ts`: the Leader's Fiery speech and the Motivator's Boring speech (room-wide morale and MP gifts; `PlayerState.boringToday`).
- `actions/interrogate.ts`: the Torturer's Interrogate (1 damage, reveals the target's last actions, one per missing HP; `interrogatedToday`).
- `actions/chitchat.ts`: Chitchat with a Confident (+2 morale, the Confident learns your last actions, one per point of their morale; `chitchatToday`).
- `actions/comfort.ts`: Comfort, the Shrink's action (+2 morale to a roommate, 1 AP, no daily limit). The Shrink's lying-down morale is `onCycle` in `modifiers/lying_down.ts`.
- `actions/coup.ts` and `coup.ts`: the Politician's Coup (`PlayerState.coupPending`) and its cycle-change resolution into the Commander title.
- `actions/anathema.ts`: the Persecutor's Anathema (the Outcast status, `PlayerState.outcastBy`).
- `actions/protect.ts`: the Bodyguard's Protect (`PlayerState.protectedBy`, `protecting`/`protected` statuses).
