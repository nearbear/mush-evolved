# Code map: shared

Other packages import from `@mush2/shared` (`shared/src/index.ts`, the barrel). Inside `shared`, import types from `types.ts`.

## Engine

- `rules.ts`: `createGame`, `newPlayer` and `startInventory` (also used by `joinShip`), `applyAction` (at once, no timing), `performAction` (its mutating core), `legalActions`, `viewFor`, `affordable` and `legalIn` (read a view's `actions`), `dayOf` (re-exported from `helpers.ts`), `setCheat`, `setActopiCheat`; private `advanceCycle` and `grantCarePoints`. `viewFor` is the single place hidden info is stripped.
- `actions.ts`: the action registry (`ACTIONS`), `ActionDef` / `ActionCost`, and the `Action` union, derived from the registry (`types.ts` re-exports it). `actionVisibility` and `actionInTerminal` read fixed per-type flags. A new action is a file in `actions/` registered here.
- `actions/action.ts`: the `Action` base class (`getCandidates`, `validate`, `getCost`, `apply`, optional `getSuccessChance` and `fail`; `check` is `validate` then the price, never overridden). The constructor takes a check per field (`Fields`, `isString`, `isBoolean`), which `parse` uses to rebuild an action from untrusted client input; `terminal` marks actions done in a terminal's window.
- `actions/capsule.ts`: `carriedCapsule` and `combustionLevel`, for the fuel and oxygen actions.
- `blueprints.ts`: `BLUEPRINTS` recipes (ingredients and resulting equipment) and the `blueprint` item type name.
- `actions/<type>.ts`: one class per action: `accommodate` (+ `accept_accommodation`, `stop_accommodation`), `access`, `bond`, `build`, `check_combustion`, `consume`, `cook`, `express_cook`, `water`, `treat`, `sow`, `dismantle`, `dispense`, `examine`, `extract_spore`, `heal`, `install`, `jettison`, `lie_down` (+ `get_up`), `uninstall`, `move`, `pick_skill`, `read_book`, `snoop` (the Scrapper's Snoop), `check_spores` (the MycoScan's spore check), `self_disease` (development-only Self Disease), `self_injury` (development-only Self Injury), `warp_to_planet` (development-only, the `easyTravel` cheat), `project`, `repair_pilgred`, `return_to_sol`, `contact_sol`, `decode_rebel`, `contact_xyloph`, `update_neron`, `set_bios`, `scan_planet`, `analyze_planet`, `delete_planet`, `turret_attack`, `patrol_attack`, `collect_scrap`, `renovate` (a docked patrol ship back to full armor), `open_capsule` (the space capsule), `repair_hull`, `turn_ship`, `travel`, `leave_orbit`, `take_fuel` (+ `load_fuel`, `unload_fuel`, `return_fuel`), `take_oxygen` (+ `return_oxygen`), `punch`, `attack` (weapons), `ready`, `research`, `share` (`dtt`, `stt`), `shower`, `spike`, `body_transfer` (the Mush skill Transfer), `transfer` (`take`, `drop`).
- `modifiers.ts`: the modifier registry and its hooks (numeric ones go through `fold`; `moveCost` is the one place a move's price is computed).
- `modifiers/<id>.ts`: one file per modifier: `paranoid` (one camera item on pick), `green_thumb` (two hydropots on pick), `astrophysician` (cheaper scan, extra analysis sector), `antic_perfume`, `caffeinomaniac`, `cold_disease` (1-in-3 chance to lose MP each cycle), `computer`, `pilot` (clean patrol-ship manoeuvres), `engineer` (doubled renovation odds), `gunner`, `gunman` (Shoot points), `persistent` (`failureStreakMultiplier`), `space_tactics` (`crewWaveShrinkChance`), `polymath` (channels, Computer points and cap), `designer` (Designer points), `sprint`, `physicist` (PILGRED points), `botanic` (garden points), `creative`, `first_aid`, `expert` (+20% success, dirt and injury chances), `logistics` (AP gifts each cycle), `lying_down`, `lethargy` (doubled AP cap, +1 AP a cycle from the 4th cycle change in bed, counted from `PlayerState.lyingSince`), `immunity`, `mankind_only_hope` (a crew-wide `crewMoraleLoss` effect), `medic`, `pacifist` (a room cost effect), `sturdy`, `wheelchair` (no hooks; marks who can be pushed); `careSkill.ts` is the factory behind `first_aid`.
- `setups.ts`: setups (#227, #233): the knobs and `parseSetupKnobs`, `Setup` (a name and description per language, the owner's display name, version chain), `validateSetup`, `setupOverrides` for a game's config, `knobsDiff`; and for posting, `moderateSetupTexts` (chat moderation per field, caps checked again after), `parsePostSetup`, the caps (`MAX_SETUPS_PER_ACCOUNT`, `MAX_SETUP_POSTS_PER_ACCOUNT`) and the `/api/setups` response types.
- `finishedGames.ts`: the finished games list's types (#155): `FinishedGame`, `FinishedCrewMember` (start and end character and role), `FinishedGamesResponse` (`GET /api/games`), `MAX_GAMES_PAGE`, and `crewRoleLabel` (alpha Mush, beta Mush or Human, by the role at the end).
- `replay.ts`: `Input`, `GameSetup`, `applyInput` (the only entry point for changing a game), `replayGame`; `RecordedInput` (an input with its server time), `stampEntries` (the server's timestamps on new log and chat entries), and `rebuildGame` (the exact stored state from `setup` and the record, stamps included; #167).
- `spot.ts`: where you stand in your room: the free `walk` input, `standUp` (a public action gets you off a chair), `arrive` (in front of the door you came in by).
- `actionTarget.ts`: what an action's fields name (`namedTarget`, which the inspect panel uses too), what it is done to (`actionTarget`, which the client walks you up to), and `endsAccommodation` (a public action on equipment or another person ends a wheelchair push).
- `queue.ts`: timed actions: `queueAction`, `actNow` (an action at once with the untimed path's hooks), `clearQueue` (optionally telling the player, through `queueCore.ts`), `tick`, `nextDue` (when the server's alarm should fire); cancels a queued action whose modifier adjustment changed (`repriced`).
- `mycoalarm.ts`: the `myco_alarm` item, `ringMycoAlarms` (called by `performAction` for `spore`-tagged actions) and `dropMycoAlarms` (research yield).
- `actions/hide.ts`, `actions/search.ts`: hiding a carried item in the room (`ItemState.hiddenBy`) and searching the room for hidden items.
- `research.ts`: `RESEARCH_IDS` (the researches with card art), `RESEARCH_COMPLETE`, and `RESEARCH_REQUIRES` (items, Chun, post-selection each research needs; checked by `researchAllowed` in `actions/research.ts`).
- `planets.ts`: the Astro terminal's planets: `PLANET_TAGS` (weights, seek, max from the original), `generatePlanet` (the original's `getPlanet`, seeded), `pickSeekSector` (what an analysis reveals), `planetsOf`, `astroTerminalsHere`, `planetPicture` (cosmetic picture index, from the name). Actions `scan_planet`, `analyze_planet`, `delete_planet` (docs/plans/astro.md).
- `sharedPlanets.ts`: sharing planets in the Astrophysics feature: `sharePlanet` (the `sharePlanet` input), `canSharePlanets`, `markSharedPlanetsStale` (called by `jump` in `actions/travel.ts` and by `leave_orbit.ts`), `MAX_SHARED_PLANET_LENGTH`/`LINES`.
- `botany.ts`: plants in hydropots: `isBotanistRole` (who sees sickness), `isPlanted`/`isEmptyPot`/`isFruit`, `potRoom`, `paidWithGardenPoint`, `plantView` (strips `sick`), `botanyCycle` and `botanyDay` (called from `advanceCycle`). Actions `water`, `treat`, `sow`.
- `navigation.ts`: steering at the Command terminal: `turned` (a quarter turn), `canSteer` (the Commander, through `hasTitleAccess`), `planetAt`, `orbitPicture` (the public `navigation.orbitPicture`). `jump` in `actions/travel.ts` is a jump without the fuel, shared with `warp_to_planet`. Actions `turn_ship`, `travel`, `leave_orbit`; state `GameState.navigation` (heading, orbited planet id).
- `relay.ts`: relay tokens shared by research, projects and PILGRED (`docs/plans/relay-tokens.md`): `RelayToken`, `RelayPool`, `Sample`, `ResearchPool`, `tokenBase`, `makeToken`, `arrangeTokens` (the best ordering's penalties), `poolProgress` (progress, waiting, values; rolls go to slots), `contributionGain`, `contribute`. Pools in `GameState.relay` (research, projects) and `GameState.pilgred.pool`.
- `assay.ts`: research samples and assays (`docs/plans/research-sabotage.md`): `researchProgress` (verified and pending), `nextMark`, `assayDue`, `runAssay` (noise rolls, survivors verified), `contaminationCandidates` and `contaminate` (Saboteur). The research action's `addSample` (`actions/research.ts`) runs them and completes the research; `actions/spoil_research.ts` (own spoil) and `actions/contaminate.ts` (Saboteur) are the Mush actions.
- `relayView.ts`: `relayView`, the view's `research`, `projects`, `pilgred`, `relay` and `yourTokens`, gated to the target's room.
- `pilgred.ts`: PILGRED's repair: `PILGRED_COMPLETE`, `PILGRED_SKILLS`, `isPilgredRepaired`, `pilgredTerminalsHere`, `commandTerminalsHere`, `canReturnToSol`. Actions `repair_pilgred`, `return_to_sol`.
- `comms.ts`: the communication center: `REBEL_BASES` (call order), `XYLOPH_ENTRIES` (weights), `newComms`, `callNextRebel` / `commsCycle` (daily rebel calls), `solChance` (Radio Expert), `loseLink`, `rollRebelGain`, `rebelReached`, `rationApBonus` (Sirius), `noITrackieNeeded` (Luyten-Ceti), `drawXyloph` / `applyXyloph`, `advanceNeron`, `commsTerminalView`. Actions `contact_sol`, `decode_rebel`, `contact_xyloph`, `update_neron`.
- `hunters.ts`: hunters and turrets: `newHunters`, `startHunters` (at the game's start), `huntersCycle` (called from `advanceCycle`: hunter turns, turret and docked patrol-ship recharge (`rechargePatrolShips` in `patrol.ts`), shield regeneration, the wave pool and roll, hull 0), `damageHunter` (drops debris into `state.space`), `huntersFollow` and `loseShipsInFlight` (from `travel` and `leave_orbit`), `destroyPatrolShip` and `retargetHunters` (patrol ships shot down or landing), `huntersPerCyclePoints`, `turretsHere`/`allTurrets`/`turretCharges`, `rollRange`. Actions `turret_attack`, `repair_hull`; `ship.ts` has `damageShip` and `shieldAbsorbPercent`.
- `patrol.ts`: patrol ships and the Pasiphae (data and lookups only, so `config.ts` can import it): `PATROL_SHIPS`, `interfaceId`/`commandId`, `patrolRooms`/`patrolEquipment` (their door-less rooms in the config), `newPatrolShips`, `shipsInFlight`, `canFly` (Pilots), `dockedHere`, `shipAboard`. Actions `takeoff` (also exports `board` and `manoeuvre`, the clean-or-rough roll through `cleanManoeuvreChance`), `land` (unloads the ship's room) and `collect_scrap`; `modifiers/pilot.ts` (docs/plans/patrol.md).
- `incidents.ts`: incident points (#184): `INCIDENT_IDS`, `incidentPointsForDay`, `incidentsCycle` (pool, roll, weighted buying; called from `advanceCycle`).
- `breakage.ts`: broken equipment: `isBreakable`, `workingBreakable`, `breakEquipment` (NERON's chat notice, Com center link), `leakOxygen`. `isBrokenIn` is in `equipment.ts`, read by `Action.check` (`BROKEN`). Action `repair` (`actions/repair.ts`).
- `fire.ts`: `GameState.fires`: `daedalusRooms`, `isOnFire`, `startFire`, `fireCycle` (spread or damage). Actions `extinguish` (`actions/extinguish.ts`) and the Firefighter's `extinguish_manually` (`actions/extinguish_manually.ts`).
- `bios.ts`: NERON's BIOS switches: `BIOS_OPTIONS` (`actopi`, `death_announcements`, `plasma_shield`), `newBios`, `biosTerminalsHere`, `canChangeBios` (NERON Admin). Action `set_bios`.
- `singlePlayer.ts`: single player (#59): `singlePlayerGame` (seats, config, the human forced Mush), `NEVER_BOTS`, `SINGLE_PLAYER_SEATS`.
- `preselection.ts`: pre-selection (`config.preselection`, `GameState.preselection`): `joinShip` (the server's `join` input), `preselectionDeadline`, `preselectionCycle` (called as each cycle begins), and `selectMush` (Mush, titles, the first rebel call, and the under-3-players stopgap).
- `victory.ts`: the game end: `winnerOnArrival` (the decided win rule on reaching Sol or Eden), `mushWinOnDeath`, and `endGame` (`phase` "ended", `winner`, `ending`).
- `projects.ts`: `PROJECT_IDS` (the original's 41 live NERON projects), `PROJECT_COMPLETE`, `projectDone` and `PROJECT_STATUS`.
- `projectEffects.ts`: `onProjectCompleted`, run when a project reaches 100% by work or by a NERON update (the Noise Reducer refreshes every AP cap).
- `mind.ts`: minds and bodies: `bodyOf` (the body a seat plays; the server resolves every token through it), `swapMinds` (a Transfer), `acknowledgeTransfer` (the victim's pop-up input).
- `rng.ts`: the seeded RNG (its state is part of `GameState`): pair functions `nextFloat`, `nextInt`, `rollRange`, `shuffle` return `[value, next]`; the `roll`, `rollInt`, `rollFloat`, `rollShuffle` helpers advance a `HasRng` holder (a `GameState`) in place, so a draw can't drop the next state. Rule code that draws from `state.rng` uses the helpers; the pair functions are for seeded generators that take a bare seed (`planets.ts`, `createGame`'s seed, `singlePlayerGame`).
- `helpers.ts`: `ActionResult`, `fail`, `clone`, `findPlayer`, `dayOf`.
- `paths.ts`: `shortestPath` (deterministic BFS over `config.rooms`; null for the door-less patrol craft), for the summons walk.
- `queueCore.ts`: the queue parts action classes may import without a cycle: `emptyQueue` (with `actionDropped` lines on request) and `dropped`.
- `fullView.ts`: the full-state view for replays (#334): `fullViewFor(state, starts)` (the state without its RNG, plus each seat's role and character when the Mush were chosen, `seatStarts`) and `perspective(full, seat)`, which equals `viewFor` (tested at every step of a random game in `replay.test.ts`). It shows every hidden thing: only for an ended game, through the replay route (#337); nothing sends one yet.
- `viewDiff.ts`: the replay history's JSON diff (#335), no dependency. `diffView(prev, next)` describes objects by changed and deleted keys and arrays as removals (chat's per-channel trim, a body's action history), in-place patches and an append (log and chat only grow); `applyDiff` builds a new value, sharing what didn't change; `jsonEqual` (undefined keys count as missing).
- `viewHistory.ts`: `HistoryStep`, each input's part of the replay history (`RecordedInput.history`): a full copy at each `cycle` input, the loaded view (`base`) plus a change for the first input after a room start, otherwise a change; copies carry `HISTORY_VERSION`. `historyStep` builds one, `rebuildHistory` rebuilds the full view after each step (`HistoryError` for another format version).
- `plans.ts`: channel plans (docs/plans/on-call.md): `postPlan`, `openPlan`, `findPlan`, `finishPlan` (keeps `config.plans.finishedKept`), hooks `leavePlans` and `dropChannelPlans` (from `removeFromChannel`), `strikeSlots` (after actions, cycles and deaths), `expirePlans` (day tick), `plansView`. Posting arrives as the `postPlan` message (`protocol.ts` calls `parsePlanDraft` here, which rebuilds the draft with known keys only; an `applyInput` case in `replay.ts`). Actions in `actions/plan_slots.ts` (`claim_slot`, `withdraw_slot`, `mark_done`, `cancel_plan`) and `actions/summon.ts` (`summon` and its `walk`; `performAction` bound by rules.ts).

## Rule areas

- `chat.ts`: chat storage, channels (`chatChannels` to post, `readChannels` to read), `sendChat`, threads under global chat (`createThread`), private channels, limits.
- `death.ts`: `damage` (the one way HP goes down) and `killPlayer`.
- `infection.ts`: `contaminate` (the one way contamination rises), conversion, `contaminationSeenBy`.
- `items.ts`: item types, containers, capacity and reach helpers, `produceItem`, `removeItem`, `newItemId`.
- `itemIds.ts`: dependency-light IDs used by item definitions and the default config.
- `equipment.ts`: room equipment types, and `equipmentHere` (equipment of a type in the player's room).
- `log.ts`: room log helpers (`logPublic`, `logPrivate`, `logSecret`, `logCovert`, `hasCamera`).
- `history.ts`: each body's action history (`recordAction`, called from `performAction`) and `revealHistory`, the private reveal lines Interrogate and Chitchat write.
- `resources.ts`: per-player skill point pools.
- `skills.ts`: the human skills, each character's pickable list (`CHARACTER_SKILLS`), `SKILL_SLOTS`, the Mush skills (`MUSH_SKILLS`, `MUSH_SKILL_SLOTS`), and `skillsOf`/`hasSkill` (picked skills, the book slot, and Mush skills).
- `titles.ts`: `TITLE_IDS`, each title's line (`SUCCESSION`), `successor` (pure), `assignTitles` (at creation) and `refreshTitles` (after a death, going inactive or coming back).
- `statuses.ts`: stored and derived statuses.
- `inactivity.ts`: inactive and super inactive (#145): `isInactive`, `isSuperInactive`, `inactivityOf`, `inactivityCycle` (from `advanceCycle`, given the clock cycle's server time), `markSeen`, and the server's `seen` and `inactivate` inputs.
- `adjustStats.ts`: capped morale changes and disease application; `addDisease` updates both the modifier and private status.
- `cheats.ts`: development cheats (issue #148), gated by `ALLOW_CHEATS`. Flag-only cheats are read where they apply: `instantActions` in `queue.ts`, `noRelayPenalty` in `relay.ts` (`makeToken`, fixed on the token), `freeHacking` in `titles.ts` (`bypassesTitles`), `anySkill` in `actions/pick_skill.ts`, `easyTravel` in `actions/warp_to_planet.ts` and `actions/leave_orbit.ts`. `alwaysClean` strips `dirty` in `applyCheats`.

## Types, config, and data

- `types.ts`: the small shared vocabulary; re-exports `types/`.
- `types/config.ts`: `GameConfig`, `MovementRules`, `Equipment`. Tuning is nested by feature (`config.punch.cost.ap`, `config.punch.effect.damage`, a [min, max] range).
- `types/player.ts`: `PlayerState`, `ResourceId`.
- `types/chat.ts`: channel and message types.
- `types/plan.ts`: `Plan`, `PlanSlot`, `PlanTask`, `PlanDraft`, `PLAN_PURPOSES`.
- `types/state.ts`: `GameState` (server-only).
- `types/view.ts`: `PlayerView`, `OtherPlayerView`, `ItemView`: the only game data a client or bot receives.
- `config.ts`: `DEFAULT_CONFIG` and `PRESELECTION` (a multiplayer ship's pre-selection rules: 16 seats, day 3). The map comes from `@mush2/assets/derived/ship-rooms.json`.
- `protocol.ts`: wire message types and `parse*` validators for untrusted client input; actions go through `ACTIONS[type].parse`.
- `moderation.ts`: `moderateChat`, called by the server, not the rules; `moderateName`, called by `viewFor` for the end screen's names.
- `characters.ts`: cosmetic crew identities, no rules effect.
- `shipLayout.ts`: types for `Mush/derived/ship-art.json` and `ship-map.json` (`ShipLayout` is the two together) and `placedEquipment`.
- `actions/speech.ts`: the Leader's Fiery speech and the Motivator's Boring speech (room-wide morale and MP gifts; `PlayerState.boringToday`).
- `actions/interrogate.ts`: the Torturer's Interrogate (1 damage, reveals the target's last actions, one per missing HP; `interrogatedToday`).
- `actions/chitchat.ts`: Chitchat with a Confident (+2 morale, the Confident learns your last actions, one per point of their morale; `chitchatToday`).
- `actions/comfort.ts`: Comfort, the Shrink's action (+2 morale to a roommate, 1 AP, no daily limit). The Shrink's lying-down morale is `onCycle` in `modifiers/lying_down.ts`.
- `actions/anathema.ts`: the Persecutor's Anathema (the Outcast status, `PlayerState.outcastBy`).
