# Code map

> **Bots (2026-10-13):** the author does not necessarily plan to run AI-controlled bots in live public games. They may be for testing only. Wherever these docs describe bots filling seats, treat live use as undecided.

Moved out of CLAUDE.md to keep per-request context small. Read it when you need to find where something lives.


- `shared/src/rules.ts`: `createGame`, `applyAction`, `legalActions` (both via the registry in `actions.ts`), `viewFor`. State is plain JSON (it is persisted and cloned via JSON). `viewFor` is the single place hidden info is stripped; extend its tests whenever `PlayerView` grows.
- `shared/src/actions.ts`: the action registry (`ACTIONS`), one `ActionDef` per action type: `candidates` (what to offer), `check` (why not, as a reason code, or null), `cost`, `apply`. `legalActions` and `applyAction` both go through it; scheduled plans will too (`docs/action-plans.md`). Adding an action means adding a definition here. Also `visibleTargets`.
- `shared/src/log.ts`: room log helpers (`logPublic`, `logPrivate`, `logSecret`) and `roomName`.
- `shared/src/config.ts`: seat count is a placeholder (8; `docs/rules-design.md` decided 16 seats, with 2 Mush, or 1 when 8 or fewer players are in the room, not yet implemented); AP, MP, HP, and morale values are confirmed. The map is the original Daedalus (27 rooms with doors, from `Mush/derived/ship-rooms.json`, imported as `@mush2/assets/derived/ship-rooms.json`); everyone starts in `LABORATORY` (confirmed). `equipment` lists the fixed equipment per room, also from that file.
- `shared/src/modifiers.ts`: rule modifier registry. Players hold modifier ids; items/skills register pure hooks (today: `movement`, which adjusts MP cost and the AP-to-MP conversion, and `apPerCycle`, which adjusts AP gained per cycle; `lying_down` gives +1 but nothing applies it until a lie-down action exists). `moveCost` is the single place a move's price is computed.
- `shared/src/equipment.ts`: English names for room equipment types (`EQUIPMENT_TYPES`, hand-translated from the French data).
- `shared/src/items.ts`: item types (`ITEM_TYPES`, placeholders) and containers. Every item is in one `Container` (a player or a room); `capacity` and `canReach` are where slot counts and future access controls live.
- `shared/src/moderation.ts`: `moderateChat` (normalize, strip invisible characters, remove links, mask a starter word list). Called by the server, not the rules.
- `shared/src/protocol.ts`: wire message types plus `parse*` validators for untrusted client input.
- `server/src/Matchmaker.ts`: single instance (`matchmaker/global`). Queues players, sets an alarm to fill with bots after 5 s, creates a `GameRoom` via `getServerByName` and calls its `setup()` over RPC, then hands each human a secret seat token.
- `server/src/bots.ts`: the `Bot` interface and `WanderBot` (scripted placeholder). Bots live in `server`, not `shared`, because model-backed bots need network calls, secrets, and a spend cap.
- `server/src/GameRoom.ts`: one per game (`game-room/<uuid>`). The connection URL carries `?token=`, which maps to a seat. Persists state to DO storage on every change (with a `STATE_VERSION`; mismatched saves are discarded), sends each connection its own `viewFor`, runs bots with a deliberate delay, and handles chat (per-seat rate limit, then moderation, then `sendChat`).
- `shared/src/shipLayout.ts`: types for `Mush/derived/ship-layout.json` (per-room isometric tiles, doors with targets, sprite slices, atlas sheets), plus `placedEquipment`, the one rule for which sprite draws which equipment (used by both the converter and the renderer).
- `tools/src/shipLayout/`: the build-time converter, with a hand-written PNG decoder and XML reader (no dependencies). `shipPlan.ts` also writes `Mush/derived/ship-plan.json` (`ShipPlan`: room cells, doors, walls of the original 2D deck plan, for the minimap), decoded with `haxe.ts` (a minimal Haxe unserializer) from the `s1Cache` string in `Mush/src/common/data/Map.hx`; the color-coded image it came from isn't in the archive. A test checks its doors match the rules' room graph.
- `tools/src/play/screenshot.ts`: Playwright script behind `npm run screenshot` (desktop: join, inspect, chat, walk through a door; phone: peek bar, panel switching, chat with the keyboard up, a wide room, landscape).
- `tools/src/lobby/lobby.test.ts`: real-browser layout test of the lobby (Vite in-process, headless Chromium, faked matchmaker socket).
- `tools/src/contactSheet/contactSheet.ts`: Playwright script behind `npm run contact-sheet`.
- `shared/src/characters.ts`: cosmetic crew identities (`Seat.character`), assigned by the matchmaker. No rules effect.
- `web/src/`: `App` (lobby, seat ticket in sessionStorage), `Lobby` + `lobby.css` (the cryopod landing page; the window and the metal wall around it are drawn once per vertical strip, each strip tilted in 3D, to bend them into a half-cylinder), `GameScreen` (three-panel layout on desktop, tabbed on phones; sends intents), `useMobile` (the phone-layout media query). The client never computes legality; it uses `view.legalActions`.
- `web/src/hud/`: `TopBar` (cycle, End cycle, Leave; on phones it also holds the `PlayerSummary`), `PlayerSummary` (portrait, name, role, and AP/MP/HP/morale bars drawn by `PipBar`: the original pips in a slotted frame redrawn in SVG from `pabar.png`, `Mush/derived/pip-bar/`, tinted by CSS `color`), `SelfPanel` (under the room on desktop: summary, then room items on the left and your inventory on the right; on phones it sits in the Inspect tab without the summary), `InspectPanel` (left; shows the selected person, equipment, or item, or yourself when nothing is selected, with buttons for the legal actions on it; characters use the full art from `www/img/art/char/`), `targets.ts` (finds the selection in the view), `InventoryPanel` (the two item zones inside `SelfPanel`: square tiles with the name inside at the bottom; drag a tile between the room and inventory zones to take/drop, highlighted only when `legalActions` allow it; a tapped tile shows a Take/Drop button as the touch fallback), `ITrackie` (right; Base UI tabs for the room log, global chat, and Features, where a drop-down picks a feature whose tracker sits above its thread; trackers are UI-only React state for now; emoji tabs with tooltips (`IconTab`), including a Private tab laid out like Features: a drop-down of your channels, the thread, members, invite, leave, and create; the tab contents sit in an outline card inside the glowing panel), and phone-only `BottomNav` (panel switcher) and `PeekBar` (the tapped person, equipment, or door, with its actions). `actionLabel` in `targets.ts` names action buttons for both.
- `web/src/iso/`: isometric room view in the DOM. `placement.ts` is pure (no DOM): grid projection, paint order, walkable cells, standing spots, `cellAtPoint` (click to floor cell) and `standSpot` (where to stand to use equipment), reproducing the original Flash client. `IsoRoom.tsx` renders it at exactly 1x (no scaling), one absolutely positioned div per sprite, in an `overflow: hidden` scroller whose camera follows your character (no manual panning); clicking floor walks you there and clicking equipment steps you up to it (local, cosmetic state only, never sent to the server); double-clicking a reachable door sends a move, a single tap opens it in the peek bar; clicking a person or a piece of equipment selects it. Clicks are hit-tested against drawn pixels, not sprite boxes: sprites ignore pointer events, the viewport runs `hitTest` (pure, in `placement.ts`) front to back with per-frame alpha masks from `hitMask.ts`, so scenery in front blocks what's behind it and see-through areas click through. `shipLayout.ts` fetches the layout JSON and maps atlas sheets to image URLs.
- `web/src/scene/`: `Minimap` (SVG deck plan in the room view's bottom-left, on both layouts: your room in color, the rest fogged grey with faded people; doors marked; expands on hover or tap; selecting a room offers Go when it is reachable), `plan.ts` (pure path and dot-placement helpers for it), and `CrewSprite`. `web/src/art/assets.ts` maps characters, room types, and item types (item type ids match icon file names in `www/img/icons/items/`) to files in `Mush/`; `keyedSprite.ts` makes sprite backgrounds transparent at load time.

Implemented rules: movement (1 MP per move; with no MP, 1 AP converts to 3 MP; MP starts at 0, cap 12, kept across cycles), AP (start 8, +1 per cycle when everyone is ready, cap 12, unspent AP carries over; +2 while lying in a bed once that exists), HP and morale (max 14 each, start at 14 HP and 7 morale, visible only to their owner; each living player loses 1 morale (`config.moralePerDay`, floor 0) when a day ends), days (`config.cyclesPerDay` = 8; `state.cycle` stays a global counter and `dayOf` derives day and cycle-of-day, both sent in `PlayerView`; the day boundary is handled in `advanceCycle`), the room log, global chat, an examine action (free; on anyone in your room including yourself, the room's equipment, your items, and the room's items; writes a private log line), and an inventory (3 private slots per player via `config.inventorySlots` and an `inventorySlots` modifier hook; rooms hold unlimited items, visible to whoever is there; `take`/`drop` cost nothing and are logged publicly; items are effect-less placeholders except coffee). Equipment can dispense an item (`EquipmentType.dispenses`): the `dispense` action, free, once per cycle per machine (`GameState.dispensedOn`), is offered on the refectory's coffee machine. `produceItem` in `items.ts` is the one way an action makes an item: into your inventory, or into the room if it's full ("knocked over"). `consume` (free; an item you carry or one in your room; `ItemType.consume`) removes it and gives AP up to `maxAp`; coffee gives 2 AP and no satiety (TODO: add satiety once hunger exists). Both log publicly. Room log visibility: public entries are the room's history, shown to anyone in that room; private entries only ever reach the actor; secret entries become room history only if another player witnessed them (this will change). Chat: everyone starts with an iTrackie (`config.startInventory`; item type `ITRACKIE_ITEM` = `super_talky`, after its icon), a normal item that uses a slot and can be dropped or taken. Carrying one opens global chat and the eight crew-wide feature threads (`FEATURE_CHANNELS` in `types.ts`: botany, research, inventory, space battle, comms, pilgred, neron, astrophysics), for reading and posting, including the full history. Private channels (`createChannel`, `inviteToChannel`, `leaveChannel`, outside the action registry like `sendChat`; ids `pc-N`, limit via the `channelLimit` modifier; errors are codes) are filtered in `viewFor` to their members. Chat history is capped per channel. ACTOPI (`GameState.actopi`, starts on; nothing switches it yet): while on, `viewFor` sends every player's room; while off, players outside your room lose their `room` and appear only as bare room entries in `PlayerView.unidentified` (sorted by room, so order leaks nothing). The minimap draws mini portraits for people it can identify and `mush.png` for the rest. Each player has an `alpha` flag (set for the Mush chosen at the start; player terminology only, nothing uses it, and it only appears in your own `you`). The player summary shows a faction icon (human, alpha or beta Mush) with a goal popover. Bonding (`bond`, `dtt`, `stt` in `actions.ts`; `GameState.bonds`, `sharedOnDay`, `contamination`; `PlayerView.bonds` carries only your own bonds, and contamination is in no view; capacity via the `contaminationCapacity` modifier). Infection and win conditions are intentionally absent. Their decisions are in `docs/rules-design.md`, with the remaining open questions in the `rule-decision` GitHub issues.
- `web/src/i18n/`: i18next setup (`index.ts`), language choice and persistence (`locale.ts`), and the lobby `LanguageSwitcher`. Catalogs are `web/src/locales/{en,fr,es}.json`. Tests: `web/src/i18n/i18n.test.ts` (runtime) and `tools/src/i18n/` (catalog parity, keys in use, and the hardcoded-text ratchet in `baseline.json`). See the `i18n` skill.
- Open work is in GitHub issues ([project](https://github.com/users/nearbear/projects/1)); `docs/mvp-plan.md` is the draft staging of it (not final).
