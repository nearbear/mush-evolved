# Code map

> **Bots (2026-10-13):** the author does not necessarily plan to run AI-controlled bots in live public games. They may be for testing only. Wherever these docs describe bots filling seats, treat live use as undecided.

Moved out of CLAUDE.md to keep per-request context small. Read it when you need to find where something lives.


- `shared/src/rules.ts`: `createGame`, `applyAction`, `legalActions` (both via the registry in `actions.ts`), `viewFor`. State is plain JSON (it is persisted and cloned via JSON). `viewFor` is the single place hidden info is stripped; extend its tests whenever `PlayerView` grows.
- `shared/src/actions.ts` and `shared/src/actions/`: the action registry (`ACTIONS`), one class per action type in its own file (`actions/<type>.ts`, extending `Action` in `actions/action.ts`): `getCandidates` (what to offer), `check` (why not, as a reason code, or null), `getCost`, `apply`, and optionally `getSuccessChance` and `fail`. `legalActions` and `applyAction` both go through the registry; scheduled plans will too (`docs/action-plans.md`). Adding an action means adding a file and registering it in `actions.ts`. Costs and odds are read from `state.config`. Also `visibleTargets`. (Later mentions of "`x` in `actions.ts`" below mean the registry; the code is in `actions/x.ts`.)
- `shared/src/log.ts`: room log helpers (`logPublic`, `logPrivate`, `logSecret`) and `roomName`.
- `shared/src/config.ts`: seat count is a placeholder (8; `docs/rules-design.md` decided 16 seats, with 2 Mush, or 1 when 8 or fewer players are in the room, not yet implemented); AP, MP, HP, and morale values are confirmed. The map is the original Daedalus (27 rooms with doors, from `Mush/derived/ship-rooms.json`, imported as `@mush2/assets/derived/ship-rooms.json`); everyone starts in `LABORATORY` (confirmed). `equipment` lists the fixed equipment per room, also from that file.
- `shared/src/modifiers.ts`: rule modifier registry. Players hold modifier ids; items/skills register pure hooks (today: `movement`, which adjusts MP cost and the AP-to-MP conversion, and `apPerCycle`, which adjusts AP gained per cycle; `lying_down` gives +1 but nothing applies it until a lie-down action exists). `moveCost` is the single place a move's price is computed.
- `shared/src/equipment.ts`: English names for room equipment types (`EQUIPMENT_TYPES`, hand-translated from the French data).
- `shared/src/items.ts`: item types (`ITEM_TYPES`, placeholders) and containers. Every item is in one `Container` (a player or a room); `capacity` and `canReach` are where slot counts and future access controls live.
- `shared/src/cheats.ts`: development cheats (`CHEATS`, `applyCheats`; issue #148). `PlayerState.cheats` holds the ones a player has on; `setCheat` (rules.ts) toggles one, and `applyAction` and `advanceCycle` refill the stat afterward. Reached by the `cheat` input, which the server refuses unless `ALLOW_CHEATS=true` (local `server/.dev.vars`; the view message carries `cheatsAllowed` so the settings dialog only shows the section then).
- `shared/src/moderation.ts`: `moderateChat` (normalize, strip invisible characters, remove links, mask a starter word list). Called by the server, not the rules.
- `shared/src/replay.ts`: replays (decided in `docs/rules-design.md`, "Replays"). `Input` (a client message plus `by`; chat and channel names hold the moderated text), `GameSetup` (seats, config, seed, `rulesVersion`), `applyInput` (the single entry point for changing a game; the server calls nothing else), and `replayGame`, which re-runs a record and throws if an input is rejected (different rules or lost determinism).
- `shared/src/protocol.ts`: wire message types plus `parse*` validators for untrusted client input.
- `server/src/Matchmaker.ts`: single instance (`matchmaker/global`). Queues players, sets an alarm to fill with bots after 5 s, creates a `GameRoom` via `getServerByName` and calls its `setup()` over RPC, then hands each human a secret seat token.
- `server/src/*.test.ts`, `server/src/testing/fakes.ts`: Vitest tests for `GameRoom`, `Matchmaker`, `RateLimiter` and `WanderBot`. `partyserver` is mocked with `FakeServer` (plus fake storage and sockets), so the rooms run without the Durable Object runtime.
- `server/src/bots.ts`: the `Bot` interface and `WanderBot` (scripted placeholder). Bots live in `server`, not `shared`, because model-backed bots need network calls, secrets, and a spend cap.
- `server/src/GameRoom.ts`: one per game (`game-room/<uuid>`). The connection URL carries `?token=`, which maps to a seat. Persists state to DO storage on every change (with a `STATE_VERSION`; mismatched saves are discarded), and records the game for replays: `setup` once, then `input:<seq>` per accepted input (server timestamp, plus the raw text when moderation changed it), written in the same atomic `put` as the snapshot; text moderation blocked goes to `blocked:<seq>`, and rate-limit rejections are only counted per seat (`Stored.rateLimited`). `env.RULES_VERSION` is "dev" locally and the commit hash on `npm run deploy`. sends each connection its own `viewFor`, runs bots with a deliberate delay, and handles chat (per-seat rate limit, then moderation, then `sendChat`).
- `shared/src/shipLayout.ts`: types for `Mush/derived/ship-layout.json` (per-room isometric tiles, doors with targets, sprite slices, atlas sheets), plus `placedEquipment`, the one rule for which sprite draws which equipment (used by both the converter and the renderer).
- `tools/src/shipLayout/`: the build-time converter, with a hand-written PNG decoder and XML reader (no dependencies). `stretch.ts` then applies our own changes to the room shapes: the three corridors are widened from 2 to 4 floor cells, and the back corridor is lengthened so Bedroom Beta and Bay Beta clear the Nexus when the rooms behind its doors are drawn (it copies plain floor/wall lines, refuses to split furniture, and keeps tile indices). `shipPlan.ts` also writes `Mush/derived/ship-plan.json` (`ShipPlan`: room cells, doors, walls of the original 2D deck plan, for the minimap), decoded with `haxe.ts` (a minimal Haxe unserializer) from the `s1Cache` string in `Mush/src/common/data/Map.hx`; the color-coded image it came from isn't in the archive. A test checks its doors match the rules' room graph.
- `tools/src/play/screenshot.ts`: Playwright script behind `npm run screenshot` (desktop: join, inspect, chat, walk through a door; phone: peek bar, panel switching, chat with the keyboard up, a wide room, landscape).
- `tools/src/lobby/lobby.test.ts`: real-browser layout test of the lobby (Vite in-process, headless Chromium, faked matchmaker socket).
- `tools/src/contactSheet/contactSheet.ts`: Playwright script behind `npm run contact-sheet`.
- `shared/src/characters.ts`: cosmetic crew identities (`Seat.character`), assigned by the matchmaker. No rules effect.
- `web/src/`: `App` (lobby, seat ticket in sessionStorage), `Lobby` + `lobby.css` (the cryopod landing page; the window and the metal wall around it are drawn once per vertical strip, each strip tilted in 3D, to bend them into a half-cylinder), `GameScreen` (three-panel layout on desktop, tabbed on phones; sends intents), `useMobile` (the phone-layout media query), `styles.css` (just `@import`s of `styles/*.css`, split by area: tokens, base, buttons, top-bar, layout, inspect, self-panel, items, itrackie, chat, iso, minimap; `responsive.css` must stay last so the phone layout overrides the rest). The client never computes legality; it uses `view.legalActions`.
- `web/src/hud/`: `TopBar` (cycle, End cycle, Leave; on phones it also holds the `PlayerSummary`), `PlayerSummary` (portrait, name, role, and AP/MP/HP/morale bars drawn by `PipBar`: the original pips in a slotted frame redrawn in SVG from `pabar.png`, `Mush/derived/pip-bar/`, tinted by CSS `color`), `SelfPanel` (under the room on desktop: summary, then room items on the left and your inventory on the right; on phones it sits in the Inspect tab without the summary), `InspectPanel` (left; shows the selected person, equipment, or item, or yourself when nothing is selected, with buttons for the legal actions on it; characters use the full art from `www/img/art/char/`), `targets.ts` (finds the selection in the view), `InventoryPanel` (the two item zones inside `SelfPanel`: square tiles with the name inside at the bottom; drag a tile between the room and inventory zones to take/drop, highlighted only when `legalActions` allow it; a tapped tile shows a Take/Drop button as the touch fallback), `ITrackie` (right; Base UI tabs for the room log, global chat, and Features, where a drop-down picks a feature whose tracker sits above its thread; trackers are UI-only React state for now; emoji tabs with tooltips (`IconTab`), including a Private tab laid out like Features: a drop-down of your channels, the thread, members, invite, leave, and create; the tab contents sit in an outline card inside the glowing panel), and phone-only `BottomNav` (panel switcher) and `PeekBar` (always shown in the Room view: the tapped person, equipment, or door, or yourself by default, with its actions; tapping bare floor resets it to yourself). `actionLabel` in `targets.ts` names action buttons for both.
- `web/src/iso/`: isometric room view in the DOM. `placement.ts` is pure (no DOM): grid projection, paint order, walkable cells, standing spots, `cellAtPoint` (click to floor cell) and `standSpot` (where to stand to use equipment), reproducing the original Flash client. `IsoRoom.tsx` renders it at exactly 1x (no scaling), one absolutely positioned div per sprite, in an `overflow: hidden` panel whose camera follows your character (no manual panning; it moves an inner `.iso-world` with a transform, clamped by `cameraOffset` to the current room's edges); clicking floor walks you there and clicking equipment steps you up to it (local, cosmetic state only, never sent to the server); double-clicking a reachable door sends a move, a single tap opens it in the peek bar; clicking a person or a piece of equipment selects it, and clicking bare floor clears the selection (on desktop any press outside the Inspect panel does too). Clicks are hit-tested against drawn pixels, not sprite boxes: sprites ignore pointer events, the viewport runs `hitTest` (pure, in `placement.ts`) front to back with per-frame alpha masks from `hitMask.ts`, so scenery in front blocks what's behind it and see-through areas click through. The rooms behind the doors are drawn dimmed around the current room (`neighborRooms` in `placement.ts` lines each one up so its door back shares the door's cell), in one paint order with it (`placeScene`: a topological sort over overlapping sprites using footprints, so wide furniture and neighbouring rooms layer correctly; walls and doors cover whatever stands behind them, people included, and footprints diagonally apart get no constraint; door doormats (`DOOR_L_FLOOR`/`DOOR_R_FLOOR`) are left out, and so are front-edge doors (`DOOR_BL`/`DOOR_BR`) once the room behind them is drawn; the current room takes clicks first). People a wall covers (`PlacedSprite.occluded`) also get a glowing outline (an SVG filter) in a layer above the scene, so nobody can hide behind a wall: fixed scenery only, plus whoever the view places there (everyone with ACTOPI on, nobody with it off; the client adds no ACTOPI check of its own). Clicking or tapping a faded room acts like its door (peek bar, Go; double-click moves). `shipLayout.ts` fetches the layout JSON and maps atlas sheets to image URLs.
- `web/src/scene/`: `Minimap` (SVG deck plan in the room view's bottom-left, on both layouts: your room in color, the rest fogged grey with faded people; doors marked; expands on hover or tap; selecting a room offers Go when it is reachable), `plan.ts` (pure path and dot-placement helpers for it), and `CrewSprite`. `web/src/art/assets.ts` maps characters, room types, and item types (item type ids match icon file names in `www/img/icons/items/`) to files in `Mush/`; `keyedSprite.ts` makes sprite backgrounds transparent at load time.

Implemented rules: action costs (`PlayerView.legalCosts`, index-aligned with `legalActions`, computed by each `ActionDef.cost`; the client displays them and never computes them), movement (1 MP per move; with no MP, 1 AP converts to 3 MP; MP starts at 0, cap 12, kept across cycles), AP (start 8, +1 per cycle when everyone is ready, cap 12, unspent AP carries over; +2 while lying in a bed once that exists), HP and morale (max 14 each, start at 14 HP and 7 morale, visible only to their owner; each living player loses 1 morale (`config.moralePerDay`, floor 0) when a day ends), days (`config.cyclesPerDay` = 8; `state.cycle` stays a global counter and `dayOf` derives day and cycle-of-day, both sent in `PlayerView`; the day boundary is handled in `advanceCycle`), the room log, global chat, an examine action (free; on anyone in your room including yourself, the room's equipment, your items, and the room's items; writes a private log line), and an inventory (3 private slots per player via `config.inventorySlots` and an `inventorySlots` modifier hook; rooms hold unlimited items, visible to whoever is there; `take`/`drop` cost nothing and are logged publicly; items are effect-less placeholders except coffee). Equipment can dispense an item (`EquipmentType.dispenses`): the `dispense` action, free, once per cycle per machine (`GameState.dispensedOn`), is offered on the refectory's coffee machine. `produceItem` in `items.ts` is the one way an action makes an item: into your inventory, or into the room if it's full ("knocked over"). `consume` (free; an item you carry or one in your room; `ItemType.consume`) removes it and gives AP up to `maxAp`; coffee gives 2 AP and 1 satiety, the placeholder `cooked_ration` 4 satiety. Cooking (`cook` in `actions/cook.ts`, 2026-10-16): in a `config.cookRooms` room (REFECTORY), 1 AP (`cookAp`), on an item whose type has `ItemType.cook` that you can reach (carried or on the floor); it changes type in place (`uncooked_ration` becomes `cooked_ration`, same container); public room log (`cooked`). Three `uncooked_ration` spawn in the refectory; they can't be consumed raw. Both log publicly. Room log visibility: public entries are the room's history, shown to anyone in that room; private entries only ever reach the actor; secret entries become room history only if another player witnessed them (this will change). Chat: everyone starts with an iTrackie (`config.startInventory`; item type `ITRACKIE_ITEM` = `super_talky`, after its icon), a normal item that uses a slot and can be dropped or taken. Carrying one opens global chat and the eight crew-wide feature threads (`FEATURE_CHANNELS` in `types.ts`: botany, research, inventory, space battle, comms, pilgred, neron, astrophysics), for reading and posting, including the full history. Private channels (`createChannel`, `inviteToChannel`, `leaveChannel`, outside the action registry like `sendChat`; ids `pc-N`, limit via the `channelLimit` modifier; errors are codes) are filtered in `viewFor` to their members. Chat history is capped per channel. Messages are markdown (2026-10-16): moderation keeps line breaks (up to `MAX_CHAT_LINES` = 12, still `MAX_CHAT_LENGTH` characters); the client draws them with `web/src/hud/Markdown.tsx` (react-markdown + remark-gfm; bold, italic, strikethrough, headers, lists, quotes, code, and task lists, but no links, images, tables, or raw HTML). `toggleCheckbox` (`rules.ts`, outside the action registry, wire message `toggleCheckbox` with `message` id and 0-based source `line`) ticks or unticks a `- [ ]` item in the message text; only the author may, and only while they can still read the channel. Errors are codes (`message_not_found`, `message_not_yours`, `checkbox_not_found`). ACTOPI (`GameState.actopi`, starts on; nothing switches it yet): while on, `viewFor` sends every player's room; while off, players outside your room lose their `room` and appear only as bare room entries in `PlayerView.unidentified` (sorted by room, so order leaks nothing). The minimap draws mini portraits for people it can identify and `mush.png` for the rest. Each player has an `alpha` flag (set for the Mush chosen at the start; player terminology only, nothing uses it, and it only appears in your own `you`). The player summary shows a faction icon (human, alpha or beta Mush) with a goal popover. Bonding (`bond`, `dtt`, `stt` in `actions.ts`; `GameState.bonds`, `sharedOnDay`, `contamination`; `PlayerView.bonds` carries only your own bonds, and contamination is in no view; capacity via the `contaminationCapacity` modifier). Spore extraction (`extract_spore` in `actions.ts`; Mush only; 1 AP, +1 `PlayerState.spores`; per-Mush 4-cycle cooldown via `GameState.sporeExtractedOn`; faction daily cap `sporesPerDay` modifier-folded, counted in `GameState.sporesToday` and reset in `advanceCycle`; private log; always applies `dirty`; spores appear only in your own `you`). Spiking (`spike` in `actions.ts`, 2026-10-15): Mush only, `spikeAp` = 1 AP and 1 spore, target a living human in your room, contamination +1; `logSecret` with `hideFrom` = the victim, so bystanders see it and the victim does not. Infection (`infection.ts`, 2026-10-15): `contaminate` is the one way contamination rises (spike and DTT call it); reaching `contaminationCapacity` converts the human at once (`role` = mush, `alpha` = false, contamination entry removed, satiety cleared; skills, HP, and morale stay; spore extraction is ready immediately), with a private `converted` log line that names nobody. No cure. A convert does not yet learn who the other Mush are (#39). Mush see a contaminated human's level as a status (`OtherPlayerView.contamination`, via `contaminationSeenBy`; only for living humans in their room with level > 0; never in a human's view, their own included); `StatusIcons` draws it as the spore icon with the number. Statuses and satiety (`statuses.ts`, 2026-10-14): `PlayerState.statuses` stores `dirty`; `full_belly` and `hungry` are derived by `statusesOf`/`isFullBelly`/`isHungry`, and `STATUS_PUBLIC` says which are public. Humans have `satiety` (start 0, loses `satietyPerCycle` = 1 per cycle via the `satietyPerCycle` modifier hook, floor 0) and `satietyZeroSince`, the cycle it reached 0 (starts at cycle 1); 3+ satiety = full belly, and `consume` is refused (`full_belly`); `hungryAfterCycles` = 24 after that cycle, hungry costs `hungerHpPerCycle` HP per cycle in `advanceCycle` (floor 0, no death yet); any consumable resets the count. Mush have no satiety or hunger and eat freely. `PlayerView.statuses` is all your own statuses; `OtherPlayerView.statuses` only public ones, only for people in your room. The client shows them with `StatusIcons` (Inspect panel only; select yourself to see your private ones). Showering (`shower` in `actions.ts`, 2026-10-14; equipment with `EquipmentType.shower`, i.e. the SHOWER in both bedrooms): offered only while dirty, 2 AP (`showerAp`), 1 less with `soap` in your inventory (`showerSoapDiscount`, soap is not used up), removes `dirty`, a Mush also loses `showerMushDamage` = 4 HP (floor 0); private log. One soap spawns in BEDROOM_A (`startItems`). Healing (`heal` in `actions.ts`, 2026-10-15): needs a `medikit` in your inventory (reusable; one spawns in SICK_BAY), target is you or a living person in your room; 2 AP on someone else (`healApOther`), 3 on yourself (`healApSelf`); restores `healAmount` = 3 HP (`healAmount` modifier hook; the `medic` skill adds `medicHealBonus` = 2, its other perks are not built), capped at `maxHp`; offered even at full HP; public room log (`healed`, `healedSelf`). Sick bay (2026-10-15): in a `config.healRooms` room (SICK_BAY) anyone can heal without a medikit, same AP costs. Care points are `resources.heal`: while above 0, a heal costs 0 AP and spends one automatically (`healCost` in `actions.ts`). The `carePointsPerDay` hook is granted by `grantCarePoints` at game start and each day boundary; they stack with no cap. The nurse (`first_aid`) skill adds `nurseCarePointsPerDay` = 2 that way, built by `careSkill` in `modifiers.ts`, which also sets the `onPick` hook (run by `pick_skill` through `skillPicked`): picking the skill grants the same amount at once. Skills with a one-off effect on pick (a future shooter's free shots) use `onPick` the same way; there is no skill base class, since hooks fold over the registry and factories compose. Punch (`punch` in `actions.ts`, issue 29, 2026-10-15): 1 AP (`punchAp`), target is a living other person in your room; rolled through `chance` = 1 - `punchMissOdds` (40% miss); a hit removes `punchDamage` = 2 HP (floor 0, death undecided); hit and miss are both public room log (`punched`, `punchMissed`); a miss is a failed action, so Creative can refund. Action failure (2026-10-15): an `ActionDef` with `chance` is rolled once by `applyAction` (seeded RNG) after the cost is paid, then runs `apply` or `fail`, then every `onActionFailed` modifier hook; only dismantle has a chance today. Skills (2026-10-15): `PlayerState.skills` holds skill ids, which are modifier ids in `modifiers.ts` (every hook folds over `modifierIds(player)`, skills first). Nobody starts with a skill (`config.startSkills` = []). `skills.ts` lists the 58 pickable human skills (`SKILLS`) and `SKILL_SLOTS` = 3 (books and the fourth slot are not built). `pick_skill` (`actions.ts`, 2026-10-15) is free and permanent, refused for a skill you have, an unknown id, or with no free slot; it writes no log line and is offered once per unowned skill in `legalActions`. Skills are public: `OtherPlayerView.skills` carries them for people in your room only (empty elsewhere). Most skills have no rules yet; picking one is harmless. The client draws `SkillSlots` (`web/src/hud/SkillSlots.tsx`) over the Inspect portrait: filled slots show the icon, your own empty slots a gold plus that opens a picker dialog built from the `pick_skill` entries in `legalActions`, and other players' empty slots are inert. Creative (`creative` in `MODIFIERS`): after a failed action that cost AP, a `creativeRefundOdds` = 50% roll gives 1 AP back, with a private log line (`creativeRefund`). Win conditions are intentionally absent. Their decisions are in `docs/rules-design.md`, with the remaining open questions in the `rule-decision` GitHub issues.
- `web/src/i18n/`: i18next setup (`index.ts`), language choice and persistence (`locale.ts`), and the lobby `LanguageSwitcher`. Catalogs are `web/src/locales/{en,fr,es}.json`. Tests: `web/src/i18n/i18n.test.ts` (runtime) and `tools/src/i18n/` (catalog parity, keys in use, and the hardcoded-text ratchet in `baseline.json`). See the `i18n` skill.
