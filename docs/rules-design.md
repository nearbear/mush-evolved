# Rules design: decisions and phased plan (written 2026-10-05, pruned 2026-10-13)

> **Bots (2026-10-13):** the author does not necessarily plan to run AI-controlled bots in live public games. They may be for testing only. Wherever these docs describe bots filling seats, treat live use as undecided.

The record of answered rule decisions and the design for the rules that are not built yet. Open questions live in GitHub issues labeled `rule-decision`, not here. Scheduled plans have their own document, `docs/action-plans.md`.

**Status (2026-10-13):** built are AP, MP, HP and morale values, the action registry, inventory, the iTrackie, global chat, and private channels. Not built: infection, spores, the attack, win conditions, the cycle timer, and the phases below.

## Decisions received
- **Mush skills, foundations** (2026-10-24, owner; built 2026-10-24, #172): each Mush has up to 4 Mush skills, separate from the human slots, picked at any time (free and permanent, like human skills); Mush can still pick human skills. All of the original's Mush skills are pickable, none implemented yet; the picker shows each one's implementation status. Private to their owner (from #25: not to humans, not to other Mush). UI: a button at the top of your own skill stack toggles between showing human and Mush skills, purely cosmetic.
- **Transfer (Mush skill)** (2026-10-24, owner; not built, waits for Mush skills, #172; eMushpedia `Transfert`). A Mush with the skill takes over a human's body (the target's player gets the Mush's old body); one use per game, free, Aggressive. Target: a living human in the same room with contamination ≥ 1; Antique Perfume immunity doesn't block it (at contamination 0 the target isn't eligible anyway). **The mind** (the player: account, seat token, bot control) moves; so does everything Mush-related: role (the target's body becomes Mush, the old body human with contamination 0 and no spores), Mush skills, spore cooldown, `alpha`. **The body** keeps everything else: AP, MP, HP, morale, satiety (the old Mush body becomes human at satiety 0 and counts toward hunger from the transfer cycle, so it is not immediately hungry), inventory, human skills (no reset, unlike the original, so a transfer leaves no trace there), titles (a Mush in the Commander's body can steer), and private channel membership. **History follows the mind:** each player keeps the private log lines and chat they saw before and never sees the other body's private past; this needs private lines addressed to the player, not the character. Both players' current action and queue are cancelled. As few mechanical signs as possible for others. The victim gets a cosmetic pop-up they must acknowledge, naming the character who took their body. Myco-alarms in the room ring as for other Mush actions; the Mush gets a private log line.
- **Botany, Pass 1** (2026-10-22, owner; built 2026-10-22; plan in `docs/scratchpad/botany-plan.md`). Mechanics and actions first, bananas only; alien species, alien fruits, grafting and fruit properties wait for expeditions. Plants grow in hydropots anywhere, carried too. Start: an empty pot and two adult banana plants in the Hydroponic Garden and two empty pots in front storage (replacing the five lab pots of 2026-10-18). Water (1 AP) targets one thirsty or dried plant; treat costs 2 AP; sow costs 2 AP and uses a carried fruit in an empty pot. Each has the original's 15% dirt chance and a public room line. Each day: young plants that have had their 36 cycles become adult; each adult plant that is not thirsty, dried or sick gives +1 oxygen (capped) and a banana (a carried plant's goes to its carrier, else their room's floor); then every plant gets thirstier, stopping at dried. No plant death yet, from thirst or sickness. Sickness is hidden: only the Botanist role (Botanist and Skilful, Mush or not) sees it, and they can't treat a healthy plant; everyone else can treat any plant, and treating a healthy one costs and reads the same. Mush gain nothing. Sickness odds are a placeholder 5% per plant per cycle (young plants too; sick plants still get thirsty). The Botanist gains 2 garden points a day (holds 4), spent on a plant in the garden only; the Skilful get none. Mush can water, treat and sow like anyone, with no confirm prompt (my reading). A banana gives +1 AP, satiety, morale and HP. Pass 2: plant death, the plant controller, the garden projects, Green Thumb.
- **Communication center** (2026-10-19 and 2026-10-21, owner; built 2026-10-21; plan and answers in `docs/comms-plan.md`). Every action costs 2 AP and needs the actor clean; Mush can act. Anyone can try the Sol link, which uses one ship-wide chance: 4%, +4% per failure, never below 4%. Radio Expert gives x2 on their own attempts and x1.5 to roommates' (my reading of the skill). The link can be lost. Decoding, Xyloph and the NERON update need the link and the Comms Officer title. The room log is private for all four; the terminal screen is read-only for anyone at it (not which Xyloph entries were drawn, my choice). Rebel bases: one calls at Mush selection, then one a day in the same cycle, in data file order, each open for 8 to 16 cycles rolled per base. NERON announces a call in crew chat if the link is up; a call that arrives during an outage stays decodable until it expires. A decode costs 2 AP or a Computer point and gains avg(two 1..40 draws); Rebel and Kivanç give +100% each, additive. Only the buildable bonuses are built (Sirius, Kaladaan, Luyten-Ceti, Cygni's morale). Xyloph always succeeds, never repeats, and ends when the table runs out; every entry is built except Lost analysis (recorded only). Its items land on the bridge. NERON update: 25% per action, repeating; each version completes a random unfinished project. Computer points pay only for decoding (my default; the owner's source named them only there).
- **PILGRED and returning to Sol** (2026-10-21, owner; repair and return to Sol built 2026-10-21; plan in `docs/scratchpad/pilgred-plan.md`): repairing PILGRED uses the original's slow formula (`Solver.calcPilgredProgres`): 1% per action base, +4 for each of Engineer and Physicist the actor has, −2 for each repeat in a row by the same player, never below 0, gain rolled in [min, min + min/2]. Mush can repair it. Once it's repaired, the Commander can return the ship to Sol, and a Mush Commander can too. If the Commander title is vacant, the alternative route is the hacker kit (not built; until it is, nobody can return). Returning to Sol ends the game immediately, with the win conditions below. Repair progress is seen only by someone at the PILGRED terminal (read as: in the engine room, since the rules don't track who has a terminal open). Each repair is private: no room log line, only the repairer's own (owner correction, 2026-10-21, superseding "a public room log line"). Completion posts a crew-wide system message in global chat and a room log line. Repair costs 2 AP, has a 25% chance to make the repairer dirty, and dirty players can repair; no injury chance until #207. Mush get no confirm prompt. The Physicist gains 1 PILGRED point per day (holds at most 2), and each point makes one repair free (my default, not asked: no point when the skill is picked, unlike the Computer Scientist). Return to Sol is a button at the Command terminal: 2 AP, with a confirm dialog. Later: Eden, PILGRED breaking again, the reactor art swap, coffee changes, Raluca's triumph, the alien merchant repair.
- **NERON's BIOS** (2026-10-21, owner): the BIOS terminal starts with two options, ACTOPI on/off and crew-wide death messages on/off (the original's "Signaler les décès"), both on at the start (the original's defaults). Only the NERON Admin can change them; free; private log (only the actor learns of a change). With death messages off, a death posts no crew-wide message; the room's public log line still appears. Anyone alive at the terminal can read the settings (my recommendation, accepted).
- **Relaying** (2026-10-21, owner; not built): the repeat penalty on PILGRED repair resets the moment someone other than the previous contributor makes progress, so the crew gains most by taking turns. Relaying applies to research and NERON projects too (they have no repeat penalty yet; built later).
- **Where you stand in a room** (#17, #21; owner, 2026-10-20): positions in a room are shared, like RuneScape, and may have in-game implications. They are game state (`PlayerState.spot`), set by a free `walk` input (not an action, never queued), and visible to living people in the same room only. Floor and chair clicks are shared; walking up to the target of an action is shared only when the action is public (private, secret and covert ones stay on your own screen). Sitting on a chair is shared, with no limit on how many sit on one. Entering a room puts you in front of the door you came in by; nobody has a spot before they first walk or move (the client spreads them out). Sending a public action gets you up from a chair (owner, 2026-10-20, after a leak review): other actions leave you seated as your roommates see it, since standing up would show you did something they otherwise can't see; your own screen stands you up for any action. You can't walk while lying in bed or being pushed.

- **Dirty action chances** (2026-10-20, owner): cook 25%, express cook 5%, consume 15%, dispense 5%, build 25%, install 10%, uninstall 5%, and heal 5%. Each action can make its actor dirty after resolving, following the existing punch chance mechanism.
- **Injury chances** (2026-10-23, owner; resolving the deferral in #207): build 5%, dismantle 5%, jettison 2%, repair PILGRED 5%, shower 2%, and taking or dropping an item 1%. Like Install, the injury roll happens after the action resolves, even if its success roll failed; an injury deals 2 HP damage and protection gloves block it.
- **Timed actions** (2026-10-17, owner): every action takes 2 seconds of real time and happens when its bar runs out ("at the end", with `config.action.resolveAt: "start"` kept as the alternative: happen at once, then a cooldown). Moving takes 2 seconds too. (2026-10-24, owner: cut to 1.5 seconds for every timed action, moving included.) A player can queue up to 3 actions behind the one under way and has a Clear queue button, which also cancels the one under way. The cost is checked again and paid when the action happens, so a dropped or cancelled action costs nothing; one that is no longer possible when its turn comes is dropped with a private log line. End cycle (`ready`) is instant; actions under way carry over into the next cycle, and nothing new can be queued once ready. A bar shows over the actor's head to people in the room when the action's log entry could reach them: public and secret actions always, covert ones only on camera, private ones never (owner: "any action that results in a room log"). The bar never says which action. My defaults: `access` is untimed too (it only opens the terminal window); `pick_skill` is timed.
- **Action tags** (2026-10-18, owner; #30): each action type carries tags that other rules can react to without listing action types. `aggressive`: punch and spiking (spiking added 2026-10-18, owner), so Pacifist's surcharge applies to both. `spore`: spiking (also aggressive), and future Mush abilities that ring a myco alarm; spore extraction is not tagged (balance). Tags are sent in the player's view with each offered action; no UI shows them yet.
- **Traits** (2026-10-18, owner): a trait is an innate, permanent modifier a character starts with (`config.characterModifiers`), with whatever effects its modifier hooks give it. It can never be removed or picked, and it survives conversion. Every trait is a public status, shown on the Inspect panel but never over the head (owner, 2026-10-18; `TRAIT_STATUS_IDS`). Ian's Pacifist is one; Chun's Immunity is the other.
- **Chun's Immunity** (2026-10-18, owner): Chun is immune to infection for the whole game; contamination attempts on her do nothing, silently, like the Antique Perfume. Shown with the immune icon as a public, permanent `immunity` status. Chun can still be a Mush from the start.
- **Chun's Mankind's Only Hope** (2026-10-18, owner): a trait for Chun, not a skill (removed from the pickable list). The daily morale loss is 2, cut to 1 while Chun is alive. Her death raises it to 2 whether she was human or Mush, and with no Chun in the game it is 2 from the start (as in the original, where the skill reduces the daily loss by 1). Public, permanent status like the other traits. Supersedes the flat 1 of the **Days** entry.
- **Accommodating Terrence** (2026-10-19, owner): others can accommodate Terrence (push his wheelchair). Anyone living in his room may offer, free; it starts only when Terrence accepts, and an offer he hasn't accepted within 5 minutes expires. While accommodated he can't move on his own; he moves with his pusher and pays no MP for it, while the pusher pays a normal move. Either of them can end it, as an instant action (not queued), and it ends if either dies. Offer, start and end go in the room's public log, and roommates see a status showing who is pushing. Following the traits decision, the wheelchair is also a public trait status on Terrence.
- **Pacifist and repriced queued actions** (2026-10-18, owner): Ian starts with Pacifist: every aggressive action in his room costs 2 more AP, his own included. He keeps it when converted to Mush (losing it would out him through punch prices). It shows as a public, permanent status icon on Ian (built 2026-10-18), with a hover card describing the surcharge. Several holders in one room stack. A queued action (or the one under way) whose modifier-driven price change differs from when it was queued is cancelled when it starts or resolves, cheaper or dearer, with a private message giving the new price, so nobody pays a price they didn't plan for. Only modifier adjustments count: base-price changes caused by the player's own queue (AP-to-MP conversion on moves, care or computer points used up) don't cancel.
- **Mush-eating bacteria research** (2026-10-17, owner): once complete, a human needs 4 contamination to convert instead of 3, for every human. Humans already at 3 are not converted when it completes (my default).
- **Caffeinomaniac** (2026-10-16, owner): consuming a coffee gives +2 AP on top of the coffee's own, capped at the AP cap; coffee only; the NERON project bonus is not built.
- **Terminals** (2026-10-16, owner): every terminal gets an `access` action that opens a blank window showing its name; the terminals' real actions come later. Free and unrestricted for now (my default; the original has a `MODULING` status and access limits for Command and BIOS, not built). Terminals: Astro, Command, Com center, NERON core, BIOS, Research lab, Pilgred, Calculator.
- **Astro terminal planets** (2026-10-19, owner; plan in `docs/astro-plan.md`, not built): scanning costs 3 AP, starts at 50% and multiplies by 1.25 after each failed scan (per player). Planets are private to their finder, capped at 2 per player, and deletable at any time from a trash button. Analysis costs 2 AP and reveals one sector, picked weighted by `seek`. The room log shows "X scanned" whether the scan worked or not, and analysis logs the planet's name. It never shows sectors. Living, not-dirty players only. A success resets the odds. Deleting is silent. Scan modifiers come later.
- **Ship travel** (2026-10-22, owner, from the wiki's Terminal de Commandement): the ship faces N/W/S/E. Only the Commander (Mush included, `hasTitleAccess`) steers, at the Command terminal. Turn left/right costs 1 AP, in orbit too. Travel costs 1 AP and goes 1 to 9 fuel the way the ship faces, using ship fuel. Short of fuel, the AP is wasted and nothing happens (the wiki's behaviour). Arriving exactly where a known planet lies puts the ship in its orbit. Every other planet on the ship is lost, and a blind jump loses them all. The orbited planet stays private to its finder; everyone knows the ship is in orbit. While in orbit there is no travel and no scanning; Leave orbit (1 AP) takes Travel's place and loses the planet. Claude's defaults, not asked: leaving orbit burns 1 fuel; the ship starts facing north; the orbited planet can't be deleted; the heading is shown only to the living at a Command terminal; the turn is a public bridge log line, while travel, arrival in orbit and leaving orbit are ship-wide lines. Not built: hunters and aracks, reactor damage, deep analysis in orbit, exploration, ending rebel calls on travel, Frieda's triumph.
- **Fuel loading** (2026-10-23, owner, from the wiki): the ship can only travel on fuel hauled by hand from the tanks (two rear storages) to the combustion chamber (Motor room), which starts empty and holds 9. Capsules are 0 AP with a dirt chance (25%, Claude's placeholder), stack in one slot, and can't be dropped; a capsule can be taken back out of the chamber. Travel no longer takes a chosen distance: it burns everything in the chamber and goes that far; Leave orbit burns 1 from it. Claude's defaults, not asked: the chamber level is public; no putting a capsule back in a tank yet. Follow-up (2026-10-23, owner): fuel actions are secret; loading and unloading log the chamber level; a free action reads the level; a capsule can be put back into a tank; taking or unloading with full hands is refused and the button shown disabled. Correction (2026-10-23, owner): capsules no longer stack; each takes a slot like any item.
- **Planet positions and sizes** (2026-10-22, owner; eMush's `PlanetService` and the wiki): every planet has a direction (N/W/S/E) and a distance of 2 to 9 fuel, unique across the ship (all players' planets; deleting frees the spot). The distance is two rolls over 2–7 averaged and rounded down, among free spots; 8 is used only when 2–7 are full, then 9. Size grows by day: 2–12 sectors before day 5, 4–16 on days 5–9, 6–20 from day 10, even sizes only.
- **Myco alarms** (2026-10-17, owner): completing the MYCO_ALARM research yields three alarms, left on the lab floor (my default for placement, confirmed). They ring (public room log, no actor, no `danger` level yet) when a Mush uses: Mutate, Punching, Infectious cuddles, Fungal kitchen, Trapper, Transfer, Nightmarish, Bacterophiliac or Radio pirate; spiking also counts (#159). Spore removal is not detected. Only active in a room inventory, never carried. Dismantle uses the standard dismantle config (confirmed). Only spiking is wired; the skills are not built. **Update (2026-10-18, owner):** the alarm rings for any action tagged `spore` (see "Action tags"), when it resolves, even if it fails; the abilities above get the tag when built.
- **Research** (2026-10-16, owner): working on a research costs 2 AP and advances it 25%; no repeat penalty for now; anyone not dirty can contribute; every research that has card art is in (24); the list and progress are fully public. Owner (2026-10-20): working on research has a 25% chance to make the researcher dirty (also when a Computer point makes the action free); this does not apply to NERON projects. My defaults, not confirmed: it is done at the lab's research terminal, a finished research cannot be worked on, any number can be in progress at once, and nothing happens on completion yet (the original's difficulty, samples, prerequisites and effects are ignored).
- **NERON projects** (2026-10-18, owner): built exactly like research: 2 AP, 25% per action, no repeat penalty, anyone not dirty. Done at the NERON core in the Nexus. All 41 projects in the original's live list are in (the 'plus' ones included; PRICE_HACKER and the deprecated ones left out), every one open at once (not the original's 3 proposals). A Computer Scientist's point pays for one action, as for research. The list and progress are public. No completion effects yet; the research terminal UI is reused.
- **Blueprints** (2026-10-16, owner): building always consumes the blueprint; no failure chance; anyone can build anywhere; ingredients may be in your inventory or on the room floor. Build costs 3 AP (the original's value). A built sofa is room equipment, not an item. The sofa needs metal scraps + a thick tube (the original's recipe). For now only a sofa blueprint exists, in the front corridor (CORRIDOR_A). Rocket launcher blueprint (2026-10-16, owner): thick tube + metal + plastic scraps (the original's first recipe), builds an effect-less item into the inventory or onto the floor, spawns in the front corridor. Open: other recipes, where blueprints come from beyond this one.
- **Sofas** (2026-10-18, owner, following the French wiki): a sofa is a bed (same rules as BED: free lie down, +1 AP per cycle, get up). It is never on the ship at the start (the turret room's map sofa is gone until built); it can be built in any room, and a room can hold more than one (the original shows extras on the shelf, with the occupant's name). It can never be moved. Dismantling costs 3 AP and leaves 1 plastic scrap, at the usual dismantle odds (12%, the owner's choice; the wiki gives none); its occupant gets up. Drawing: one sofa per room at a hand-picked spot (Claude proposed, owner reviews; the bridge's is in its upper-right corner under the camera). Not built yet: getting up on a breakdown or when boarded onto the Icarus, repair, the shelf listing.

  - **Infection mechanic (to be built):** a Mush who has the cat in their own inventory can use *infectious caress* (original `MUSH_CARESS`, Mush only, 1 AP, tracked) to make him a Mush cat. A human who then takes him up is contaminated (the original log: "X was contaminated by Y by taking Schrödinger. Their contamination level is now N."). It feeds the same contamination and conversion rules as `spike`.
  - **Death (to be built):** his death has consequences for Raluca's morale. Only this fact is recorded; the amount, the cause of death, and the announcements are not specified.
  - **No win condition.** The original's three Eden objectives about him are dropped.
  - **From the original, not decided here** (`Mush/derived/data/DataAction/actions.json`): a normal `CARESS` (1 AP, unique bonus of +3 morale per the original footnote) and `PICK_CAT` (0 AP) exist; he also wanders, stows away on expeditions, and has NERON quips. None of these are decisions yet.

- **Item attributes and Heavy** (2026-10-16, owner): items can have attributes that work the same on every item that has them (`ItemType`); the first is `heavy`. Carrying any heavy item makes each room-to-room move cost 2 more MP (`heavyMpPenalty`), once however many you carry; floor items do not count. The `sturdy` skill (Solid, "Robuste") cancels it and adds 1 to punch damage (`sturdyPunchBonus`); Throw Out a crewmate is not built. The freezer is heavy and spawns in the refectory at game start. The Inspect panel tags heavy items.
- **Skill books** (2026-10-21, owner): a skill book yields a skill in the fourth (book) slot. Reading costs 2 AP (the original's LEARN_BOOK cost), works on a book you carry or one on your room's floor, destroys the book, and is logged publicly in the room. One book per player per game; refused for a skill you already have; Mush can read too; the three normal slots need not be full. For now one book for every skill spawns on the bridge.
- **Skill picking** (2026-10-15, owner): all 58 human skills are pickable (57 since 2026-10-18: Mankind's Only Hope became Chun's trait) by everyone for now (each character will get its own set later). Picks are free, permanent, and need a free slot (3; the book slot is separate and later). Nobody starts with Creative any more. Skills are public to anyone in the same room as the player, and show only on the Inspect portrait (not the self panel); only your own portrait has the plus button. Most skills do nothing yet. Descriptions are not shown (they would be rules text). Supersedes the Creative-at-start and "not shown to anyone else" parts of the next entry.
- **Skills and Creative** (2026-10-15, owner): every player has 3 human skill slots; a fourth comes only from books (later). Players will be able to pick skills at any time through a UI (later). For now every player spawns with Creative in one slot and the other two empty. Creative: each failure of an action that cost AP has a fixed 50% chance to give back 1 AP (the retained `CREATIVE` row in `skills.json`; the older 25% `CREATIF` row is ignored). It can't exceed the 12 AP cap because the AP was just spent; no action costs MP. A refund writes a private log line. Skills are not shown to anyone else until there is a skills UI.
- **ACTOPI and the minimap** (2026-10-13): everyone's location stays visible on the minimap, but who is where is only known while the ship's ACTOPI system is on. With it off you know who is in your own room, and everyone else is an unnamed dot (`mush.png`). ACTOPI is a ship-wide in-game system state that starts on. What turns it off or on is **undecided**; for now it is only a flag (`GameState.actopi`) with nothing switching it.
- **Players:** 16 seats, 2 Mush. If 8 or fewer players are in the room when Mush are selected, only 1 Mush. Selection may happen later than game start (for example on a later day). The code still has the placeholder of 8 seats.
- **Joining and Mush selection** (2026-10-13): one plain queue per language. Joining puts a player into that language's open ship, which is in a pre-selection phase where no one is Mush. The game starts, and Mush are chosen, when the ship fills (16) or on day 3 cycle 8, whichever comes first, with whoever has joined. There is no minimum player count: 8 or fewer players get 1 Mush, more get 2. During pre-selection there are no spore actions (there are no Mush) and all combat is disabled. Multiplayer has no bots; bots exist only in single player. **Built 2026-10-24 (owner answers):** for now a ship has **4 seats** (so 1 Mush when it fills). The deadline is the **calendar** day 3 cycle 8 (#202): Mush are chosen as that cycle begins, so a ship launched late in a GMT day gets about 2 days, one launched at midnight 3. **Stopgap:** with fewer than 3 players aboard at selection, the Mush are chosen as usual and then every human dies at once, so the game ends with the Mush win (all humans dead). Each new Mush gets a private log line; the crew gets a system message in global chat that the Mush have been chosen and the ship takes no more crew, without names. Local dev servers behave the same (no bots there either). My readings, not asked: "all combat" is punch and weapons (`attack`); titles and the first rebel call wait for selection, as the titles and comms decisions tie them to it; the ship launches with its first joiner, and a joiner wakes with the start AP, HP, morale and iTrackie, their hunger count starting in the cycle they join.
- **Setups and ship voting** (2026-10-24, owner; Private beta): players can post a **setup** (a few coarse game settings, never fine-grained values like AP counts) and vote on which setup the next ship in their language's queue uses. Joining is unchanged: Join still puts a player into the open ship. The knobs: seat count 4–16 (standard 16); pre-selection length 1–5 days, still ending early if the ship fills (standard 3); Mush count Auto (the default, the player-count rule), 1, 2 or 3, at most the seat count minus 2 (a setup with 3 Mush of 4 seats is rejected: a deathmatch from the start), and at launch lowered to the number of players who joined minus 2, with at least 1; cycle length 1, 2, 3, 4 or 6 hours (standard 3; a day stays 8 cycles, so it shortens too); shared positions in a room on (standard) or off (`sharedSpots`). One vote per connection until accounts exist, then account holders only; until then the 5-setup cap is per browser too, accepted as easy to get around for private beta. The vote closes when the current open ship launches; a tie is broken at random among the tied setups; no votes means the standard ruleset, which is always on the ballot. At most 5 setups per player, no expiry for now. A posted setup is immutable; changes are posted as a new version. No analytics for setups for now.
- **Single player** (2026-10-13): 9 seats. The human is always the only Mush, against 8 bots who are all human. This overrides the player-count rule (9 players would otherwise get 2 Mush). Cycles advance when the player ends them, not on the timer. Stage not decided. **Bots and investigation (2026-10-24, owner; #222):** each bot plays its character's one primary role, derived from that character's skills in `heros.json` (Finola: researcher; Raluca: technician; the rest open in #222). Investigation and accusing are out of the MVP. Eleesha, Chun and Chao, the investigation characters, are never bots in MVP single player; the human may pick any character, those three included. The original's and eMush's skill lists give the same primary roles, so either source works. No per-character personalities. A post-game retrospective of the replay (#225) will inform bot investigation later.
- **Cycles:** AP refills on a timer, 3 hours per cycle and 8 per day (timer decided 2026-10-05, length 2026-10-13). There is no way to end a cycle early, so the "ready" action goes away. **Cycle timer** (2026-10-19, owner, #24, accepting a commenter's point that eMush days start at 00:00 GMT): cycles change on the UTC clock at 00:00, 03:00, … 21:00 GMT. A ship that launches mid-day starts on that cycle of day 1 (14:00 GMT is Day 1 · Cycle 5), so the first day is short. End cycle (`ready`) is kept for testing only, offered where the server allows cheats; the timer runs beside it. A dev-only `CYCLE_SECONDS` shortens cycles. Skill points (care, Computer) keep their current rules for now rather than resetting daily as in eMush; the other daily resets the commenter listed (commander missions, plant watering, Chun's glory) wait for those features. ## Phases

Each phase ends with typecheck and tests passing and a small commit. Phase headings note which open questions (now `rule-decision` issues) they wait on.

### Phase 1: rules core in `shared` (needs the infection, Sol, and death decisions)

- **Time as an input, not a clock read.** Add a `tick` that the server calls when a cycle boundary passes, for example `advanceCycles(state, n)`. The rules stay pure and tests can jump days instantly.
  - Tradeoff: the server owns real time and the rules only count cycles. That keeps rules deterministic, at the cost of the server having to compute how many cycles were missed after downtime.
- **Delete `ready`.** Cycles advance only on `tick`.
- **Player state additions:** HP, status effects (starting with `dirty`), spore count, and an inventory (minimal, only what the iTrackie needs).
- **Ship state:** spores extracted today (reset at each day boundary), the ship's position or Sol-return progress once the Sol trip is decided, and whether Mush have been selected yet.
- **Mush selection:** a separate step (`selectMush`, `shared/src/preselection.ts`, built 2026-10-24). It picks 1 or 2 Mush from the eligible players using the seeded RNG.
- **Actions:**
  - `extract_spore`: enforces the daily cap.
  - The infect action, once decided.
  - `hit`: decrements HP; at 0 HP the player dies.
  - The return-to-Sol action, once decided.
- **Win/end checks** after every action and tick. When the game ends, `phase: "ended"` records the winner.
- **Tests:**
  - Mush count is 1 vs 2 around the 8-player boundary.
  - The daily spore cap holds and resets on the day boundary.
  - Extracting a spore always applies `dirty`.
  - AP refills only on a tick, never by action.
  - Each win condition triggers correctly.
  - Determinism for a given seed.

### Phase 2: visibility and chat rules in `shared` (mostly built: global and private channels)

- **`viewFor`:**
  - A Mush sees the roles of the other Mush; everyone else still sees no roles.
  - Log entries get a scope: public, room, Mush-only, or private.
  - Tests check, for every seat, that a human's view has no roles except their own.
- **`say` action:** writes a room-scoped log entry and costs no AP (I'll assume no cost unless you say otherwise).
- **Global chat:** a separate message type allowed only for players holding an iTrackie.
- **Mush chat:** a channel filtered in `viewFor`, the same as the log scopes.

### Phase 3: server (needs the late-joiner and bot-seat decisions)

- **`GameRoom` timing:** use a Durable Object alarm for cycle ticks instead of `setTimeout`, so ticks survive restarts. On wake, apply any missed cycles.
- **Dev time scale:** an env var (for example `CYCLE_SECONDS=30` locally) so a "day" passes in minutes during testing.
- **Matchmaker:** 16 seats, plus the late-join behavior once decided.
- **Chat safety:**
  - A per-player chat rate limit.
  - A max message length.
  - A basic word-filter moderation hook, plain code with no new dependency to start.
  - A report/mute path deferred and noted.
- **Fix the known gap:** idle humans can no longer stall the game, because ticks ignore readiness.

- Show HP, status effects, spores (Mush only), and the cycle countdown.

- Still plain DOM, still driven only by `PlayerView`.

### Phase 5: local model bots

  - On 8 GB VRAM that leaves room for long prompts.
  - An ~8B Q4 model also fits but is tight.
  - Check current model rankings when picking a specific model.
- **Bot interface:**
  - The model-backed bot speaks the OpenAI chat-completions format, with base URL, model name, and key in `.dev.vars`.
  - Switching later to a cheap hosted API, or to Triton (which also offers an OpenAI-compatible frontend), is then a config change, not a code change.
  - When you want a cheap hosted fallback, compare current per-token prices; I have no live pricing.

- **Safeguards:**
  - The bot must pick from the legal actions in its view (`legalIn(view)`). Any invalid output falls back to the scripted bot.
  - Player chat goes into the prompt marked as untrusted quoted text.
  - A per-game request cap.
  - The "hard spend cap" becomes a token/request budget, kept so it still works if you switch to a hosted API.
- **Dependency note:** Ollama or llama.cpp is a system install, not an npm package. I'll ask before installing either.
