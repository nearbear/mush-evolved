# Implemented rules

What the rules code does today, one bullet per rule, naming where it lives. Moved out of `docs/code-map.md` so the map stays a list of files. Numbers come from `state.config` (`shared/src/config.ts`); when each value was confirmed is recorded there and in `docs/rules-design.md`, not here. Open work is in GitHub issues ([project](https://github.com/users/nearbear/projects/1)).

- **Action costs.** Each entry of `PlayerView.actions` carries its `cost`, read through `Action.cost` (the one place costs are read: legality, paying, and the view all go through it; subclasses set the base price in `getCost`). The client displays them and never computes them. Entries you can do now come first with empty `lacks`; then the ones you lack AP or MP for, with `lacks` naming which (`affordable`, `legalIn` in rules.ts).
- **Success chances.** Each `PlayerView.actions` entry's `chance` comes from the action's `chance`; action buttons show the odds in parentheses, e.g. "Punch (60%)", only when below 100%.
- **Action tags** (issue 30, owner 2026-10-18). Each action type declares `tags` (`ActionTag` in `actions/action.ts`), fixed per type like visibility, and each `PlayerView.actions` entry carries them so the UI can mark them (no UI yet). `aggressive`: punch and spike. `spore`: spike (not spore extraction, for balance).
- **Timed actions** (`queue.ts`; `PlayerState.current`, `PlayerState.queue`; `config.action`). Every action but `ready` and `access` (`timed = false`) takes `action.durationMs` = 2000 ms and happens when its bar runs out (`resolveAt: "end"`; `"start"` makes it happen at once, with the bar as a cooldown). Players act through `queueAction` (via `applyInput`): idle, the action starts; busy, it waits (at most `action.queueCap` = 3, else `queue_full`). The server stamps each action input with `at` and sends a `tick` input at `nextDue`; `tick` resolves due bars earliest first, then in seat order, through `performAction` (checked and paid then; being ready doesn't stop it) and starts the next queued action that is still legal. A dropped action costs nothing and writes a private `actionDropped` line. Each queued entry records `Action.adjustment` (how far modifiers moved its price) when queued; if the adjustment differs when it starts or resolves, it is cancelled with a private `actionCostChanged` line giving the new price, and nothing is paid (owner, 2026-10-18). Base-price changes the queue itself causes (a move's AP-to-MP conversion, a care point used up) don't cancel. The view sends `you.queue` as plain actions and `you.current` without the adjustment. `clearQueue` cancels the queue and, with "end", the action under way. Death clears both. `OtherPlayerView.busy` (times only) goes to people in the actor's room when `activitySeen` (log.ts): public and secret always, covert on camera, private never.
- **Cycles** (#24; `newCycle` in rules.ts, `server/src/cycleClock.ts`). Cycles change on the UTC clock, every 3 hours from midnight GMT, so a day starts at 00:00 GMT. The server sends a `cycle` input at each boundary (one storage alarm for the earliest bar or boundary; after downtime it applies every missed one in time order), and `newCycle` runs `advanceCycle` for everyone, ready or not. A ship launches on the clock's cycle of day 1 (`GameSetup.startCycle`, so 14:10 GMT is Day 1 · Cycle 5). End cycle (`actions/ready.ts`) is offered only with `config.manualCycles` (false by default; the server sets it from `ALLOW_CHEATS`, and single player can use it later): `ready` marks you done, and once every living player is, `performAction` calls `advanceCycle` early, so on the dev server the cycle number can run ahead of the clock. `CYCLE_SECONDS` in `server/.dev.vars` shortens cycles for testing. The view message carries `nextCycleAt`; the top bar (phone: under the name) counts down to it.
- **Movement, AP, HP, morale** (`actions/move.ts`, `moveCost` in `modifiers.ts`). 1 MP per move; with no MP, 1 AP converts to 3 MP; MP starts at 0, cap 12, kept across cycles. AP: start 8, +1 per cycle, cap 12, unspent AP carries over; +2 while lying in a bed once that exists. HP and morale: max 14 each, start at 14 HP and 7 morale, visible only to their owner; each living player loses morale when a day ends (`dailyMoraleLoss` in `modifiers.ts`: `config.moralePerDay` = 2, cut by 1 while Chun lives, see Mankind's Only Hope below; floor 0). Days: `config.cyclesPerDay` = 8; `state.cycle` stays a global counter and `dayOf` derives day and cycle-of-day, both sent in `PlayerView`; the day boundary is handled in `advanceCycle`.
- **Room log** (`log.ts`). Public entries are the room's history, shown to anyone in that room; private entries only ever reach the actor; secret entries become room history if another player witnessed them or a camera is in the room; covert entries become room history only if a camera is in the room (bystanders never see them). A camera is, for now, a `camera` item in the room's inventory (`hasCamera`; one carried by a player doesn't count); a camera reveals the entry to everyone, overriding `hideFrom`.
- **Identity** (owner, 2026-10-17). Players know each other only by character (`Seat.character`; `characterName` in `characters.ts`). Account names (`Seat.name`) stay in server state but are in no view, your own included: `viewFor` strips `name` from `you` (`YouView`) and `OtherPlayerView`, rebuilds chat messages field by field (`ChatMessage` has no name), and log and system-message params carry character ids (`name`, `target`, `body`), which the client's `names.logLine` turns into names. Bots are still tagged AI (`isBot`). Revealing names when the game ends waits on game completion (#191, blocked by #27).
- **Examine** (`actions/examine.ts`, free). On anyone in your room including yourself, the room's equipment, your items, and the room's items; writes a private log line.
- **Inventory.** 3 private slots per player (`config.inventorySlots`, `inventorySlots` modifier hook); rooms hold unlimited items, visible to whoever is there. `take`/`drop` (`actions/transfer.ts`) cost nothing and are logged publicly. Items are effect-less placeholders except coffee, food, and the items below. Actions make items in two ways: `produceItem` in `items.ts` hands one to the player (into your inventory, or into the room if it's full, "knocked over"; dispense uses it), and dismantle puts its scraps straight into the room.
- **Dispense** (`actions/dispense.ts`). Equipment can dispense an item (`EquipmentType.dispenses`): free, once per cycle per machine (`GameState.dispensedOn`), offered on the refectory's coffee machine; 5% chance to become dirty.
- **Consume** (`actions/consume.ts`, free). An item you carry or one in your room (`ItemType.consume`) is removed and gives AP up to `maxAp`; coffee gives 2 AP and 1 satiety, the placeholder `cooked_ration` 4 satiety, and an `uncooked_ration` 4 satiety for 1 morale (`ItemType.consume.morale`, kept within 0 and `maxMorale`). 15% chance to become dirty.
- **Build** (`actions/build.ts`, `blueprints.ts`). A `blueprint` item carries a recipe key in `ItemState.builds` (also in `ItemView`). Anyone can build, anywhere, for `build.cost.ap` = 3, no failure chance. Ingredients are items in your inventory or on the room floor (floor first); the blueprint and ingredients are always consumed and the equipment is added to the room (`state.config.equipment[room]`, id `ROOM:TYPE:n`); public room log (`built`). 25% chance to become dirty. Recipes: SOFA (metal scraps + thick tube; makes equipment) and MISSILE_LAUNCHER (thick tube + metal + plastic scraps; makes an effect-less `missile_launcher` item via `produceItem`: inventory if there is room, else the floor; log `builtItem`). One blueprint of each spawns in CORRIDOR_A, with two thick tubes and two metal scraps (stand-ins so both can be built). A room can have any number of sofas. The iso view draws the room's first sofa at a hand-picked spot (`SOFA_SPOTS` in `web/src/iso/equipmentTiles.ts`; none in the Nexus or hydroponics); further sofas work but aren't drawn (the original lists them on the shelf, not built).
- **Cook** (`actions/cook.ts`). In a `cook.rooms` room (REFECTORY), `cook.cost.ap` = 1, on an item whose type has `ItemType.cook` that you can reach (carried or on the floor); it changes type in place (`uncooked_ration` becomes `cooked_ration`, same container); public room log (`cooked`); 25% chance to become dirty. Three `uncooked_ration` spawn in the refectory; they can also be eaten raw (see Consume).
- **Express cook** (`actions/express_cook.ts`). `expressCook.cost.ap` = 0, in any room, on a reachable item with `ItemType.cook`, while you can reach (carried or on the floor) a `microwave` with charges left. Spends one of its `ItemState.charges` and cooks the item in place like Cook; public room log (`expressCooked`); 5% chance to become dirty. The microwave (heavy) spawns in the refectory with `expressCook.charges.start` = 4, regains `perDay` = 1 at each day start up to `max` = 4 (`rechargeMicrowaves` in `items.ts`); charges show on the Inspect panel. Consequences of using it are not built.
- **Dismantle** (`actions/dismantle.ts`). On a reachable item whose type has `ItemType.dismantle`; `dismantle.cost.ap` = 3, `dismantle.successChance` = 0.12. Success removes the item and puts its metal and plastic scraps in your room (public log `dismantled`); failure writes a private `dismantleFailed` line.
- **Chat** (`chat.ts`). Everyone starts with an iTrackie (`config.startInventory`; item type `ITRACKIE_ITEM` = `super_talky`, after its icon), a normal item that uses a slot and can be dropped or taken. Carrying one opens global chat and the eight crew-wide feature threads (`FEATURE_CHANNELS` in `types/chat.ts`: botany, research, inventory, space battle, comms, pilgred, neron, astrophysics), for reading and posting, including the full history. History is capped per channel (`CHAT_HISTORY`).
- **Mush channel** (`MUSH_CHANNEL` = `mush`, in `types/chat.ts`). In `chatChannels` for living Mush only, no iTrackie needed; `contaminate` posts system messages into it (`mushContaminated` with name, level, capacity; `mushConverted` with name; `ChatMessage.from` is null and `system` holds the key and params; `pushChat` in `chat.ts`); no client tab yet.
- **Private channels.** `createChannel`, `inviteToChannel`, `leaveChannel` sit outside the action registry like `sendChat`; ids `pc-N`, limit via the `channelLimit` modifier; errors are codes. `viewFor` filters them to their members.
- **Threads** (`createThread` in `chat.ts`). Discord-style threads under global chat, ids `th-N` (`ThreadId`, part of `ChannelId`), stored in `GameState.threads`. `chatChannels` and `readChannels` add every thread id wherever they add global chat, so posting, reading, checkboxes and `viewFor`'s chat filter need nothing extra; `PlayerView.threads` lists them to anyone who can read global chat. Optional `from` = the global message it started from (one thread per message). No count cap. Errors: `thread_forbidden`, `thread_name_invalid`, `thread_exists`, `message_not_found`.
- **Markdown chat.** Moderation keeps line breaks (up to `MAX_CHAT_LINES` = 12, still `MAX_CHAT_LENGTH` characters); the client draws messages with `web/src/hud/Markdown.tsx` (react-markdown + remark-gfm; bold, italic, strikethrough, headers, lists, quotes, code, and task lists, but no links, images, tables, or raw HTML). `toggleCheckbox` (`chat.ts`, outside the action registry, wire message `toggleCheckbox` with `message` id and 0-based source `line`) ticks or unticks a `- [ ]` item in the message text; only the author may, and only while they can still read the channel. Errors are codes (`message_not_found`, `message_not_yours`, `checkbox_not_found`).
- **ACTOPI** (`GameState.actopi`, starts on; nothing switches it yet; the `setActopiCheat` dev cheat overrides how it looks to one player via `PlayerState.actopiCheat`). While on, `viewFor` sends every player's room; while off, players outside your room lose their `room` and appear only as bare room entries in `PlayerView.unidentified` (sorted by room, so order leaks nothing). `Minimap` draws mini portraits for people it can identify and `mush.png` for the rest (the minimap is not rendered right now; see `TODO(minimap)` in `GameScreen.tsx`).
- **Alpha flag.** Each player has an `alpha` flag (set for the Mush chosen at the start; player terminology only, nothing uses it, and it only appears in your own `you`). The player summary shows a faction icon (human, alpha or beta Mush) with a goal popover.
- **Bonding** (`actions/bond.ts`, `actions/share.ts` for `dtt` and `stt`; `GameState.bonds`, `sharedOnDay`, `contamination`). `bond.cost.ap`, `share.cost.ap` = 1; `share.effect.morale` = 2 each. `PlayerView.bonds` carries only your own bonds, and contamination is in no view; capacity via the `contaminationCapacity` modifier.
- **Spore extraction** (`actions/extract_spore.ts`). Mush only; `spores.cost.ap` = 1, `spores.effect.spores` = 1 into `PlayerState.spores`; per-Mush cooldown `spores.cooldownCycles` = 4 via `GameState.sporeExtractedOn`; faction daily cap `spores.perDay` = 4 (`sporesPerDay` modifier-folded), counted in `GameState.sporesToday` and reset in `advanceCycle`; secret log (2026-10-17); always applies `dirty`; spores appear only in your own `you`.
- **Spiking** (`actions/spike.ts`). Mush only, `spike.cost.ap` = 1 AP and 1 spore, target a living human in your room, contamination +1; covert (`logCovert`): only a camera in the room reveals it, and then to everyone, the victim included.
- **Infection** (`infection.ts`). `contaminate` is the one way contamination rises (spike and DTT call it); reaching `infection.capacity` = 3 (`contaminationCapacity` modifier) converts the human at once (`role` = mush, `alpha` = false, contamination entry removed, satiety cleared; skills, HP, and morale stay; spore extraction is ready immediately), with a private `converted` log line that names nobody. No cure. A convert does not yet learn who the other Mush are (#39). Mush see a contaminated human's level as a status (`OtherPlayerView.contamination`, via `contaminationSeenBy`; only for living humans in their room with level > 0; never in a human's view, their own included); `StatusIcons` draws it as the spore icon with the number.
- **Statuses and satiety** (`statuses.ts`). `PlayerState.statuses` stores `dirty`; `full_belly` and `hungry` are derived by `statusesOf`/`isFullBelly`/`isHungry`, and `STATUS_PUBLIC` says which are public. Humans have `satiety` (start 0, loses `hunger.satietyPerCycle` = 1 per cycle via the `satietyPerCycle` modifier hook, floor 0) and `satietyZeroSince`, the cycle it reached 0 (starts at cycle 1); `hunger.fullBellyAt` = 3 satiety is full belly, and `consume` is refused (`full_belly`); `hunger.hungryAfterCycles` = 24 after that cycle, hungry costs `hunger.hpPerCycle` HP per cycle in `advanceCycle` (through `damage`, so it can kill); any consumable resets the count. Mush have no satiety or hunger and eat freely. `PlayerView.statuses` is all your own statuses; `OtherPlayerView.statuses` only public ones, only for people in your room. The client shows them with `StatusIcons` (Inspect panel; select yourself to see your private ones) and public ones with `StatusBadges` over heads in the room.
- **Accessing a terminal** (`actions/access.ts`; equipment with `EquipmentType.terminal`: Astro, Command, Com center, NERON core, BIOS, Research lab, Pilgred, Calculator). Free, no restrictions, no state change; the client opens a blank window titled with the terminal's name (`TerminalDialog`). The terminals' own actions are not built, except research at the Research lab, NERON projects at the NERON core, planet scanning at the Astro terminal, and repair at PILGRED.
- **Research** (`actions/research.ts`, `research.ts`; `GameState.research`, percent per research id, public in `PlayerView.research`). At the lab's research terminal (`RESEARCH_LAB`), a living, not-dirty player spends 2 AP to advance one research 25% (`config.research`). Each research action has a 25% chance to make the researcher dirty, including Computer-point-free actions; NERON projects do not have this chance (owner, 2026-10-20). No repeat penalty. The 24 researches that have card art are listed; difficulty, samples, prerequisites and completion effects are not used yet. The client lists them, with a work button each, in the terminal window. Public room log lines `researched` / `researchCompleted`. Each research shows an implementation status badge (`RESEARCH_STATUS` in `research.ts`, like `SKILL_STATUS`); only researches with completion effects read "Implemented" (`RESEARCH_STATUS`). **Mush-eating bacteria** (`MUSHOPHAGE_BACTERIA`, full; owner, 2026-10-17): once complete, every human's contamination capacity is 4 instead of 3 (`config.infection.mushophageBonus`, added in `contaminationCapacity`). Humans already at 3 stay human until they reach 4. **Myco alarms** (`MYCO_ALARM`, partial; owner, 2026-10-17, `mycoalarm.ts`): completing it drops three `myco_alarm` items on the lab floor (public log `mycoAlarmsBuilt`). An alarm on a room floor (not carried) rings once per trigger however many are there, with a public room-log line `mycoAlarmRang` that names no one, readable by anyone who is later in the room. It is not used up, and anyone can dismantle it for one metal scrap through the normal dismantle action. Any action tagged `spore` rings it when it resolves, success or failure (`performAction`; owner, 2026-10-18). Only spiking has the tag so far (the comment in `mycoalarm.ts` lists the nine Mush abilities that get it when built); extracting never does. No `danger` log level yet (#20).
- **NERON projects** (`actions/project.ts`, `projects.ts`; `GameState.projects`, percent per project id, public in `PlayerView.projects`). Built exactly like research (owner, 2026-10-18): at NERON's core in the Nexus (`NERON_CORE`, not the BIOS terminal), a living, not-dirty player spends 2 AP to advance one project 25% (`config.project`), free with a Computer point (spent). No repeat penalty; every project is open at once (not the original's 3 proposals). All 41 projects in the original's live list (`projets.json` above `$EOF`, the 10 'plus' ones included, not PRICE_HACKER) can be completed; no completion effects yet (`PROJECT_STATUS` is empty). The NERON core's terminal window reuses the research list. Public room log lines `projectWorked` / `projectCompleted`.
- **PILGRED repair** (`pilgred.ts`, `actions/repair_pilgred.ts`, `modifiers/physicist.ts`; `GameState.pilgred`; owner, 2026-10-21, plan in `docs/scratchpad/pilgred-plan.md`). At the PILGRED terminal (`MOTOR_ROOM`), any living player, Mush and the dirty included, spends `pilgred.cost.ap` = 2 AP (free with a PILGRED point, which is spent) to advance the repair by the original's slow formula (`pilgredGainRange`): `floor(rate 6 × mod 2 / 10)` = 1, +`skillBoost` 4 for each of Engineer and Physicist, −`relayPenalty` 2 for each repair in a row by the same player (relaying: `lastBy`/`streak`, reset when someone else repairs), never below 0; the gain is rolled in [min, min + min/2] (1, 5–7, or 9–13 before the penalty). 25% dirty chance (`pilgred.dirtyChance`). Each repair is a public room line `pilgredRepaired` without the percent; reaching 100% logs `pilgredDone` instead and posts a crew-wide system message `pilgredDoneCrew` in global chat, after which it is no longer offered. `PlayerView.pilgred` is the percent only for the living in a room with the terminal, else null; `lastBy` and `streak` are never sent. Physicist: +`pilgred.pointsPerDay` = 1 PILGRED point at each day start (`pilgredPointsPerDay` fold), up to `capPoints` = 2, none when picked. The terminal window shows the card, description, progress and the repair button. Not built: return to Sol and the game end it triggers, Eden, breaking again, the reactor art swap, Raluca's triumph, the alien merchant repair.
- **Planets** (`planets.ts`, `actions/scan_planet.ts`, `analyze_planet.ts`, `delete_planet.ts`; `GameState.planets` and `scanFailures` per player; owner, 2026-10-19, plan in `docs/astro-plan.md`). Each player's planets are **private**: only their own view has them (`PlayerView.planets`), and unknown sectors come as `null`. At the Astro terminal (`ASTRO_MODULE`, Bridge), a living, not-dirty player (Mush too) can **scan** for 3 AP at 50%. Each failed scan in a row multiplies that player's next chance by 1.25, up to 100%, and a success resets it. A found planet follows the original's generator: 2 to 12 sectors drawn by weight from 22 tags with per-planet limits, shuffled, with a syllable name. The one difference: an exhausted tag leaves the weight total, so every sector gets a tag. The cap is 2 planets per player (`config.astro`). **Analysis** (2 AP, own planets, not dirty) reveals one unknown sector, weighted by the tag's `seek`. **Delete** removes one of your planets: free, anywhere, at once, silent, from a bin button in the Astro window or the self panel. Room log: `scannedPlanets` whether the scan worked or not (no planet name), and `analyzedPlanet` with the planet's name, never sectors. The scanner alone gets `planetFound` (with the name) or `planetNotFound`. No travel, orbit, exploration, or scan modifiers (Astrophysicist, CHIPSET_ACCELERATION, PLANET_SCANNER) yet.
- **Lying down** (`actions/lie_down.ts`, #34; `EquipmentType.bed`: BED and SOFA). `lie_down` is free (`lieDown.cost.ap` = 0) and adds the `lying_down` modifier (+1 AP per cycle). `get_up` removes it, and so does any other timed action including a move, from the moment it is queued (`queueAction` calls `getUp`; `performAction` too, for instant ones; `ready` is not timed). No other effects. Moving to another room still works and gets you up; only the client's walking about the room is blocked while lying (`get_up` is offered on yourself in Inspect and the peek bar). `PlayerState.lyingIn` is the bed's equipment id, cleared with the modifier; `OtherPlayerView.lying` shows it to people in the same room, and `you.lyingIn` to yourself. The client draws them in the corpse's lying pose on the bed, mirrored to run along it.
- **Where you stand** (`spot.ts`, #17/#21; owner, 2026-10-20). `PlayerState.spot` is a floor cell (`{ x, y, sitting? }`) or the door you came in by (`{ door }`, set by `arrive` in a move and in `wheelAlong`); unset until then. The `walk` input (protocol and `applyInput`, not an `Action`) sets it for free; refused (`cant_walk`) when dead, in bed, pushed, the game is over, or the cell is not a whole number within `MAX_SPOT_CELL`. The rules don't know cells, so the client treats a spot off the room's floor as none. `queueAction` stands you up from a chair for public actions only (`standUp`; others would give away an unseen action), while your own screen stands you up for any. `OtherPlayerView.spot` goes to living roommates only. The client sends floor and chair clicks, and act-walks for public actions (`ActingOn.share`); others walk to their spot and sit once they reach the chair. The server sends views again only to the walker's room after a walk. `config.sharedSpots` (on by default) switches it all off for a future game setting: `walk` is refused, no spot is sent, and the client (`PublicConfig.sharedSpots`) stops sending walks.
- **Wheelchair and accommodating** (`actions/accommodate.ts`, `modifiers/wheelchair.ts`; owner, 2026-10-19). Terrence starts with the `wheelchair` trait (`config.characterModifiers`; public, permanent `wheelchair` status, Inspect only). Any living other person in his room can `accommodate` him (offer to push; `accommodate.cost.ap` = 0); the offer is stored in his `PlayerState.accommodationOffers` (his own view only) with an expiry time, and lapses after `accommodate.offerMs` = 5 minutes of server time (silently; `nextDue` includes offer expiries, so the server ticks for them, and `tick` drops them through `expireOffers`), or when the offerer leaves the room or dies. Offers read the time from `GameState.now`, the server time of the latest action input or tick (set in `queue.ts`; never sent). He starts the push with `accept_accommodation` on one offerer (free), which sets `PlayerState.pushedBy` and clears all offers. While pushed he has no moves (`being_pushed`), and when the pusher moves, he is moved with them at no AP or MP cost, out of bed, with his own left/entered lines (`wheelAlong`); the pusher pays an ordinary move. Either of them ends it with `stop_accommodation` (free, and untimed: it happens at once, skipping the queue); either one's death ends it (`endAccommodationOnDeath` in `killPlayer`). Offer, start and end are public room log lines (`accommodationOffered`, `accommodated`, `accommodationEnded`); roommates see the `accommodated` status (also over his head) and `OtherPlayerView.pushedBy`. The client blocks his walking about the room while pushed, like lying down; it does not yet keep him beside his pusher in the room view. Both statuses use the original's `disabled` (wheelchair) icon.
- **Showering** (`actions/shower.ts`; equipment with `EquipmentType.shower`, i.e. the SHOWER in both bedrooms). Offered only while dirty; `shower.cost.ap` = 2, 1 less (`shower.cost.soapDiscountAp`) with `soap` in your inventory (soap is not used up); removes `dirty`; a Mush also loses `shower.effect.mushDamage` = 4 HP (through `damage`, so it can kill); private log. One soap spawns in BEDROOM_A (`startItems`).
- **Hydropots** (`tree_pot`, the original's TREE_POT, named after its icon; 2026-10-18). Five spawn in the LABORATORY at the start (`startItems`). No effect yet: they can only be taken, dropped, and examined.
- **Healing** (`actions/heal.ts`). Needs a `medikit` in your inventory (reusable; one spawns in SICK_BAY); target is you or a living person in your room; `heal.cost.apOther` = 2, `heal.cost.apSelf` = 3; restores `heal.effect.hp` = 3 HP (`healAmount` modifier hook; the `medic` skill adds `heal.effect.medicBonusHp` = 2, its other perks are not built), capped at `maxHp`; offered even at full HP; public room log (`healed`, `healedSelf`); 5% chance to become dirty. Sick bay: in a `heal.rooms` room (SICK_BAY) anyone can heal without a medikit, same AP costs.
- **Care points** (`resources.ts`). `resources.heal`: while above 0, a heal costs 0 AP and spends one automatically (`HealAction.healCost`). The `carePointsPerDay` hook is granted by `grantCarePoints` (rules.ts) at game start and each day boundary; they stack with no cap. The nurse (`first_aid`) skill adds `heal.effect.nursePointsPerDay` = 2 that way, built by `careSkill` in `modifiers/careSkill.ts`, which also sets the `onPick` hook (run by `pick_skill` through `skillPicked`): picking the skill grants the same amount at once. Skills with a one-off effect on pick (a future shooter's free shots) use `onPick` the same way; there is no skill base class, since hooks fold over the registry and factories compose.
- **Cost modifiers.** `Action.cost` folds `getCost` through the actor's `actionCost` hooks, then every `roomActionCost` hook of the living players in the actor's room (the holder's own actions included), in seat order; holders stack. Hooks can't push a price below 0 (or below a negative base, as a move's net MP). Room effects are computed on demand, never stored. **Pacifist** (`modifiers/pacifist.ts`, owner 2026-10-18): Ian starts with it (`config.characterModifiers`); aggressive actions in his room cost `pacifist.aggressiveApSurcharge` = 2 more AP, his own too. Kept on conversion. Shown as the public, permanent `pacifist` status (derived from the modifier in `statuses.ts`, icon `status/pacifist.png`, hover card in `StatusIcons`); it can't be removed.
- **Punch** (`actions/punch.ts`, issue 29). `punch.cost.ap` = 1; target is a living other person in your room; rolled through `getSuccessChance` = `punch.successChance` = 0.6 (40% miss); a hit removes `punch.effect.damage` = 2 HP (`punchDamage` modifier hook; through `damage`, so it can kill); hit and miss are both public room log (`punched`, `punchMissed`); a miss is a failed action (`fail`), so Creative can refund.
- **Action failure.** An action with a `getSuccessChance` below 1 is rolled once by `applyAction` (seeded RNG) after the cost is paid, then runs `apply` or `fail`, then every `onActionFailed` modifier hook. Dismantle and punch have a chance today.
- **Skills** (`skills.ts`, `actions/pick_skill.ts`). `PlayerState.skills` holds skill ids, which are modifier ids in `modifiers.ts` (every hook folds over `modifierIds(player)`, skills first). Nobody starts with a skill (`config.startSkills` = []). `skills.ts` lists the 57 pickable human skills (Mankind's Only Hope is Chun's trait instead) (`SKILLS`) and `SKILL_SLOTS` = 3, plus the book slot (below). `pick_skill` is free and permanent, refused for a skill you have, an unknown id, or with no free slot; it writes no log line and is offered once per unowned skill in `legalActions`. Skills are public: `OtherPlayerView.skills` carries them for people in your room only (empty elsewhere). Most skills have no rules yet; picking one is harmless. The client draws `SkillSlots` (`web/src/hud/SkillSlots.tsx`) over the Inspect portrait: filled slots show the icon, your own empty slots a gold plus that opens a picker dialog built from the `pick_skill` entries in `legalActions`, and other players' empty slots are inert.
- **Skill books** (`actions/read_book.ts`; owner, 2026-10-21). A `book` item (`BOOK_ITEM`, the original's Apprentron) carries a skill id in `ItemState.teaches` (also in `ItemView`, so whoever sees the book sees its skill). `read_book` costs `readBook.cost.ap` = 2, on a book you can reach (carried or on the floor); the skill goes into the book slot, `PlayerState.bookSkill`, for good, and the book is destroyed; public room log `bookRead`. One book per player (refused once the book slot is filled), refused for a skill you already have (and `pick_skill` refuses the book's skill); Mush can read too; the normal slots need not be full. `skillsOf`/`hasSkill` in `skills.ts` cover both, and `modifierIds` includes the book skill. Roommates see it as `OtherPlayerView.bookSkill`. For now one book per skill (57) spawns on the bridge (COMMAND_CENTER, `startItems`). The client draws the book slot as a fourth, dashed slot under the three on the Inspect portrait (no plus; the Read action is on the book item).
- **Heavy items.** `ItemType.heavy` (the `freezer`, which spawns in the refectory); `carriesHeavy` in `items.ts`; `movementRules` adds `heavy.mpPenalty` = 2 to `mpPerMove` once if you carry one, unless a modifier zeroes the `heavyMpPenalty` fold (`sturdy`, which also adds `punch.effect.sturdyBonusDamage` = 1 through the `punchDamage` hook).
- **Antic perfume** (`modifiers/antic_perfume.ts`). Each shower makes you immune to infection for `anticPerfume.immuneCycles` = 2 cycles (`immuneUntil`); a new shower resets the count rather than stacking. `contaminate` does nothing while immune, silently. The `immune` status is private to its owner.
- **Computer Scientist** (`modifiers/computer.ts`, skill `computer`, partial; owner, 2026-10-16). Grants `computer.pointsPerDay` = 2 Computer points (`resources.comp`, private) when picked and at each day start (`computerPointsPerDay` fold, applied in `grantCarePoints`), capped at `computer.capPoints` = 4; they carry over. One Computer point makes one research or NERON project action free (0 AP instead of 2) and is spent (`ResearchAction.getCost`, `ProjectAction.getCost`; projects added 2026-10-18, owner); it is not exchanged for the AP. Corrected by the owner the same day. No hacking.
- **Logistics** (`modifiers/logistics.ts`, skill `logistics`, fully implemented). Its `onCycle` hook (run by `cycleChanged` in `advanceCycle`, after the AP refill) gives `logistics.ap` = 1 AP to one random living other player in the same room below the AP cap (Mush count; seeded RNG), free for the giver; nothing if nobody qualifies. Giver and recipient each get a private log line (`logisticsGave`, `logisticsGot`).
- **Creative** (`modifiers/creative.ts`). After a failed action that cost AP, a `creative.refundOdds` = 50% roll gives 1 AP back, with a private log line (`creativeRefund`).
- **Caffeinomaniac** (`modifiers/caffeinomaniac.ts`, skill `caffeinomaniac`, fully implemented). Its `onConsume` hook (run by `consumed` in `modifiers.ts` from the consume action, after the item's own AP and satiety) gives `caffeinomaniac.ap` = 2 extra AP when the item is a `coffee`, capped at `maxAp`. No log line. The NERON project bonus is not built.
- **Antique Perfume** (`modifiers/antic_perfume.ts`, skill `antic_perfume`, fully implemented). Its `onShower` hook (run by `showered` in `modifiers.ts` from the shower action) sets `PlayerState.immuneUntil` = current cycle + `anticPerfume.immuneCycles` (2); a new shower resets it, no stacking. `contaminate` does nothing while `isImmune` (silent, every source). Shown only to its owner as the private `immune` status (Mush `immune.png` icon).
- **Cameras** (`actions/install.ts`, `uninstall.ts`, `dismantle.ts`, #35). An installed camera is `CAMERA` equipment (`<ROOM>:CAMERA`, one per room); `hasCamera` looks only at that, so a `camera` item never films. `install` (1 AP, no tool) uses up a carried camera item and adds the equipment; `uninstall` (`uninstall.cost.ap`, 1 AP) removes it and gives you a camera item; `dismantle` of the equipment removes it and leaves a metal scrap (usual 3 AP, 12%); all are logged publicly. Installation has a 10% dirty chance, uninstalling 5%. The iso view draws the room's camera tile only when the room has the equipment, and it is clickable like other equipment.
- **Sofas** (`equipment.ts`, owner 2026-10-18, from the French wiki). `SOFA` is a bed (`lie_down`, `get_up`, +1 AP per cycle) and `builtOnly`: the map's sofa in LASER_TURRET_B_0 is left out of the starting equipment (`roomGraph` in `tools/src/shipLayout/convert.ts`) and of the drawn layout (`withoutBuiltOnly`). Built from its blueprint (see Build), any number per room. `dismantle` works on any equipment with `EquipmentType.dismantle` scrap (CAMERA: 1 metal; SOFA: 1 plastic), at the usual cost and odds, logged `dismantledEquipment` (public) or `dismantleEquipmentFailed` (private); whoever lies on a dismantled sofa gets up. Not built: getting up when it breaks or is boarded onto the Icarus (neither exists yet), repairing it.
- **Death** (`death.ts`, #28). `damage` is the one way HP goes down (floor 0; `tools/src/death/hpWrites.test.ts` fails if any other file but `cheats.ts` and `actions/heal.ts` writes `.hp`); at 0 it calls `killPlayer`, which sets `alive` = false, destroys the iTrackie, drops the rest of the inventory into the room, adds a heavy `corpse` item (`CORPSE_ITEM` in `items.ts`; `ItemState.of` = whose body, not yet in `ItemView`), voids bonds both ways and contamination, takes them out of every private channel (`removeFromChannel` in `chat.ts`, with a `leftThisWorld` system message in each channel that still has members), logs a public `died` line in the room (character only) and posts `diedHuman`/`diedMush` to global chat. The `infiniteHp` cheat keeps HP full instead, and `applyCheats` skips the dead. The dead player's view (#45, in `viewFor`): `readChannels` (`chat.ts`) gives the dead global chat and the feature threads without an iTrackie, plus the Mush channel for a dead Mush, while `chatChannels` (what you may post to, also used by `toggleCheckbox`) holds only the **graveyard** (`GRAVEYARD_CHANNEL`, dead players only, read and post, no iTrackie; the iTrackie shows a skull tab for it); `PlayerView.readChannels` and `chatChannels` carry both, and the iTrackie shows a channel's messages from the first and offers the chat box from the second. The dead get nothing room-based: no room items or equipment, only ship-wide log entries (cycles, days; their own private lines go too), no `unidentified` head counts, and nobody's room, statuses, skills, or contamination. For everyone, a dead player has no `room` in `OtherPlayerView` and is not counted in `unidentified`: the corpse item is what's in the room. Carrying a corpse is ordinary `take`/`drop` (one slot, heavy). **Jettison** (`actions/jettison.ts`): destroys a corpse you carry while you are in a `jettison.rooms` room (SPACESHIP_BAY_A, SPACESHIP_BAY_AA, SPACESHIP_BAY_B, ICARUS); `jettison.cost.ap` = 0; secret (`logSecret`, `jettisoned` with the actor's and the body's characters). The client draws corpses on the floor lying down and shows the dead a death notice instead of the room. Leaving the ship after death is #182.
- **Titles** (`titles.ts`, #144; owner, 2026-10-20). Commander, NERON Admin and Comms Officer (`TITLE_IDS`), each with a line of succession (`SUCCESSION`, a commenter's proposal adopted by the owner; Andie and Derek are listed but nobody plays them). `createGame` issues each to the first eligible person in its line, whatever their role (`GameState.titles`, player id or null). `killPlayer` calls `refreshTitles`: a holder who is no longer eligible (`eligibleForTitle`: alive; inactivity joins it with #145) passes the title to the first eligible person in the line (`successor`), so a former holder never takes it back except through that succession; nobody eligible leaves it vacant until someone is. Each change posts `titlePassed` or `titleVacant` to global chat (no room log line). Public: `PlayerView.titles` gives each title's holder and its line as it stands aboard, by character. The client shows them as ID-card chips in the self panel (Inspect tab on phones) with the line in a popover. Not built: the Politician skill's usurping, and what titles let you do.
- **Win conditions** are intentionally absent. Their decisions are in `docs/rules-design.md`, with the remaining open questions in the `rule-decision` GitHub issues.
- **Traits and Chun's Immunity** (`config.characterModifiers`, `modifiers/immunity.ts`). A trait is a starting modifier tied to a character (Ian: `pacifist`, Chun: `immunity` and `mankind_only_hope`). `immunity` has no hooks; `isImmune` (`statuses.ts`) is true for its holder, so `contaminate` does nothing. Shown as the public, permanent `immunity` status; traits (`TRAIT_STATUS_IDS`) are left off the over-head badges.
- **Chun's Mankind's Only Hope** (`modifiers/mankind_only_hope.ts`, the `crewMoraleLoss` hook). A trait, not a pickable skill. While its holder is alive (human or Mush), the whole crew's daily morale loss is cut by `config.mankindOnlyHope.moraleLossCut` = 1, so it is 1 with Chun alive and 2 once she dies or when she isn't in the game. Shown as the public, permanent `mankind_only_hope` status (skill icon stands in), off the over-head badges.
