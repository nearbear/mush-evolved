# Implemented rules

What the rules code does today, one bullet per rule, naming where it lives. Moved out of `docs/code-map.md` so the map stays a list of files. Numbers come from `state.config` (`shared/src/config.ts`); when each value was confirmed is recorded there and in `docs/rules-design.md`, not here. Open work is in GitHub issues ([project](https://github.com/users/nearbear/projects/1)).

- **Action costs.** Each entry of `PlayerView.actions` carries its `cost`, read through `Action.cost` (the one place costs are read: legality, paying, and the view all go through it; subclasses set the base price in `getCost`). The client displays them and never computes them. Entries you can do now come first with empty `lacks`; then the ones you lack AP or MP for, with `lacks` naming which (`affordable`, `legalIn` in rules.ts).
- **Success chances.** Each `PlayerView.actions` entry's `chance` comes from the action's `chance`; action buttons show the odds in parentheses, e.g. "Punch (60%)", only when below 100%.
- **Action tags** (issue 30, owner 2026-10-18). Each action type declares `tags` (`ActionTag` in `actions/action.ts`), fixed per type like visibility, and each `PlayerView.actions` entry carries them so the UI can mark them (no UI yet). `aggressive`: punch and spike. `spore`: spike (not spore extraction, for balance).
- **Timed actions** (`queue.ts`; `PlayerState.current`, `PlayerState.queue`; `config.action`). Every action but `ready` and `access` (`timed = false`) takes `action.durationMs` = 2000 ms and happens when its bar runs out (`resolveAt: "end"`; `"start"` makes it happen at once, with the bar as a cooldown). Players act through `queueAction` (via `applyInput`): idle, the action starts; busy, it waits (at most `action.queueCap` = 3, else `queue_full`). The server stamps each action input with `at` and sends a `tick` input at `nextDue`; `tick` resolves due bars earliest first, then in seat order, through `performAction` (checked and paid then; being ready doesn't stop it) and starts the next queued action that is still legal. A dropped action costs nothing and writes a private `actionDropped` line. Each queued entry records `Action.adjustment` (how far modifiers moved its price) when queued; if the adjustment differs when it starts or resolves, it is cancelled with a private `actionCostChanged` line giving the new price, and nothing is paid (owner, 2026-10-18). Base-price changes the queue itself causes (a move's AP-to-MP conversion, a care point used up) don't cancel. The view sends `you.queue` as plain actions and `you.current` without the adjustment. `clearQueue` cancels the queue and, with "end", the action under way. Death clears both. `OtherPlayerView.busy` (times only) goes to people in the actor's room when `activitySeen` (log.ts): public and secret always, covert on camera, private never.
- **Cycles** (#24; `newCycle` in rules.ts, `server/src/cycleClock.ts`). Cycles change on the UTC clock, every 3 hours from midnight GMT, so a day starts at 00:00 GMT. The server sends a `cycle` input at each boundary (one storage alarm for the earliest bar or boundary; after downtime it applies every missed one in time order), and `newCycle` runs `advanceCycle` for everyone, ready or not. A ship launches on the clock's cycle of day 1 (`GameSetup.startCycle`, so 14:10 GMT is Day 1 · Cycle 5). End cycle (`actions/ready.ts`) is offered only with `config.manualCycles` (false by default; the server sets it from `ALLOW_CHEATS`, and single player turns it on): `ready` marks you done, and once every living player is, `performAction` calls `advanceCycle` early, so on the dev server the cycle number can run ahead of the clock. `CYCLE_SECONDS` in `server/.dev.vars` shortens cycles for testing. The view message carries `nextCycleAt`; the top bar (phone: under the name) counts down to it.
- **Cold disease** (`modifiers/cold_disease.ts`; `modifiers.ts`). Each cycle, a player with `cold_disease` has a 1-in-3 chance to lose 1 MP, floored at 0; the player gets a private log line when it happens.
- **Self Disease** (`actions/self_disease.ts`; development only, gated by `ALLOW_CHEATS`). A free, instant, private action on yourself that randomly applies an eligible disease from `config.diseases.allDiseases`, using seeded RNG and `addDisease`. Diseases already held are excluded; it is unavailable to Mush, bots, and players who have every configured disease.
- **Self Injury** (`actions/self_injury.ts`; development only, gated by `ALLOW_CHEATS`). A free, instant, private action on yourself that randomly applies an injury from `config.diseases.allInjuries` not already held, using seeded RNG. Unavailable when no eligible injury remains; not offered to bots.
- **Single player** (#59; `singlePlayer.ts`, `GameRoom.setupSinglePlayer`; owner, rules-design.md). The lobby's Single player button sends `singlePlayer` to the matchmaker, which launches a new room. `singlePlayerGame` seats the human as `p0`, forced Mush (`mushCount` 1), and 8 `model` bots on characters drawn with the seed from those left, never Eleesha, Chun or Chao (`NEVER_BOTS`). No pre-selection, `manualCycles` on, and no cycle clock: `nextCycleAt` is null and the alarm only settles action bars, so a cycle ends once everyone, bots included, has ended theirs. **Pause (#114):** a model bot with a key but no reply returns null instead of playing scripted; `ModelGate.pause` (`unavailable`, `key`, `budget`) goes out as `botsPaused` in the view message and shows as a top-bar tag (`BotsPausedTag`). `unavailable` retries after `MODEL_RETRY_MS`, doubling to `MODEL_RETRY_MAX_MS`; `key` and `budget` wait. Without a key the bots play scripted (`WanderBot`). No save slots (#243).
- **Movement, AP, HP, morale** (`actions/move.ts`, `moveCost` in `modifiers.ts`). 1 MP per move; with no MP, 1 AP converts to 3 MP; MP starts at 12 (`startMp`, owner 2026-10-24; was 0), cap 12, kept across cycles. AP: start 8, +1 per cycle, cap 12, unspent AP carries over; +2 while lying in a bed once that exists. HP and morale: max 14 each, start at 14 HP and 7 morale, visible only to their owner; each living player loses morale when a day ends (`dailyMoraleLoss` in `modifiers.ts`: `config.moralePerDay` = 2, cut by 1 while Chun lives, see Mankind's Only Hope below; floor 0). Days: `config.cyclesPerDay` = 8; `state.cycle` stays a global counter and `dayOf` derives day and cycle-of-day, both sent in `PlayerView`; the day boundary is handled in `advanceCycle`.
- **Room log** (`log.ts`). Public entries are the room's history, shown to anyone in that room; private entries only ever reach the actor; secret entries become room history if another player witnessed them or a camera is in the room; covert entries become room history only if a camera is in the room (bystanders never see them). A camera is, for now, a `camera` item in the room's inventory (`hasCamera`; one carried by a player doesn't count); a camera reveals the entry to everyone, overriding `hideFrom`.
- **Identity** (owner, 2026-10-17). Players know each other only by character (`Seat.character`; `characterName` in `characters.ts`). Account names (`Seat.name`) stay in server state but are in no view, your own included: `viewFor` strips `name` from `you` (`YouView`) and `OtherPlayerView`, rebuilds chat messages field by field (`ChatMessage` has no name), and log and system-message params carry character ids (`name`, `target`, `body`), which the client's `names.logLine` turns into names. Bots are still tagged AI (`isBot`). Revealing names when the game ends waits on game completion (#191, blocked by #27).
- **Examine** (`actions/examine.ts`, free). On anyone in your room including yourself, the room's equipment, your items, and the room's items; writes a private log line.
- **Inventory.** 3 private slots per player (`config.inventorySlots`, `inventorySlots` modifier hook); rooms hold unlimited items, visible to whoever is there. `take`/`drop` (`actions/transfer.ts`) cost nothing and are logged publicly. Items are effect-less placeholders except coffee, food, and the items below. Actions make items in two ways: `produceItem` in `items.ts` hands one to the player (into your inventory, or into the room if it's full, "knocked over"; dispense uses it), and dismantle puts its scraps straight into the room.
- **Dispense** (`actions/dispense.ts`). Equipment can dispense an item (`EquipmentType.dispenses`): free, once per cycle per machine (`GameState.dispensedOn`), offered on the refectory's coffee machine; 5% chance to become dirty.
- **Consume** (`actions/consume.ts`, free). An item you carry or one in your room (`ItemType.consume`) is removed and gives AP up to `maxAp`; coffee gives 2 AP and 1 satiety, the placeholder `cooked_ration` 4 satiety, and an `uncooked_ration` 4 satiety for 1 morale (`ItemType.consume.morale`, kept within 0 and `maxMorale`). 15% chance to become dirty.
- **Build** (`actions/build.ts`, `blueprints.ts`). A `blueprint` item carries a recipe key in `ItemState.builds` (also in `ItemView`). Anyone can build, anywhere, for `build.cost.ap` = 3, no failure chance. Ingredients are items in your inventory or on the room floor (floor first); the blueprint and ingredients are always consumed and the equipment is added to the room (`state.equipment[room]`, id `ROOM:TYPE:n`); public room log (`built`). 25% chance to become dirty. Recipes: SOFA (metal scraps + thick tube; makes equipment) and MISSILE_LAUNCHER (thick tube + metal + plastic scraps; makes an effect-less `missile_launcher` item via `produceItem`: inventory if there is room, else the floor; log `builtItem`). One blueprint of each spawns in CORRIDOR_A, with two thick tubes and two metal scraps (stand-ins so both can be built). A room can have any number of sofas. The iso view draws the room's first sofa at the spot of the room's `SOFA`-bound sofa tile in `ship-map.json` (editable in the ship editor; none in the Nexus or hydroponics); further sofas work but aren't drawn (the original lists them on the shelf, not built).
- **Cook** (`actions/cook.ts`). In a `cook.rooms` room (REFECTORY), `cook.cost.ap` = 1, on an item whose type has `ItemType.cook` that you can reach (carried or on the floor); it changes type in place (`uncooked_ration` becomes `cooked_ration`, same container); public room log (`cooked`); 25% chance to become dirty. Three `uncooked_ration` spawn in the refectory; they can also be eaten raw (see Consume).
- **Express cook** (`actions/express_cook.ts`). `expressCook.cost.ap` = 0, in any room, on a reachable item with `ItemType.cook`, while you can reach (carried or on the floor) a `microwave` with charges left. Spends one of its `ItemState.charges` and cooks the item in place like Cook; public room log (`expressCooked`); 5% chance to become dirty. The microwave (heavy) spawns in the refectory with `expressCook.charges.start` = 4, regains `perDay` = 1 at each day start up to `max` = 4 (`rechargeMicrowaves` in `items.ts`); charges show on the Inspect panel. Consequences of using it are not built.
- **Dismantle** (`actions/dismantle.ts`). On a reachable item whose type has `ItemType.dismantle`; `dismantle.cost.ap` = 3, `dismantle.successChance` = 0.12. Success removes the item and puts its metal and plastic scraps in your room (public log `dismantled`); failure writes a private `dismantleFailed` line.
- **Chat** (`chat.ts`). Everyone starts with an iTrackie (`config.startInventory`; item type `ITRACKIE_ITEM` = `super_talky`, after its icon), a normal item that uses a slot and can be dropped or taken. Carrying one opens global chat and the eight crew-wide feature threads (`FEATURE_CHANNELS` in `types/chat.ts`: botany, research, inventory, space battle, comms, pilgred, neron, astrophysics), for reading and posting, including the full history. History is capped per channel (`CHAT_HISTORY`).
- **Mush channel** (`MUSH_CHANNEL` = `mush`, in `types/chat.ts`). In `chatChannels` for living Mush only, no iTrackie needed; `contaminate` posts system messages into it (`mushContaminated` with name, level, capacity; `mushConverted` with name; `ChatMessage.from` is null and `system` holds the key and params; `pushChat` in `chat.ts`); no client tab yet.
- **Private channels.** `createChannel`, `inviteToChannel`, `leaveChannel` sit outside the action registry like `sendChat`; ids `pc-N`, limit via the `channelLimit` modifier; errors are codes. `viewFor` filters them to their members.
- **Threads** (`createThread` in `chat.ts`). Discord-style threads under global chat, ids `th-N` (`ThreadId`, part of `ChannelId`), stored in `GameState.threads`. `chatChannels` and `readChannels` add every thread id wherever they add global chat, so posting, reading, checkboxes and `viewFor`'s chat filter need nothing extra; `PlayerView.threads` lists them to anyone who can read global chat. Optional `from` = the global message it started from (one thread per message). No count cap. Errors: `thread_forbidden`, `thread_name_invalid`, `thread_exists`, `message_not_found`.
- **Markdown chat.** Moderation keeps line breaks (up to `MAX_CHAT_LINES` = 12, still `MAX_CHAT_LENGTH` characters); the client draws messages with `web/src/hud/Markdown.tsx` (react-markdown + remark-gfm; bold, italic, strikethrough, headers, lists, quotes, code, and task lists, but no links, images, tables, or raw HTML). `toggleCheckbox` (`chat.ts`, outside the action registry, wire message `toggleCheckbox` with `message` id and 0-based source `line`) ticks or unticks a `- [ ]` item in the message text; only the author may, and only while they can still read the channel. Errors are codes (`message_not_found`, `message_not_yours`, `checkbox_not_found`).
- **ACTOPI** (`GameState.bios.actopi`, starts on; the NERON Admin switches it at the BIOS terminal; the `setActopiCheat` dev cheat overrides how it looks to one player via `PlayerState.actopiCheat`). While on, `viewFor` sends every player's room; while off, players outside your room lose their `room` and appear only as bare room entries in `PlayerView.unidentified` (sorted by room, so order leaks nothing). `Minimap` draws mini portraits for people it can identify and `mush.png` for the rest (the minimap is not rendered right now; see `TODO(minimap)` in `GameScreen.tsx`).
- **Alpha flag.** Each player has an `alpha` flag (set for the Mush chosen at the start; player terminology only, nothing uses it, and it only appears in your own `you`). The player summary shows a faction icon (human, alpha or beta Mush) with a goal popover.
- **Bonding** (`actions/bond.ts`, `actions/share.ts` for `dtt` and `stt`; `GameState.bonds`, `sharedOnDay`, `contamination`). `bond.cost.ap`, `share.cost.ap` = 1; `share.effect.morale` = 2 each. `PlayerView.bonds` carries only your own bonds, and contamination is in no view; capacity via the `contaminationCapacity` modifier.
- **Spore extraction** (`actions/extract_spore.ts`). Mush only; `spores.cost.ap` = 1, `spores.effect.spores` = 1 into `PlayerState.spores`; per-Mush cooldown `spores.cooldownCycles` = 4 via `GameState.sporeExtractedOn`; faction daily cap `spores.perDay` = 4 (`sporesPerDay` modifier-folded), counted in `GameState.sporesToday` and reset in `advanceCycle`; secret log (2026-10-17); always applies `dirty`; spores appear only in your own `you`.
- **Spiking** (`actions/spike.ts`). Mush only, `spike.cost.ap` = 1 AP and 1 spore, target a living human in your room, contamination +1; covert (`logCovert`): only a camera in the room reveals it, and then to everyone, the victim included.
- **Infection** (`infection.ts`). `contaminate` is the one way contamination rises (spike and DTT call it); reaching `infection.capacity` = 3 (`contaminationCapacity` modifier) converts the human at once (`role` = mush, `alpha` = false, contamination entry removed, satiety cleared; skills, HP, and morale stay; spore extraction is ready immediately), with a private `converted` log line that names nobody. No cure. A convert does not yet learn who the other Mush are (#39). Mush see a contaminated human's level as a status (`OtherPlayerView.contamination`, via `contaminationSeenBy`; only for living humans in their room with level > 0; never in a human's view, their own included); `StatusIcons` draws it as the spore icon with the number.
- **Statuses and satiety** (`statuses.ts`). `PlayerState.statuses` stores `dirty`; `full_belly` and `hungry` are derived by `statusesOf`/`isFullBelly`/`isHungry`, and `STATUS_PUBLIC` says which are public. Disease IDs in `config.diseases.allDiseases` are automatically included in the client's status list and are private by default. Humans have `satiety` (start 0, loses `hunger.satietyPerCycle` = 1 per cycle via the `satietyPerCycle` modifier hook, floor 0) and `satietyZeroSince`, the cycle it reached 0 (starts at cycle 1); `hunger.fullBellyAt` = 3 satiety is full belly, and `consume` is refused (`full_belly`); `hunger.hungryAfterCycles` = 24 after that cycle, hungry costs `hunger.hpPerCycle` HP per cycle in `advanceCycle` (through `damage`, so it can kill); any consumable resets the count. Mush have no satiety or hunger and eat freely. `PlayerView.statuses` is all your own statuses; `OtherPlayerView.statuses` only public ones, only for people in your room. The client shows them with `StatusIcons` (Inspect panel; select yourself to see your private ones) and public ones with `StatusBadges` over heads in the room.
- **Accessing a terminal** (`actions/access.ts`; equipment with `EquipmentType.terminal`: Astro, Command, Com center, NERON core, BIOS, Research lab, Pilgred, Calculator). Free, no restrictions, no state change; the client opens a blank window titled with the terminal's name (`TerminalDialog`). The terminals' own actions are not built, except research at the Research lab, NERON projects at the NERON core, planet scanning at the Astro terminal, repair at PILGRED, the Com center, and the BIOS.
- **Research** (`actions/research.ts`, `research.ts`; `GameState.research`, percent per research id, public in `PlayerView.research`). At the lab's research terminal (`RESEARCH_LAB`), a living, not-dirty player spends 2 AP to advance one research 25% (`config.research`). Each research action has a 25% chance to make the researcher dirty, including Computer-point-free actions; NERON projects do not have this chance (owner, 2026-10-20). No repeat penalty. The 24 researches that have card art are listed; difficulty and prerequisites are not used yet. **Requirements** (`RESEARCH_REQUIRES` in `research.ts`, checked by `researchAllowed` in `actions/research.ts`; owner, 2026-10-25, from the original's `research.json`): a research is not offered, and is refused, unless the lab meets its needs at that moment. `items` (the original's `samples`): each item type must be in the lab, on the floor or carried by a living player there; `consumable` matches any item with `consume` (food, drink or drug). `consumes` (`kill_sample`: the blaster for NATAMY_GUN, the soap for MUSHICIDE_SOAP): one is removed from the lab when the research completes, the floor's first; other items are never used up. `chun` (`need_chun`): Chun alive in the lab, until Xyloph's ZONG_CHUN_SAMPLE entry is drawn, which lifts it for good. `postSelection` (`need_cryo`): not during pre-selection. The terminal shows each unfinished research's needs as static text ("Needs: …"). A Mush sample, a Mush genome disk, Schrödinger (`body_cat`), a water stick and a starmap fragment (`super_map`) spawn in front storage (no effects of their own); coffee comes from the dispenser. The client lists them, with a work button each, in the terminal window. Public room log lines `researched` / `researchCompleted`. Each research shows an implementation status badge (`RESEARCH_STATUS` in `research.ts`, like `SKILL_STATUS`); only researches with completion effects read "Implemented" (`RESEARCH_STATUS`). **Mush-eating bacteria** (`MUSHOPHAGE_BACTERIA`, full; owner, 2026-10-17): once complete, every human's contamination capacity is 4 instead of 3 (`config.infection.mushophageBonus`, added in `contaminationCapacity`). Humans already at 3 stay human until they reach 4. **Myco alarms** (`MYCO_ALARM`, partial; owner, 2026-10-17, `mycoalarm.ts`): completing it drops three `myco_alarm` items on the lab floor (public log `mycoAlarmsBuilt`). An alarm on a room floor (not carried) rings once per trigger however many are there, with a public room-log line `mycoAlarmRang` that names no one, readable by anyone who is later in the room. It is not used up, and anyone can dismantle it for one metal scrap through the normal dismantle action. Any action tagged `spore` rings it when it resolves, success or failure (`performAction`; owner, 2026-10-18). Only spiking has the tag so far (the comment in `mycoalarm.ts` lists the nine Mush abilities that get it when built); extracting never does. No `danger` log level yet (#20).
- **Hide and search** (`actions/hide.ts`, `actions/search.ts`; `ItemState.hiddenBy`, owner 2026-10-25). `hide` (1 AP, secret) moves a carried, droppable item into the room with `hiddenBy` set; `viewFor` sends it only to the hider (`ItemView.hidden`), and `canReachItem` / `visibleItemsIn` in `items.ts` keep everyone else from taking, consuming, dismantling, building with or examining it. It still counts for `itemsIn`-based rules (research needs, alarms, botany). Taking it clears `hiddenBy`. `search` (1 AP, secret, always offered) clears `hiddenBy` on every hidden item in the room and moves each into the searcher's inventory while there is space. Both refuse in pre-selection. Log keys `hid`, `foundHidden`, `searchedNothing`.
- **Anti-Mush serum** (`ANTI_MUSH_SERUM`, full; owner, 2026-10-25, the wiki's retro-fungal serum; `actions/vaccinate.ts`, `cure` in `infection.ts`): completing the research leaves one `anti_mush_serum` item on the lab floor (public log `serumBuilt`). Carrying it, `vaccinate` costs 1 AP (`config.vaccine`) on a living other in your room. A Mush becomes human (spores, Mush skills and extraction cooldown cleared, satiety restarts at 0 from now: not decided, a placeholder); a human with contamination loses it; on a healthy human nothing happens. The serum is always used up. Public log `vaccinated` shows no result; the user gets a private `vaccineWorked`/`vaccineNothing`, the cured person a private `cured`. Choosing human skills again is not built.
- **NERON projects** (`actions/project.ts`, `projects.ts`; `GameState.projects`, percent per project id, public in `PlayerView.projects`). Built exactly like research (owner, 2026-10-18): at NERON's core in the Nexus (`NERON_CORE`, not the BIOS terminal), a living, not-dirty player spends 2 AP to advance one project 25% (`config.project`), free with a Computer point (spent). No repeat penalty; every project is open at once (not the original's 3 proposals). All 41 projects in the original's live list (`projets.json` above `$EOF`, the 10 'plus' ones included, not PRICE_HACKER) can be completed; no completion effects yet (`PROJECT_STATUS` is empty). The NERON core's terminal window reuses the research list. Public room log lines `projectWorked` / `projectCompleted`.
- **PILGRED repair** (`pilgred.ts`, `actions/repair_pilgred.ts`, `modifiers/physicist.ts`; `GameState.pilgred`; owner, 2026-10-21, plan in `docs/scratchpad/pilgred-plan.md`). At the PILGRED terminal (`MOTOR_ROOM`), any living player, Mush and the dirty included, spends `pilgred.cost.ap` = 2 AP (free with a PILGRED point, which is spent) to advance the repair by the original's slow formula (`pilgredGainRange`): `floor(rate 6 × mod 2 / 10)` = 1, +`skillBoost` 4 for each of Engineer and Physicist, −`relayPenalty` 2 for each repair in a row by the same player (relaying: `lastBy`/`streak`, reset when someone else repairs), never below 0; the gain is rolled in [min, min + min/2] (1, 5–7, or 9–13 before the penalty). 25% dirty chance (`pilgred.dirtyChance`). Repairs are private (owner, 2026-10-21, correcting the plan's public line): the repairer alone gets `pilgredRepaired` (no percent), and roommates see no busy bar; reaching 100% logs `pilgredDone` instead and posts a crew-wide system message `pilgredDoneCrew` in global chat, after which it is no longer offered. `PlayerView.pilgred` is the percent only for the living in a room with the terminal, else null; `lastBy` and `streak` are never sent. Physicist: +`pilgred.pointsPerDay` = 1 PILGRED point at each day start (`pilgredPointsPerDay` fold), up to `capPoints` = 2, none when picked. The terminal window shows the card, description, progress and the repair button. Not built: Eden, breaking again, the reactor art swap, Raluca's triumph, the alien merchant repair.
- **Communication center** (`comms.ts`, `actions/contact_sol.ts`, `decode_rebel.ts`, `contact_xyloph.ts`, `update_neron.ts`; `GameState.comms`; owner, 2026-10-19 and 2026-10-21, `docs/comms-plan.md`). At the Com center terminal (`COM_CENTER`, bridge), every action costs 2 AP (`config.comms`) and needs the actor alive and not dirty (Mush included). All four are private: only the actor gets a log line. **Link with Sol** (`contact_sol`, anyone, while the link is down): one ship-wide chance, 4% at the start, +4% per failed attempt; a Radio Expert's own attempts get x2, anyone else's in a room with a Radio Expert x1.5. The link can be lost (Xyloph below), and the chance never drops below 4%. The other three need the link and the **Comms Officer** title (`hasTitleAccess`). **Rebel bases**: one calls at Mush selection and the next one a day later in the same cycle, in the original's order (Wolf, Sirius, Centauri, Kaladaan, Luyten-Ceti, Cygni). Each call stays open for 8 to 16 cycles, rolled per base; NERON announces it in global chat (`rebelCalling`) only if the link is up then, and a call missed that way can still be decoded until it expires. Travel would also end it, once travel exists. A decode (`decode_rebel`, free with a Computer point) adds the average of two 1..40 draws, rounded down, with +100% each for the Rebel skill and for Kivanç (additive, so x3 with both). At 100% the base is reached: Sirius gives rations +1 AP, Kaladaan +6 morale and Cygni +3 morale to every living player, and Luyten-Ceti opens global chat without an iTrackie. Wolf, Centauri and Cygni's patrol ship damage have no effect yet. **Xyloph** (`contact_xyloph`): always works and draws one of the 12 live entries by weight, never twice; once all are drawn it is no longer offered. Snow crash drops the link; Wireless infidelity drops it and takes 20 points off the chance. The genome disk (`mush_floppy_disk`), Nils (`mush_sample`, the Mush test strain), the cookbook (a cook skill book), the school manuals (2 skill books for random skills) and the workshop manuals (3 random blueprints) appear on the bridge floor; the items have no effect yet. NERON's lost database adds 25% to the NERON update, and Kivanç's bonus is the rebel decoding one. Lost analysis and Zong Chun's ghost are only recorded (`comms.xyloph`). **NERON update** (`update_neron`): +25% per action, and it repeats; at 100% NERON's version goes up by one and a random unfinished NERON project completes at once. **Views**: `PlayerView.comms.linked` goes to everyone; `comms.terminal` (Sol chance, every rebel call with progress, status and expiry, how many Xyloph entries are left, NERON version and progress) goes only to the living in a room with the terminal, read-only, whatever their title. Which Xyloph entries were drawn is never sent; the drawer has it in their log. The terminal window is `CommsCenter.tsx`. Not built: the general announcement, merchant trades (#143), Lost analysis's printout, Kivanç's triumph for Paola.
