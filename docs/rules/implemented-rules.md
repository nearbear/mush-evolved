# Implemented rules

What the rules code does today, one bullet per rule, naming where it lives. Moved out of `docs/code-map/README.md` so the map stays a list of files. Numbers come from `state.config` (`shared/src/config.ts`); when each value was confirmed is recorded there and in `docs/rules/rules-design.md`, not here. Open work is in GitHub issues ([project](https://github.com/users/nearbear/projects/1)).

- **Action costs.** Each entry of `PlayerView.actions` carries its `cost`, read through `Action.cost` (the one place costs are read: legality, paying, and the view all go through it; subclasses set the base price in `getCost`). The client displays them and never computes them. Entries you can do now come first with empty `lacks`; then the ones you lack AP or MP for, with `lacks` naming which (`affordable`, `legalIn` in rules.ts).
- **Success chances.** Each `PlayerView.actions` entry's `chance` comes from the action's `chance`; action buttons show the odds in parentheses, e.g. "Punch (60%)", only when below 100%.
- **Action tags** (issue 30, owner 2026-10-18). Each action type declares `tags` (`ActionTag` in `actions/action.ts`), fixed per type like visibility, and each `PlayerView.actions` entry carries them so the UI can mark them (no UI yet). `aggressive`: punch and spike. `spore`: spike (not spore extraction, for balance).
- **Timed actions** (`queue.ts`; `PlayerState.current`, `PlayerState.queue`; `config.action`). Every action but `ready` and `access` (`timed = false`) takes `action.durationMs` = 2000 ms and happens when its bar runs out (`resolveAt: "end"`; `"start"` makes it happen at once, with the bar as a cooldown). Players act through `queueAction` (via `applyInput`): idle, the action starts; busy, it waits (at most `action.queueCap` = 3, else `queue_full`). The server stamps each action input with `at` and sends a `tick` input at `nextDue`; `tick` resolves due bars earliest first, then in seat order, through `performAction` (checked and paid then; being ready doesn't stop it) and starts the next queued action that is still legal. A dropped action costs nothing and writes a private `actionDropped` line. Each queued entry records `Action.adjustment` (how far modifiers moved its price) when queued; if the adjustment differs when it starts or resolves, it is cancelled with a private `actionCostChanged` line giving the new price, and nothing is paid (owner, 2026-10-18). Base-price changes the queue itself causes (a move's AP-to-MP conversion, a care point used up) don't cancel. The view sends `you.queue` as plain actions and `you.current` without the adjustment. `clearQueue` cancels the queue and, with "end", the action under way. Death clears both. `OtherPlayerView.busy` (times only) goes to people in the actor's room when `activitySeen` (log.ts): public and secret always, covert on camera, private never.
- **Cycles** (#24; `newCycle` in rules.ts, `server/src/cycleClock.ts`). Cycles change on the UTC clock, every `config.cycleHours` (3 by default; a setup may pick 1, 2, 3, 4 or 6, #230) from midnight GMT, so a day starts at 00:00 GMT and has `cyclesPerDay` = 24 / `cycleHours` cycles (`resolveConfig` derives it). Daily effects stay once per 24-hour day; anything counted in cycles stays in cycles. The server sends a `cycle` input at each boundary (one storage alarm for the earliest bar or boundary; after downtime it applies every missed one in time order), and `newCycle` runs `advanceCycle` for everyone, ready or not. A ship launches on the clock's cycle of day 1 (`GameSetup.startCycle`, so 14:10 GMT is Day 1 · Cycle 5 with 3-hour cycles). End cycle (`actions/ready.ts`) is offered only with `config.manualCycles` (false by default; the server sets it from `ALLOW_CHEATS`, and single player turns it on): `ready` marks you done, and once every living player is, `performAction` calls `advanceCycle` early, so on the dev server the cycle number can run ahead of the clock. `CYCLE_SECONDS` in `server/.dev.vars` shortens cycles for testing, overriding `cycleHours`. The view message carries `nextCycleAt`; the top bar (phone: under the name) counts down to it.
- **Cold disease** (`modifiers/cold_disease.ts`; `modifiers.ts`). Each cycle, a player with `cold_disease` has a 1-in-3 chance to lose 1 MP, floored at 0; the player gets a private log line when it happens.
- **Self Disease** (`actions/self_disease.ts`; development only, gated by `ALLOW_CHEATS`). A free, instant, private action on yourself that randomly applies an eligible disease from `config.diseases.allDiseases`, using seeded RNG and `addDisease`. Diseases already held are excluded; it is unavailable to Mush, bots, and players who have every configured disease.
- **Self Injury** (`actions/self_injury.ts`; development only, gated by `ALLOW_CHEATS`). A free, instant, private action on yourself that randomly applies an injury from `config.diseases.allInjuries` not already held, using seeded RNG. Unavailable when no eligible injury remains; not offered to bots.
- **Single player** (#59; `singlePlayer.ts`, `GameRoom.setupSinglePlayer`; owner, rules-design.md). The lobby's Single player button sends `singlePlayer` to the matchmaker, which launches a new room. `singlePlayerGame` seats the human as `p0`, forced Mush (`mushCount` 1), and 8 `model` bots on characters drawn with the seed from those left, never Eleesha, Chun or Chao (`NEVER_BOTS`). No pre-selection, `manualCycles` on, and no cycle clock: `nextCycleAt` is null and the alarm only settles action bars, so a cycle ends once everyone, bots included, has ended theirs. **Pause (#114):** a model bot with a key but no reply returns null instead of playing scripted; `ModelGate.pause` (`unavailable`, `key`, `budget`) goes out as `botsPaused` in the view message and shows as a top-bar tag (`BotsPausedTag`). `unavailable` retries after `MODEL_RETRY_MS`, doubling to `MODEL_RETRY_MAX_MS`; `key` and `budget` wait. Without a key the bots play scripted (`WanderBot`). No save slots (#243).
- **Movement, AP, HP, morale** (`actions/move.ts`, `moveCost` in `modifiers.ts`). 1 MP per move; with no MP, 1 AP converts to 3 MP; MP starts at 12 (`startMp`, owner 2026-10-24; was 0), cap 12, kept across cycles. AP: start 8, +1 per cycle, cap 12, unspent AP carries over; +2 while lying in a bed once that exists. HP and morale: max 14 each, start at 14 HP and 7 morale, visible only to their owner; each living player heals `config.dailyHeal` = 1 HP (up to max, `healDaily` in `death.ts`; owner, 2026-10-28) and loses morale when a day ends (`dailyMoraleLoss` in `modifiers.ts`: `config.moralePerDay` = 2, cut by 1 while Chun lives, see Mankind's Only Hope below; floor 0). Days: `config.cyclesPerDay` = 8; `state.cycle` stays a global counter and `dayOf` derives day and cycle-of-day, both sent in `PlayerView`; the day boundary is handled in `advanceCycle`.
- **Room log** (`log.ts`). Public entries are the room's history, shown to anyone in that room; private entries only ever reach the actor; secret entries become room history if another player witnessed them or a camera is in the room; covert entries become room history only if a camera is in the room (bystanders never see them). A camera is, for now, a `camera` item in the room's inventory (`hasCamera`; one carried by a player doesn't count); a camera reveals the entry to everyone, overriding `hideFrom`. **Window** (owner, 2026-11-05, #365): a seat sees room lines, its private ones included, from the current cycle and the 7 before it (`config.logWindow.cycles` = 8; `seesLine`, `inLogWindow`), 16 with the Tracker skill (`hunt`, picked or from a book; `logWindow.tracker`). Ship-wide lines and chat have no window. As each cycle begins, `pruneLog` drops room lines older than the longer window, so the state stops growing; the record keeps every line for replays. `PlayerState.logSeen` counts the lines each body could see as they are written (aged-out ones included; a Transfer starts it over for both bodies at what their views show) and goes out as `PlayerView.logSeen`, which the announcer uses to find new lines.
- **Identity** (owner, 2026-10-17). Players know each other only by character (`Seat.character`; `characterName` in `characters.ts`). Account names (`Seat.name`) stay in server state but are in no view, your own included: `viewFor` strips `name` from `you` (`YouView`) and `OtherPlayerView`, rebuilds chat messages field by field (`ChatMessage` has no name), and log and system-message params carry character ids (`name`, `target`, `body`), which the client's `names.logLine` turns into names. Bots are still tagged AI (`isBot`). Revealing names when the game ends waits on game completion (#191, blocked by #27).
- **Examine** (`actions/examine.ts`, free). On anyone in your room including yourself, the room's equipment, your items, and the room's items; writes a private log line.
- **Inventory.** 3 private slots per player (`config.inventorySlots`, `inventorySlots` modifier hook); rooms hold unlimited items, visible to whoever is there. `take`/`drop` (`actions/transfer.ts`) cost nothing and are logged publicly. Items are effect-less placeholders except coffee, food, and the items below. Actions make items in two ways: `produceItem` in `items.ts` hands one to the player (into your inventory, or into the room if it's full, "knocked over"; dispense uses it), and dismantle puts its scraps straight into the room.
- **Dispense** (`actions/dispense.ts`, `dispense.ts`). Equipment can dispense an item (`EquipmentType.dispenses`): free, offered on the refectory's coffee machine; 5% chance to become dirty. Coffee regenerates on a schedule (`GameState.dispensedOn`): base is cycle 1 (once/day); Fission Coffee Roaster adds cycle 5 (twice/day); PILGRED repair adds cycles 3 and 7 (4x/day); both Roaster and PILGRED regenerate every cycle (1..8). The machine holds up to 1 coffee across cycles until taken; taking it empties the machine until the next scheduled regen cycle.
- **Consume** (`actions/consume.ts`, free). An item you carry or one in your room (`ItemType.consume`) is removed and gives AP up to `maxAp`; coffee gives 2 AP and 1 satiety, a `cooked_ration` 4 AP and 4 satiety, and an `uncooked_ration` 4 AP and 4 satiety for 1 morale (owner, 2026-11-05; Sirius adds 1 AP to either; tests in `shared/tests/food.test.ts`). A Mush gains nothing from any consumable, AP included (rations, coffee, bananas; no exceptions) (`ItemType.consume.morale`, kept within 0 and `maxMorale`). 15% chance to become dirty.
- **Build** (`actions/build.ts`, `blueprints.ts`). A `blueprint` item carries a recipe key in `ItemState.builds` (also in `ItemView`). Anyone can build, anywhere, for `build.cost.ap` = 3, no failure chance. Ingredients are items in your inventory or on the room floor (floor first); the blueprint and ingredients are always consumed and the equipment is added to the room (`state.equipment[room]`, id `ROOM:TYPE:n`); public room log (`built`). 25% chance to become dirty. Recipes: SOFA (metal scraps + thick tube; makes equipment) and MISSILE_LAUNCHER (thick tube + metal + plastic scraps; makes an effect-less `missile_launcher` item via `produceItem`: inventory if there is room, else the floor; log `builtItem`). One blueprint of each spawns in CORRIDOR_A, with two thick tubes and two metal scraps (stand-ins so both can be built). A room can have any number of sofas. The iso view draws the room's first sofa at the spot of the room's `SOFA`-bound sofa tile in `ship-map.json` (editable in the ship editor; none in the Nexus or hydroponics); further sofas work but aren't drawn (the original lists them on the shelf, not built).
- **Cook** (`actions/cook.ts`). In a `cook.rooms` room (REFECTORY), `cook.cost.ap` = 1, on an item whose type has `ItemType.cook` that you can reach (carried or on the floor); it changes type in place (`uncooked_ration` becomes `cooked_ration`, same container); public room log (`cooked`); 25% chance to become dirty. 32 `uncooked_ration` spawn in the refectory (matching eMush); they can also be eaten raw (see Consume).
- **Express cook** (`actions/express_cook.ts`). `expressCook.cost.ap` = 0, in any room, on a reachable item with `ItemType.cook`, while you can reach (carried or on the floor) a `microwave` with charges left. Spends one of its `ItemState.charges` and cooks the item in place like Cook; public room log (`expressCooked`); 5% chance to become dirty. The microwave (heavy) spawns in the refectory with `expressCook.charges.start` = 4, regains `perDay` = 1 at each day start up to `max` = 4 (`rechargeMicrowaves` in `items.ts`); charges show on the Inspect panel. Consequences of using it are not built.
- **Dismantle** (`actions/dismantle.ts`). Needs the `engineer` skill (offered and allowed only to a Technician; owner, 2026-11-03). On a reachable item whose type has `ItemType.dismantle`; `dismantle.cost.ap` = 3, `dismantle.successChance` = 0.12. Success removes the item and puts its metal and plastic scraps in your room (public log `dismantled`); failure writes a private `dismantleFailed` line.
- **Chat** (`chat.ts`). Everyone starts with an iTrackie (`config.startInventory`; item type `ITRACKIE_ITEM` = `super_talky`, after its icon), a normal item that uses a slot and can be dropped or taken. Carrying one opens global chat and the eight crew-wide feature threads (`FEATURE_CHANNELS` in `types/chat.ts`: botany, research, inventory, space battle, comms, pilgred, neron, astrophysics), for reading and posting, including the full history. History is capped per channel (`CHAT_HISTORY`).
- **Mush channel** (`MUSH_CHANNEL` = `mush`, in `types/chat.ts`). In `chatChannels` for living Mush only, no iTrackie needed; `contaminate` posts system messages into it (`mushContaminated` with name, level, capacity; `mushConverted` with name; `ChatMessage.from` is null and `system` holds the key and params; `pushChat` in `chat.ts`); no client tab yet.
- **Private channels.** `createChannel`, `inviteToChannel`, `leaveChannel` sit outside the action registry like `sendChat`; ids `pc-N`, limit via the `channelLimit` modifier; errors are codes. `viewFor` filters them to their members.
- **Channel plans** (`plans.ts`, `types/plan.ts`, `actions/plan_slots.ts`, `actions/summon.ts`; docs/plans/on-call.md). A private channel's creator posts one open plan at a time (`postPlan`, not yet wired to a client message): a room with a door, a purpose label, up to `config.plans.slotsPerPlan` on-call and task slots, optionally reserved for living members (never in a way the claim rules would refuse to that member). Members claim (`claim_slot`; one on-call slot each, none for the author, no STT or Comfort aimed at yourself), withdraw, tick tasks Done (`mark_done`), and the author cancels (`cancel_plan`): free, untimed, unrecorded registry actions. `summon`, offered to the author in the plan's room on a plan with an on-call slot, walks each on-call holder in slot order with live `move`s along `shortestPath` (queue dropped with `actionDropped` lines, out of bed, stop without refund on a refused or unaffordable step; the reason only in that holder's private log) and marks the plan `called`. Leaving the channel or dying withdraws claims and drops reservations; the author leaving or dying cancels and sets `planningClosed`; a dead target or a task finished while the plan is open strikes its slot (`struck`), unless it was already ticked Done; a member without an iTrackie neither sees nor acts on their channel's plans, as with its messages; open plans expire at the end of the day after posting. `PlayerView.plans` holds the plans of your channels. `clearQueue` takes a `notify` flag (`queueCore.ts`).
- **Threads** (`createThread` in `chat.ts`). Discord-style threads under global chat, ids `th-N` (`ThreadId`, part of `ChannelId`), stored in `GameState.threads`. `chatChannels` and `readChannels` add every thread id wherever they add global chat, so posting, reading, checkboxes and `viewFor`'s chat filter need nothing extra; `PlayerView.threads` lists them to anyone who can read global chat. Optional `from` = the global message it started from (one thread per message). No count cap. Errors: `thread_forbidden`, `thread_name_invalid`, `thread_exists`, `message_not_found`.
- **Markdown chat.** Moderation keeps line breaks (up to `MAX_CHAT_LINES` = 12, still `MAX_CHAT_LENGTH` characters); the client draws messages with `web/src/hud/Markdown.tsx` (react-markdown + remark-gfm; bold, italic, strikethrough, headers, lists, quotes, code, and task lists, but no links, images, tables, or raw HTML). `toggleCheckbox` (`chat.ts`, outside the action registry, wire message `toggleCheckbox` with `message` id and 0-based source `line`) ticks or unticks a `- [ ]` item in the message text; only the author may, and only while they can still read the channel. Errors are codes (`message_not_found`, `message_not_yours`, `checkbox_not_found`).
- **ACTOPI** (`GameState.bios.actopi`, starts on; the NERON Admin switches it at the BIOS terminal). While on, `viewFor` sends every player's room; while off, players outside your room lose their `room` and appear only as bare room entries in `PlayerView.unidentified` (sorted by room, so order leaks nothing). `Minimap` draws mini portraits for people it can identify and `mush.png` for the rest.
- **Alpha flag.** Each player has an `alpha` flag (set for the Mush chosen at the start; player terminology only, nothing uses it, and it only appears in your own `you`). The player summary shows a faction icon (human, alpha or beta Mush) with a goal popover.
- **Bonding** (`actions/bond.ts`, `actions/share.ts` for `dtt` and `stt`; `GameState.bonds`, `sharedOnDay`, `contamination`). `bond.cost.ap`, `share.cost.ap` = 1; `share.effect.morale` = 2 each. `PlayerView.bonds` carries only your own bonds, and contamination is in no view; capacity via the `contaminationCapacity` modifier.
- **Fertile** (Mush skill `fertile`; owner, 2026-10-27, rules-design.md). The first `extract_spore` each day costs 0 AP (the same action, shown free); it ignores the per-Mush cooldown but starts it, and still counts toward and is blocked by the faction's daily cap. `PlayerState.fertileToday` (own-only, reset at day start) moves with the mind in a Transfer. Skill status full.
- **Spore extraction** (`actions/extract_spore.ts`). Mush only; `spores.cost.ap` = 1, `spores.effect.spores` = 1 into `PlayerState.spores`; no cooldown (removed on request, 2026-11-03); faction daily cap `spores.perDay` = 4 (`sporesPerDay` modifier-folded), counted in `GameState.sporesToday` and reset in `advanceCycle`; secret log (2026-10-17); always applies `dirty`; spores appear only in your own `you`.
- **Spiking** (`actions/spike.ts`). Mush only, `spike.cost.ap` = 1 AP and 1 spore, per-Mush cooldown `spike.cooldownCycles` = 4 via `GameState.spikedOn` (owner, 2026-11-03), target a living human in your room, contamination +1; covert (`logCovert`): only a camera in the room reveals it, and then to everyone, the victim included.
- **Infection** (`infection.ts`). `contaminate` is the one way contamination rises (spike and DTT call it); reaching `infection.capacity` = 3 (`contaminationCapacity` modifier) converts the human at once (`role` = mush, `alpha` = false, contamination entry removed, satiety cleared; skills, HP, and morale stay; spore extraction is ready immediately), with a private `converted` log line that names nobody. No cure. A convert does not yet learn who the other Mush are (#39). Mush see a contaminated human's level as a status (`OtherPlayerView.contamination`, via `contaminationSeenBy`; only for living humans in their room with level > 0; never in a human's view, their own included); `StatusIcons` draws it as the spore icon with the number.
- **Statuses and satiety** (`statuses.ts`). `PlayerState.statuses` stores `dirty`; `full_belly` and `hungry` are derived by `statusesOf`/`isFullBelly`/`isHungry`, and `STATUS_PUBLIC` says which are public. Disease IDs in `config.diseases.allDiseases` are automatically included in the client's status list and are private by default. Humans have `satiety` (start 0, loses `hunger.satietyPerCycle` = 1 per cycle via the `satietyPerCycle` modifier hook, floor 0) and `satietyZeroSince`, the cycle it reached 0 (starts at cycle 1); `hunger.fullBellyAt` = 3 satiety is full belly, and `consume` is refused (`full_belly`); `hunger.hungryAfterCycles` = 24 after that cycle, hungry costs `hunger.hpPerCycle` HP per cycle in `advanceCycle` (through `damage`, so it can kill); any consumable resets the count. Mush never get hungry; they eat freely for no food effects, but each meal still adds its satiety (owner, 2026-11-05), so they can reach full belly and be blocked from eating. Full belly is never floated over the head (`overheadStatuses`); it shows on Inspect only. `PlayerView.statuses` is all your own statuses; `OtherPlayerView.statuses` only public ones, only for people in your room. The client shows them with `StatusIcons` (Inspect panel; select yourself to see your private ones) and public ones with `StatusBadges` over heads in the room.
- **Accessing a terminal** (`actions/access.ts`; equipment with `EquipmentType.terminal`: Astro, Command, Com center, NERON core, BIOS, Research lab, Pilgred, Calculator). Free, no restrictions, no state change; the client opens a blank window titled with the terminal's name (`TerminalDialog`). The terminals' own actions are not built, except research at the Research lab, NERON projects at the NERON core, planet scanning at the Astro terminal, repair at PILGRED, the Com center, and the BIOS.
- **Relay tokens** (`relay.ts`, `relayView.ts`; `docs/plans/relay-tokens.md`; owner, 2026-10-30/31; part A of #311, built 2026-10-31). Research, NERON projects and PILGRED take contributions as tokens: each action adds `{ by, base, roll }` to the target's pool (`GameState.relay.research`, `relay.projects`, `pilgred.pool`), `base` = floor(rate × mod / 10) + skillBoost per matching skill at that moment, `roll` drawn then from the seeded RNG. Progress is the best total any ordering of the tokens could give under the relay penalty (−`relayPenalty` per token in a row by the same player, never below 0), found in O(n log n) by `arrangeTokens`: only a player holding more than everyone else combined plus one is penalized, their tokens split into even runs, highest bases on the lowest penalties. The pool's rolls, highest first, go to the arranged values, highest first, each value g rolled in [g, g + g/2] (owner, 2026-10-31: a token keeping its own roll could make progress fall). Pools last the target's lifetime. A token made under the noRelayPenalty cheat (`unpenalized`) counts as from a player of its own. **Views**: progress, `waiting` (what the pool would add with every penalty waived), the gain if you contribute now (`gain`, a min–max over your roll) and the token list (contributor and value) go only to the living in the target's room (`PlayerView.relay`); elsewhere `research` and `projects` hold only completed targets. Each viewer's own token counts go everywhere (`yourTokens`). Rolls are never sent. The terminals show the help sentence, the waiting line, the token faces and the gain on each work button (`RelayDetails.tsx`). Research adds a pending stage (see Research samples and assays). Not built: scripted bots preferring targets their token unlocks.
- **Research samples and assays** (`assay.ts`, `actions/research.ts`, `actions/spoil_research.ts`, `actions/contaminate.ts`; `docs/plans/research-sabotage.md`; owner, 2026-10-30/31; part B of #311, built 2026-10-31). A research's relay tokens are **samples** to players. A new sample is pending (`ResearchPool.pending`); `GameState.research` is the best arrangement of the verified samples only, and the view's `relay.research[id].pending` is the striped segment (all samples' best arrangement minus verified). When verified plus pending reaches the next mark of `config.research.assayMarks` (25, 50, 75, 100) above verified progress, an **assay** tests every pending sample: one noise roll each from the seeded RNG, in sample order; a contaminated sample always spoils, any other at `spoilChance` (5%). Spoiled samples are removed as if never made; the rest become verified and never spoil, so verified progress never falls. If spoils leave it short of the mark, the next contribution that reaches it assays again. The lab's public line `assayPassed` / `assaySpoiled` names everyone tested and whose samples spoiled, with counts (`tested`, `spoiledBy`: "chun:3,paola:1"), never why. The research completes, with its effects, only at the assay that leaves it at 100; `researchCompleted` names nobody. **Own spoil** (`spoil_research`, Mush only): Participate's price, needs and dirt chance, and a sample contaminated by its maker; others' views and the private line match an honest contribution; the action history records it as own spoil, so Interrogate and Chitchat can reveal it (owner, 2026-10-31). **Contaminate** (Saboteur, `sapper`; 1 AP, `config.research.contaminate`; private, so no camera): contaminates one pending sample made by someone else and not already contaminated, from the contributor with the fewest samples (verified and pending) in that research, a tie broken by the seeded RNG (`contaminationCandidates`); never by role, other Mush included. It is offered whenever someone else has a pending sample and does nothing when all of them are contaminated, so it can't reveal another player's own spoil (Claude, 2026-10-31). The terminal shows a striped bar segment, "N% (+M% pending)", pending samples underlined in the list, and the two buttons beside Participate. `contaminatedBy` and rolls are never sent. No bot uses either action.
- **Research** (`actions/research.ts`, `research.ts`; `GameState.research`, percent per research id, in `PlayerView.research` only in the lab until complete). At the lab's research terminal (`RESEARCH_LAB`), a living, not-dirty player spends 2 AP to add a relay token (see Relay tokens; `config.research.progress`; owner, 2026-10-26, the original's `getBaseProgress`): base = floor(6 × 10 / 10) = 6, +4 for each Biologist or Medic skill, −2 per token in a row in the best arrangement (6–9% for a lone first token with no skill). Each research action has a 25% chance to make the researcher dirty, including Computer-point-free actions; NERON projects do not have this chance (owner, 2026-10-20). The 24 researches that have card art are listed; difficulty and prerequisites are not used yet. **Requirements** (`RESEARCH_REQUIRES` in `research.ts`, checked by `researchAllowed` in `actions/research.ts`; owner, 2026-10-25, from the original's `research.json`): a research is not offered, and is refused, unless the lab meets its needs at that moment. `items` (the original's `samples`): each item type must be in the lab, on the floor or carried by a living player there; `consumable` matches any item with `consume` (food, drink or drug). `consumes` (`kill_sample`: the blaster for NATAMY_GUN, the soap for MUSHICIDE_SOAP): one is removed from the lab when the research completes, the floor's first; other items are never used up. `chun` (`need_chun`): Chun alive in the lab, until Xyloph's ZONG_CHUN_SAMPLE entry is drawn, which lifts it for good. `postSelection` (`need_cryo`): not during pre-selection. The terminal shows each unfinished research's needs as static text ("Needs: …"). A Mush sample, a Mush genome disk, Schrödinger (`body_cat`), a water stick and a starmap fragment (`super_map`) spawn in front storage (no effects of their own); coffee comes from the dispenser. The client lists them, with a work button each, in the terminal window. Research is private (owner, 2026-10-30): the worker alone gets `researched`; assay lines and `researchCompleted` are public room lines (see Research samples and assays). Each research shows an implementation status badge (`RESEARCH_STATUS` in `research.ts`, like `SKILL_STATUS`); only researches with completion effects read "Implemented" (`RESEARCH_STATUS`). **Mush-eating bacteria** (`MUSHOPHAGE_BACTERIA`, full; owner, 2026-10-17): once complete, every human's contamination capacity is 4 instead of 3 (`config.infection.mushophageBonus`, added in `contaminationCapacity`). - **Expert and Stickler** (documented 2026-10-24, built earlier). **Expert** (`modifiers/expert.ts`, full; owner, 2026-10-18): every action's success, dirty and injury chances are multiplied by 1.2. **Stickler** (`rules.ts`, full): a dirty roll that succeeds is blocked instead (private log `sticklerBlockedDirty`), like an apron.
- **Water Resistant** (Mush skill `water_resistant`; `actions/shower.ts`; eMushpedia `Résistance à l'eau`, my reading, 2026-10-27). Showering costs at most `shower.cost.waterResistantAp` = 1 AP (soap doesn't stack) and a Mush with it loses no HP (and gets the human log line). Skill status full.
- **Apprentice** (skill `apprentice`; `actions/apprenticeship.ts`; owner, 2026-11-05). Action `apprenticeship` `{ target, skill }`: `config.apprenticeship.cost.ap` = 1 AP, copies a human skill (picked or book slot) that a living roommate has and you don't. Once per game: the copied skill takes Apprentice's slot, so the action is gone afterwards; no free slot needed. Mush skills can't be copied. Apprentice can never be picked again afterwards (`PlayerState.apprenticeUsed`, own view only, stays with the body). Private, no log line. Aimed at the teacher, so it shows on their Inspect panel and the phone peek bar as "Learn <skill>" (`actions.apprenticeshipOf`).
- **Genius** (skill `genius`; `actions/become_genius.ts`; owner, 2026-11-05). Action `become_genius` (no target): free, once per game (`PlayerState.geniusUsed`, own view only, stays with the body), private, no log line. It gives the private `genius` status (`statuses.ts`, icon `genius_idea`), which lasts until used: the next `research` (requirements still apply) or `project` the holder works on completes at once, at its normal price; a research skips the assay. It also makes the next `repair` or `repair_hull` attempt certain (owner, 2026-11-05; PILGRED repairs excluded) and is used up by it. The Mush spoil is not covered.
