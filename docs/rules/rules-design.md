# Rules design: decisions and phased plan (written 2026-10-05, pruned 2026-10-13)

> **Bots (decided 2026-10-13):** multiplayer has no bots. They exist only in a single-player mode (stage not decided) and as test tooling. Wherever these docs describe bots filling seats in a live game, that no longer applies.

The record of answered rule decisions and the design for the rules that are not built yet. Open questions live in GitHub issues labeled `rule-decision`, not here. Scheduled plans have their own document, `docs/plans/archive/action-plans.md`, whose executor was dropped on 2026-10-30 for channel plans with on-call summons (`docs/plans/on-call.md`) and pooled relay tokens (`docs/plans/archive/relay-tokens.md`).

**Status (2026-10-13):** built are AP, MP, HP and morale values, the action registry, inventory, the iTrackie, global chat, and private channels. Not built: infection, spores, the attack, win conditions, the cycle timer, and the phases below.

## Decisions received

- **ACTOPI protocol (`WHOS_WHO`) as an early-game research** (2026-11-24, owner; built): `WHOS_WHO` is now a lab research (`RESEARCH_IDS`, marked `full`, no requirements so it is available from game start like `DRUG_DISPENSER`, using the uniform research progress formula). `GameState.bios.actopi` starts **off** (`false`) and its BIOS toggle is locked (`actopi_locked`) until `WHOS_WHO` completes; completing `WHOS_WHO` switches ACTOPI on (`true`), unlocks the BIOS switch so the NERON Admin can toggle it off/on afterwards, and writes only the standard `researchCompleted` lab log line.
- **Terrence's Wheelchair passive (matching eMush)** (2026-11-24, owner; built): adds eMush's **−2 MP** per solo AP-to-MP conversion (`config.wheelchair.conversionMpPenalty`, clamped at 0) and free exit (`mpPerMove = 0`, waiving heavy items and Broken Ribs too) when at least one **non-comatose, active (not inactive)** living roommate has been in the room for at least **30 seconds** (`config.wheelchair.helpDelayMs`, tracked via server-only `PlayerState.enteredRoomAt`; `nextDue`/`tick` wake at the 30s mark). Prevents Terrence from infinitely evading pursuers. Leaving for free writes a public room log line naming a qualifying roommate (`wheelchairHelped`). Applies to a Mush Terrence too (like all other character traits). **Accommodate** stays as-is for players who don't want to wait 30 seconds. (Updated 2026-11-24, owner: removed the awake/`lyingIn === undefined` requirement; only non-inactive and non-comatose are required.)
- **Global death morale loss** (2026-11-24, owner; built): every non-traded crewmate death (human or Mush, excluding `daedalus_destroyed`) costs every living crewmate (human or Mush) **−1 morale** (`config.death.moraleLoss`), or **−2 morale** (`config.death.chunMoraleLoss`) when Chun dies (human or Mush), with the standard private `loseMorale` line (so it doesn't leak deaths when announcements are off or a room is defaced). Replaces `hopeless.deathMorale` (Hopeless deaths no longer double-charge) and stacks with `share.pregnancy.deathMoraleLoss` (−3 total, or −4 for pregnant Chun).
- **Pyromaniac AP cost** (2026-11-24, owner; built, reverting 2026-11-23's 3 AP): `ignite` (`actions/ignite.ts`, `config.ignite.cost.ap`) costs **4 AP** again.
- **Hostile NPCs** (2026-11-22, owner; built in `shared`): stored in their own list (`GameState.hostiles`), not as players; a `HostileNpc` base class with one subclass per kind. They run their own action set (not the player `Action`s), taking a turn at each cycle change with AP/MP regained like a player's. Move, and Punch (2026-11-23: the same as a player's Punch). The intruder takes one action per cycle change: it punches a random player in its room, or moves when nobody is there; other kinds may take more (`actionsPerTurn`). Pacifist, Bodyguard, Elusive, Guarding and anything similar affect hostile actions as they do players' (2026-11-23): everything another player in the room or the target brings to an action (room cost hooks, targeted success hooks, Ceasefire, a guardian's hold on leaving). Attacked in melee, hit or miss, the intruder tries to punch its attacker back if it survives, paying the punch's AP (with surcharges); no AP, no counter (2026-11-23). Targetable by Punch, Attack and Throw Out. Spawned only by tests and a dev cheat; players in the room see kind and HP; death removes it with a public log line. Not decided: the intruder's numbers (placeholders), damage to hostiles from weapon outcome side effects, natural spawning, and how the client shows them.
- **Activity overload** (2026-11-22, owner, [#241](https://github.com/nearbear/mush2/issues/241), superseding the wiki formula adopted for [#263](https://github.com/nearbear/mush2/issues/263)): eMush's `DifficultyService` multiplier, applied to both hunter and incident points each cycle change. Threshold = 7 AP × the ship's seats (`config.preselection.seats`, 16; everyone aboard without a pre-selection). At or under it, × living players ÷ seats (the dead don't count, unlike eMush); above it, × AP spent today ÷ threshold; rounded. The count is the crew's AP since the day began, server-only, reset after the new day's first cycle change (which still uses the full day, as eMush); an action paid with a skill point counts the AP it would have cost (the wiki's rule; eMush counts only real AP).
- **Private HP change logs** (2026-11-22, owner; built): every non-zero HP loss or gain (`damage` and `heal` in `shared/src/death.ts`) writes a private `loseHp` or `gainHp` log line to the affected player with the actual HP lost/gained, whether the player survives or not (`loseHp` precedes `died`). Existing caller-specific lines that also mention HP are left as-is for now.
- **Stat caps on a role change** (2026-11-22, owner, [#267](https://github.com/nearbear/mush2/issues/267)): a Mush's diseases don't change their caps, so every role change recomputes max AP, MP, HP and morale (`updateMaxValues`). A sick human turned Mush (conversion or selection) gets back what their diseases took; a sick Mush made human (serum, role cheat) loses it again, with current values lowered to the new cap. Current HP and morale don't rise.
- **Gravity Simulator restart, alert and no-gravity effects** (2026-11-22, owner; eMush's `NO_GRAVITY` and `NO_GRAVITY_REPAIRED`; built in `shared` and the web client's alert popover). Any repair (Repair or a drone) clears broken, but gravity restarts until the next cycle change: each AP-to-MP conversion still gives `config.gravitySimulator.brokenMpPenalty` less MP, the cycle-change gain doesn't (the restart ends at that cycle change); breaking it again ends the restart and the ordinary broken penalty applies. When the restart ends, NERON posts `gravityRestarted` (eMush's `RESTART_GRAVITY`) in global chat. While gravity is down (broken or restarting) a heavy item adds no MP to moves, and a tremor uses the no-gravity line (`tremorNoGravity`; same damage); the ordinary tremor line becomes eMush's longer one. The restart shows on the alert bar (icon `simulator.png`, eMush's `gravity_reboot` text). The simulator is never reported, since its broken state is public. A broken simulator gets its own alert row (eMush's `no_gravity`), shown the same way as the restart row (owner, 2026-11-22).
- **Expedition Disease event** (2026-11-21, owner; eMushpedia's `Évènements`: "un équipier tombe malade"): in Forest, Swamp and Insects, one random member still with the crew, Mush included (carriers, as for the disease incident), picked among those who can still catch one, gets a random disease from `config.diseases.expeditionDiseases` that they lack; a Hygienist resists 50% silently (`addDisease`). If nobody can catch one, the event is Nothing. The report line is anonymous: it names neither the member nor the disease. Fight diseases (owner, 2026-11-21): after a lost fight, each member still with the crew has 5% (`expedition.combatDiseaseChance`) to catch a random disease from `expeditionCombatDiseases` they lack (Mush as carriers, Hygienist resists). Claude's defaults, not asked: members killed by the fight don't roll, and nothing in the report shows it.
- **Boarded crew stay in the Icarus Bay until takeoff** ([#469](https://github.com/nearbear/mush2/issues/469), 2026-11-21, owner; built). Boarding no longer moves you into the Icarus's craft room: you stay in the bay with `boardedIcarus` (public to the bay) until takeoff moves the crew in, so nobody can duck into the docked Icarus to become untargetable. The boarded player still sees the Icarus panel. A public aggressive action aimed at someone boarded (punch, attack, interrogate...) puts them off the Icarus, succeeded or not, with a public line, "like getting up from bed when punched". Walking out, being thrown out and dying also clear it. A Guardian in the bay does **not** block boarding (being targetable is enough). Dropping while boarded is **allowed** (items land on the bay floor). Claude's readings: covert or private aggressive actions (Spike, Demoralize, Body transfer) don't put the victim off, since that would give them away; only an action naming the boarded player as its target counts (not an area weapon).
- **Crew bar and who Mush know** (2026-11-21, owner; built). A bar of the original's 7x15 figures, one per seat: alive (`p_alive`), cryo (`p_cryo`, the seats still empty: `config.preselection.seats` minus the crew), dead (`p_dead`), and for Mush viewers only, living Mush (`p_mush`) and dead Mush (`p_deadmush`). Mush (alive or dead) learn which other players are Mush, living or dead, through `OtherPlayerView.mush`; humans never get the flag and see every living crewmate as alive and every corpse as dead. Grouped in that order, with a popover of each group's count and characters. Desktop top bar, ship zone; phones, the ship card. Not asked: whether a dead Mush viewer keeps the flag (built: yes, as they keep the Mush channel).
- **Dead Mush research requirement (`deadMush`)** (2026-11-21, owner; built): `MUSHOPHAGE_BACTERIA`, `FUNGUS_SCRAMBLER`, `PATULINE_SCRAMBLER`, `MUSH_BREEDS`, and `MUSH_BREEDING_SYSTEM` require a dead Mush aboard (`hasMushDied`, matching the Sick Bay cryo tank; stays met even if the corpse is jettisoned or traded), replacing `postSelection` on those five researches (`PHEROMODEM` and `ANTI_MUSH_SERUM` keep `postSelection`).
- **Board and Take off show disabled when no expedition can launch** (2026-11-19, owner, `docs/scratchpad/bot-survival-plan.md` Run A; built). On a planet with every sector explored, or once the Icarus is lost, Board the Icarus (in the bay) and Take off (aboard, for someone who can fly) stay as disabled buttons with the reason ("explored", "Icarus lost") instead of disappearing, following the owner's preference for disabled buttons over hidden ones. Only someone in the Icarus Bay (or aboard) sees them. Other refusals (away, full, no spacesuit, out of orbit, can't fly) still hide the button.

- **The iTrackie is a private item** (2026-11-18, owner; built 2026-11-25). An iTrackie can still be dropped, but only its owner can see it or pick it up: to everyone else it isn't in the room. The owner is the body, not the player: in a Transfer each iTrackie stays with its body's inventory, as everything else does. Dropping or picking up your own iTrackie is a private action, as in eMush. Since nobody else can see it and it can't break, no other player and no room-wide effect can affect it. It can't change hands, which is why a Radio Pirate hack can sit on the target's iTrackie (see "Radio Pirate, reworked"). Supersedes "can be dropped or taken" in the iTrackie entry (2026-10-13). **Edge cases (2026-11-25, owner):** nothing at all can be dropped (or hidden) in a patrol ship in flight, so a wrecked patrol ship never scatters an iTrackie as debris for someone else to collect; the expedition's "lost item" event can still destroy a carried iTrackie, as today. My readings, not asked: an iTrackie of a dead body is destroyed wherever it lies (nobody else could ever see it again); one on a floor in a game stored before this change stays public.
- **Radio Pirate, reworked** (2026-11-18, owner; the owner's proposal from a player discussion of 2026-10-16, revised; not built; reasoning in `docs/plans/balance-review.md`, "Radio Pirate rework"). A Mush skill action at the Communication center terminal, so it suits the front-of-ship Mush (Paola, Frieda) who have a reason to be there. 3 AP, private, once a day per hacker. It has no `spore` tag, so myco alarms don't ring (this removes Radio pirate from the Myco alarms list below). Any other player can be targeted, anywhere on the ship, Mush teammates included. A hacker holds one hack at a time; a new hack ends the old one. While a hack lasts, the hacker reads the target's channels **forward only** (messages posted after the hack, never earlier history), including private channels, and can post as the target in every channel the target can post in: global chat, every feature thread, threads, and private channels. Spoofed messages show to everyone in the channel except the target. The target is never silenced, the hacker's own iTrackie works as usual, and no one is told a hack happened. The hack sits on the target's iTrackie. **No time limit:** a hack lasts until the target's **factory reset**, the hacker's next hack, the hacker's death, the target's death, or the hacker using Transfer. The factory reset is an iTrackie action, 1 AP, that removes any hack. It always gives the resetter a private log line that never says whether there was a hack, and when it removes one, it gives the hacker a private log line saying the hack was lost. Dropped from the 2026-10-16 proposal: reading chat history, MycoAlarm detection, and every change to private channels (invites, locked channels). Rejected: a time limit (3 AP for 4 cycles is too expensive; 8 cycles is a 3 AP daily upkeep). To watch in real games: a "confirm every order" ritual against spoofs (`balance-review.md`, "No rituals"), and hubs such as Chun resetting every day. The hacker's Transfer ends the hack even though Mush skills move with the mind (see "Transfer (Mush skill)"), which also settles a Transfer into the hacked target. An iTrackie can't change hands (see "The iTrackie is a private item").
- **Food spoilage** (2026-11-18, owner, following eMush): perishable food (coffee, cooked rations, alien steaks, bananas, alien fruits; not raw rations or drugs) goes one stage further at each day change, carried or on a floor: unstable, hazardous, decomposing (the last). Eating hazardous food gives Food Poisoning at 50%, decomposing at 90%, unstable never. A Mush rolls too and carries it, like a fruit's diseases (not eMush's immunity). Only living Chefs see the stage (eMush's status visibility; the wiki also says Botanists). NERON's Foodstuff destruction BIOS option is deferred to [#461](https://github.com/nearbear/mush2/issues/461).
- **Alien steak & Hyperfreeze** (2026-11-18, owner): `alien_steak` is added as a perishable expedition loot item (`expedition.loot.provision`, replacing the `uncooked_ration` placeholder; +4 AP, +4 satiety, -1 morale, cooks into `cooked_ration`). With a reachable working `freezer` (carried or on the floor), `hyperfreeze` costs 1 AP (or 0 AP + 1 Cook point, like `cook`) and turns a reachable `cooked_ration` or `alien_steak` into `uncooked_ration` in place, clearing Fungal Cuisine spores and keeping any existing spoilage stage (which stops advancing). Public room log.
- **Hard-boiled (Mush skill `tough`)** (2026-11-22, owner, following eMushpedia except the floor): takes 1 off each non-critical punch or weapon hit, not crits, instant kills or expedition fights; stacks with Plastenite Armor. **Floor of 1 for everyone:** armor and Hard-boiled, alone or together, never take a combat hit below 1 (`config.combatDamageFloor`), so no hit is fully absorbed; this also changes Plastenite Armor, including in expedition fights (owner chose this over a floor on Hard-boiled alone).
- **Plastenite Armor (`plastenite_armor`)** (2026-11-17, owner, following eMush and eMushpedia): an unbroken armor in the target's inventory absorbs 1 damage from a non-critical punch or weapon hit (targeted or area) and from each member's expedition fight damage; never below 0. Not crits, instant kills, self-damage, or non-combat damage (accidents, falls, fire, disease). Several armors absorb at most 1; broken armor does nothing. Stacks with Survival in fights. A fully absorbed punch or targeted weapon hit logs a public "…but only found their protections" line instead of the hit line.
- **Antigrav Scooter (`scooter`)** (2026-11-17, owner): works like Sprinter's movement bonus (+2 MP per AP-to-MP conversion, still capped), carried in inventory and not broken; does not stack with Sprinter or another scooter; no expedition sector bonus. Starts with 8 charges, spends 1 per conversion (0 when Sprinter already applies or when moving with existing MP), and recharges 1 per cycle up to 8.

## Phases

Each phase ends with typecheck and tests passing and a small commit. Phase headings note which open questions (now `rule-decision` issues) they wait on.

### Phase 1: rules core in `shared` (needs the infection, Sol, and death decisions)

- **Time as an input, not a clock read.** Add a `tick` that the server calls when a cycle boundary passes, for example `advanceCycles(state, n)`. The rules stay pure and tests can jump days instantly.
  - Tradeoff: the server owns real time and the rules only count cycles. That keeps rules deterministic, at the cost of the server having to compute how many cycles were missed after downtime.
- **Delete `ready`.** Cycles advance only on `tick`.
- **Player state additions:** HP, status effects (starting with `dirty`), spore count, and an inventory (minimal, only what the iTrackie needs).
- **Ship state:** spores extracted today (reset at each day boundary), the ship's position or Sol-return progress once the Sol trip is decided, and whether Mush have been selected yet.
- **Mush selection:** a separate step (`selectMush`, `shared/src/preselection.ts`, built 2026-10-24). It picks 1 or 2 Mush from the eligible players using the seeded RNG.
- **Actions:**
  - `extract_spore`: enforces the daily cap.
  - The infect action, once decided.
  - `hit`: decrements HP; at 0 HP the player dies.
  - The return-to-Sol action, once decided.
- **Win/end checks** after every action and tick. When the game ends, `phase: "ended"` records the winner.
- **Tests:**
  - Mush count is 1 vs 2 around the 8-player boundary.
  - The daily spore cap holds and resets on the day boundary.
  - Extracting a spore always applies `dirty`.
  - AP refills only on a tick, never by action.
  - Each win condition triggers correctly.
  - Determinism for a given seed.

### Phase 2: visibility and chat rules in `shared` (mostly built: global and private channels)

- **`viewFor`:**
  - A Mush sees the roles of the other Mush; everyone else still sees no roles.
  - Log entries get a scope: public, room, Mush-only, or private.
  - Tests check, for every seat, that a human's view has no roles except their own.
- **`say` action:** writes a room-scoped log entry and costs no AP (I'll assume no cost unless you say otherwise).
- **Global chat:** a separate message type allowed only for players holding an iTrackie.
- **Mush chat:** a channel filtered in `viewFor`, the same as the log scopes.

### Phase 3: server (needs the late-joiner and bot-seat decisions)

- **`GameRoom` timing:** use a Durable Object alarm for cycle ticks instead of `setTimeout`, so ticks survive restarts. On wake, apply any missed cycles.
- **Dev time scale:** an env var (for example `CYCLE_SECONDS=30` locally) so a "day" passes in minutes during testing.
- **Matchmaker:** 16 seats, plus the late-join behavior once decided.
- **Chat safety:**
  - A per-player chat rate limit.
  - A max message length.
  - A basic word-filter moderation hook, plain code with no new dependency to start.
  - A report/mute path deferred and noted.
- **Fix the known gap:** idle humans can no longer stall the game, because ticks ignore readiness.

### Phase 4: client

- Show HP, status effects, spores (Mush only), and the cycle countdown.
- A Mush chat tab, shown only to Mush.
- Still plain DOM, still driven only by `PlayerView`.

### Phase 5: local model bots

- **Recommendation:** run a local OpenAI-compatible server, either **Ollama** (easiest) or **llama.cpp's `llama-server`** (lighter, more control), with a ~4B instruct model at Q4 quantization.
  - On 8 GB VRAM that leaves room for long prompts.
  - An ~8B Q4 model also fits but is tight.
  - Check current model rankings when picking a specific model.
- **Bot interface:**
  - The model-backed bot speaks the OpenAI chat-completions format, with base URL, model name, and key in `.dev.vars`.
  - Switching later to a cheap hosted API, or to Triton (which also offers an OpenAI-compatible frontend), is then a config change, not a code change.
  - When you want a cheap hosted fallback, compare current per-token prices; I have no live pricing.
- **Fits the cycle structure:** cycles last hours, so bots can queue requests one at a time and the single GPU is never a bottleneck.
- **Safeguards:**
  - The bot must pick from the legal actions in its view (`legalIn(view)`). Any invalid output falls back to the scripted bot.
  - Player chat goes into the prompt marked as untrusted quoted text.
  - A per-game request cap.
  - The "hard spend cap" becomes a token/request budget, kept so it still works if you switch to a hosted API.
- **Dependency note:** Ollama or llama.cpp is a system install, not an npm package. I'll ask before installing either.
- **Public access later:** running everything on your machine is fine for development. When the game goes public, either deploy the game server to Cloudflare and keep only the model local, or expose your machine through a tunnel. Decide this at deploy time.
