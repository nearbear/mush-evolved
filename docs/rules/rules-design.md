# Rules design: decisions and phased plan (written 2026-10-05, pruned 2026-10-13)

> **Bots (decided 2026-10-13):** multiplayer has no bots. They exist only in a single-player mode (stage not decided) and as test tooling. Wherever these docs describe bots filling seats in a live game, that no longer applies.

The record of answered rule decisions and the design for the rules that are not built yet. Open questions live in GitHub issues labeled `rule-decision`, not here. Scheduled plans have their own document, `docs/plans/action-plans.md`, whose executor was dropped on 2026-10-30 for channel plans with on-call summons (`docs/plans/on-call.md`) and pooled relay tokens (`docs/plans/relay-tokens.md`).

**Status (2026-10-13):** built are AP, MP, HP and morale values, the action registry, inventory, the iTrackie, global chat, and private channels. Not built: infection, spores, the attack, win conditions, the cycle timer, and the phases below.

## Decisions received

- **Sinus Storm, Migraine, Slight Nausea, Food Poisoning** (2026-11-15, owner): effects and durations as listed in `implemented-rules.md`. Sinus Storm's "30% less accuracy when piloting" is a patrol ship's shot ×0.7; Migraine's "-2% when relaying" is −2 on each relay contribution's base (research, NERON projects, PILGRED); Food Poisoning's "unable to eat" blocks food and drugs; none of the four joins the alien-fruit disease pool.
- **Nimble Fingers (`nimble_fingers`)** (2026-11-14, owner): lets a living Mush with `nimble_fingers` enter (`enter_nimble`) and exit (`exit_nimble`) Nimble mode for 0 AP, instant, with a private log (`enteredNimble` / `exitedNimble`) and a private `nimble` status (`STATUS_PUBLIC.nimble = false`, never sent to other players). Stays active until the player exits it, dies, resets Mush skills, or transfers bodies. While in Nimble mode, all room-level `logPublic` calls during the actor's actions (including `move`'s `left` and `entered` lines) become `logSecretIn` for that actor in that room: hidden when moving between or acting in rooms with no living witnesses or working cameras, and revealed as `secret` (`leaked: true`) when witnessed or filmed. Ship-wide public logs (`room === undefined`: `travel`, `leave_orbit`, `return_to_sol`) stay ship-wide public.

- **Meridon scrambler (`FUNGUS_SCRAMBLER`)** (2026-11-14, owner): once complete, whenever a hunter selects a new target (`pickTarget` in `hunters.ts`, including `retargetNow`), it has a `config.hunters.meridonScramblerChance` (20%) chance to target a random other shooting hunter (`actions > 0`, excluding self and asteroids), falling back to normal targeting if none exist. Shooting a teammate rolls `hitChance` and `damage` through `damageHunter` (respecting D1000 armor and dropping debris on kill), then clears `target = null` so it picks a new target on its next action. If a targeted teammate is already destroyed before this hunter's turn, it clears `target` and spends that action picking a new target. Friendly fire is silent (no log entry; crew sees hunter count / HP change in battle list). Marked `"full"` in `RESEARCH_STATUS`; en/fr/es `FUNGUS_SCRAMBLER` descriptions updated to say "when selecting a new target".

- **Frugivore (`frugivore`)** (2026-11-14, owner): English display name renamed from Fruitarian to Frugivore. Grants humans +1 extra AP (`config.frugivore.bananaAp`) when eating a banana and +2 extra AP (`config.frugivore.alienFruitAp`) when eating an alien fruit, capped at `maxAp`, with no other effect (no fruit lore, does not apply to Mush).

- **Auxiliary terminals (`AUXILIARY_TERMINAL`)** (2026-11-14, owner): the two auxiliary NERON terminals (`SICK_BAY:neron_sick` and `MOTOR_ROOM:neron_engine`) stay completely offline until `AUXILIARY_TERMINAL` is complete — no `access`, `project`, `coup`, breakage, sabotage, green jelly, reinforce, or relay view (even with `freeHacking`), and they render as the static black-screen `auxiliary_terminal_neron` sprite. Once `AUXILIARY_TERMINAL` is complete, both work as NERON cores (including `coup`) and animate as `auxiliary_terminal_neron_upgrade_a` (or `_b` with `NERON_PROJECT_THREAD`).

- **Automatic sprinklers (`AUTO_WATERING`)** (2026-11-14, owner): once complete, each cycle change rolls `config.project.autoWatering.extinguishChance` (25%) per burning room with no daily cap, before fires act (spread/damage), including fires started on that same cycle. Extinguishing a fire posts NERON's global chat line (`fireExtinguishedSprinklers`) without the room name.

- **NERON participation (`NERON_PROJECT_THREAD`)** (2026-11-14, owner): once complete, each cycle change advances every currently offered project (`offeredProjects(state)`) strictly above 0% by `config.project.neronParticipation.percent` (5%). At most one project can complete per cycle (any other offered project that would reach 100% is capped at 99% before the batch retires from `projectDeck`). Emits a ship-wide public log (`neronProjectCompleted`) only when a project completes; silent otherwise.

- **Opportunist (`opportunist`)** (2026-11-14, owner): +5 AP (`config.opportunist.ap`, capped at `maxAp`) the first time a living player (human or Mush) gains each of the three ship titles (`commander`, `neron_admin`, `comms_officer`) while having the skill — including initial Mush-selection assignment (`issueTitles`), succession (`refreshTitles`), and Politician's coup (`coupCycle`). Does not trigger retroactively if picked while already holding a title. Private log line (`opportunistTitle`) to the player; `PlayerState.opportunistTitles` is never sent.

- **Antispore gas (`ANTISPORE_GAZ`)** (2026-11-14, owner): once complete, reduces the Mush daily spore extraction cap (`sporesPerDay`) by `config.spores.antisporeReduction` (2, from 4 to 2, clamped at 0). Standard `researchCompleted` public log line only.
- **Ultra-healing ointment (`HEALING_OINTMANT`)** (2026-11-14, owner): requires a `medikit` in the lab (not consumed). Once complete, both `heal` (Medikit / Sick Bay) and `use_bandage` restore `heal.effect.ointmentBonusHp` (1) extra HP for everyone (humans and Mush, stacking with `medic`). Standard `researchCompleted` public log line only.
- **Constipaspore serum (`CONSTIPASPORE_SERUM`)** (2026-11-14, owner): once complete, raises `extract_spore` cost by `config.spores.constipasporeExtraAp` (2 AP, from 1 to 3 AP). Fertile's first daily extraction still costs 0 AP (overrides the serum). Standard `researchCompleted` public log line only.
- **Chef (`cook`)** (2026-11-14, owner): grants +4 Cook (`cook`) points on pick and at each day start, held up to `config.cook.capPoints` (8). Alien fruit lore (`FRUIT_LORE_SKILLS`), the `FOOD_RETAILER` NERON project bonus, and Cook-point spending on `cook` (0 AP, `paidBy: "cook"`, not `fungal_cuisine`) were already wired.
- **Maintenance Agent** (2026-11-14, owner): grants +1 Engineer (`eng`), +1 Garden (`garden`), and +1 Cook (`cook`) point on pick and at each day start, sharing `config.engineer.capPoints` (2) and `config.botany.capPoints` (4), with `config.cook.capPoints` = 8. Cook points pay for `cook` only (0 AP, `paidBy: "cook"`), not `fungal_cuisine`.

- **Alien fruits** (2026-11-14, owner; backend built in [#437](https://github.com/nearbear/mush2/issues/437), client tooltips/art in [#438](https://github.com/nearbear/mush2/issues/438); replaces eMush's per-trait rolls, which leave most alien fruits worse than a banana). Goal: every alien plant is worth planting over a banana.
  - **Species and source**: the original's 12 alien species (its `Data.ods` Skins rows 1–12, icons `fruit01`–`fruit12`, Lianube to Filandru; `fruit00` is the banana and `fruit13`, Citrouïd, is the Halloween event fruit, left out), each species' traits fixed for the whole ship (seeded at creation). Expedition Harvest events drop a random alien fruit instead of bananas; the ship starts with none. Bananas are unchanged (+1 AP, +1 satiety, +1 morale, +1 HP, 36 cycles).
  - **Base**: every fruit gives 1 satiety and 1 AP, outside the budget.
  - **Value budget**: an alien species is worth 3–6 (grafts 4–9, later pass). A purely random fruit is generated, then the whole fruit is re-rolled until its value fits. Purely random: each single-slot category (AP, morale, health) picks one of its options or none with equal odds; diseases and specials each roll 0–3 distinct effects. A simulation fits about 35–38% of fruits, under 3 tries per species; generation should still cap its tries and fail loudly, with a test over many seeds.
  - **Effects and values**: AP, max 1: +1 AP (+2), +2 AP (+5). Morale, max 1: +1/+2/+3 (+1/+2/+3), −2 (−2). Health, max 1: +1/+2 HP (+1/+2). Special, max 3: Treat Disease, every disease loses 1 extra duration per cycle for 4 cycles (+2); Energize, AP-to-MP conversion gives 2 extra MP for 2 cycles (+1); Resistance, immune to spores for 2 cycles (+2); Perception, +10% relative success chance on every action for 2 cycles (+2). Re-eating a buff resets its timer; buffs don't stack.
  - **Diseases**, max 3: each has fixed odds per species (30–80%) and a delay rolled per meal (2–16 cycles). Listed costs: skin inflammation 2, extreme tinnitus 2, fungal infection 2, space rabies 3, gastroenteritis 3, smallpox 1, black bite 2, rejuvenation 1, acid reflux 1, Mush allergy 3, tapeworm 2. A disease's value is −max(1, round(cost × odds / 55%)). The pool of diseases a fruit can cause is its own config list (with each one's cost), separate from `config.diseases.allDiseases`; cold is never in it. Pass 1 rolls only listed diseases that exist in the code; the rest join the pool as #214 lands them.
  - **Grow time**: always shorter than a banana's, scaling with value: 4 cycles per point (value 3 → 12, 6 → 24; a graft capped at 32).
  - **Resistance vs. spores**: a spike on an immune player spends the spore and fails silently; neither the Mush nor the target is told.
  - **Mush eating**: as with every consumable, Mush get the fruit's morale (−2 included, per Hopeless above) and its satiety, but no AP, HP or buffs. They do catch the fruit's diseases, as carriers (owner, 2026-11-14, following #439: Mush carry and spread diseases but don't suffer from them): same odds and same 2–16 cycle delay as a human. A human converted while a fruit disease is pending still gets it on schedule.
  - **Visibility**: the Botanist role (Botanist and Skilful, a.k.a. Polyvalent, as for plant sickness), the Chef (the `cook` skill) and Mush see a species' effects, disease odds and grow time; everyone else sees only the species name. The Mush's tooltip flags it in danger text as information they wouldn't normally have.
  - **Grafting**, a later pass: a graft draws its effects randomly from both parents' effects, then fits to 4–9.

- **NERON project proposals, streak relay, and Unrestricted terminals** (2026-11-14, owner; built the same day; supersedes the "all open at once" and relay-token parts of **NERON projects** and **Relay tokens** below):
  - **Three-project proposals**: `createGame` shuffles `PROJECT_IDS` (`newProjectDeck(seed)`); NERON's core shows and offers only the first 3 unfinished projects (`config.project.offerCount: 3`). Completing one of the 3 via `project` permanently retires all 3 projects in that batch from `projectDeck` (never drawn again), and draws the next 3 unfinished projects. A Comms Center NERON update (`advanceNeron` at 100%) still draws uniformly from all unfinished projects (`PROJECT_IDS`); if it completes one of the 3 currently offered projects, only that project leaves `projectDeck` and 1 replacement fills the 3rd slot (the other 2 stay offered).
  - **No relay tokens on NERON projects (streak relay penalty kept)**: NERON projects drop the `RelayPool` token pool and keep the per-player repeat streak relay penalty (`RelayStreak` `{ lastBy, streak }`), rolling each contribution's progress directly (`[min, min + min/2]`, `−2` per consecutive repeat by the same player, skipped under `noRelayPenalty`). `PlayerView.yourTokens` omits `projects`, and `TerminalDialog` omits the relay-token help text on projects. Research and PILGRED keep relay tokens.
  - **Unrestricted terminals (`freeHacking`)**: keeps the internal `freeHacking` cheat id and renames the UI setting to "Unrestricted terminals" (fr "Terminaux sans restriction", es "Terminales sin restricciones"). Besides bypassing titles, it bypasses research requirements at the Research Lab (`researchNeedsMet`: items, Chun, post-selection) and shows/offers all unfinished `PROJECT_IDS` at NERON's core; if a cheat player completes a project inside the current batch of 3, that batch retires as normal, while completing one outside it removes only that project from `projectDeck`.
- **Premonition** (2026-11-13, owner; built the same day). The `premonition` skill grants the Premonition action: 1 morale, no AP, on any living crewmate anywhere, showing their most recent action as Interrogate does (name only; `historyNothing` if none). No daily limit; refused at 0 morale. My readings, not asked: the use is unlogged and not recorded in your own history (wiki "Action délogguée"), and the owner's "same as torture" was taken as the reveal only.
- **Magnetic net** (2026-11-12, owner; built the same day). Magnetic net (`MAGNETIC_NET`), not Magnetic return, saves patrol ships in flight when the Daedalus travels or leaves orbit: each docks in its bay at once with its pilot, always cleanly (no manoeuvre roll), as in the original. No NERON on/off switch: active once the project is done. Seen only as a normal landing (the secret line in the bay), nothing ship-wide. Floating debris is still lost. Magnetic return stays expedition-only (the Icarus and a patrol ship on a planet).
- **Jump warning** (2026-11-12, owner; built the same day). Travel and Leave orbit always open a confirm window with one static warning (patrol ships in flight, an expedition out, a rebel signal being decoded), whatever the ship's state. Prompted by a player suggestion for a first-time warning; the owner chose always, unconditional.
- **Hopeless: death at 0 morale** (2026-11-11, owner; built the same day; replaces the trauma and coping plan in `docs/scratchpad/mental-health.md`, which the owner set aside, as a stopgap until something better for wrong kills). A living player at 0 morale has the private status Hopeless (en Hopeless, fr Sans espoir, es Sin esperanza; the original's `demoralized` icon; its `suicidal` icon and the word are deliberately not used). Any morale gain ends it. When a cycle ends, every human still Hopeless dies; each such death costs every living player, Mush included, 1 morale (`config.hopeless.deathMorale`). Mush get the status but never die of it (owner: a Mush can lie about morale gains to cover having reached 0). Deaths resolve at the cycle's end, not at once, so a death's cost can push others to 0 only for the next cycle and a chain can't wipe the ship in one tick. **Mush get consumables' morale** (same day, owner): a banana's +1, a raw ration's −1 and a drug's morale effect apply to Mush exactly as to humans, so a Mush's morale follows a human's and they never have to track it (keeping morale tracking out of the game is an owner ideal); every other food and drug effect still doesn't. Exception to "no food effects" (2026-11-05). My readings, not asked: the status shows only in its holder's view; a human who reaches 0 at a cycle change (the daily loss) gets that whole next cycle; pre-selection included; the invincible and infiniteMorale cheats prevent it.
- **Fertile for every Mush** (2026-11-11, owner; not built; `docs/plans/balance-review.md` decision 5, after a player pointed out eMush's developers are considering the same). Every Mush, alpha and converted alike, has Fertile's effect without picking it: once per calendar day their first spore extraction costs 0 AP, still counting toward and blocked by the faction's daily cap and the holding limit. Fertile is removed from the Mush skill picker, freeing the slot it used to take. Supersedes the Fertile skill entry below (2026-10-27) for who gets it; the effect is unchanged, and the used-today flag still follows the mind in a Transfer.
- **NERON's priority is public** (2026-11-10, owner; not built). When the daily ship priority set by the NERON admin is built, the current priority is shown to everyone aboard: it can be inferred from progress amounts anyway. The rest of the priority (its values, effects and cost) is not decided here. Bots read it as a signal of the day's intent (`docs/plans/bot-goals.md`, "Direction").
- **Spore holding limit** (2026-11-10, owner; `docs/plans/balance-review.md` decision 8, built the same day). A Mush holds at most 2 spores (`config.spores.max`). At the limit `extract_spore` is shown disabled (capacity) and refused; spending one (spike, Phagocytosis, Fungal cuisine) frees a slot. The limit is per Mush, alongside the faction's daily cap.
- **Focused at a terminal** (2026-11-07, owner; [#192](https://github.com/nearbear/mush2/issues/192), built 2026-11-08). Sitting at a terminal shows a public status, **Focused** (a glasses icon). It is purely cosmetic: it tells roommates the person is looking at a screen, with no rule effect. The terminal position is a new `Spot` variant, `{ kind: "occupancy", equipment, chair? }`, set by the server; the owner ruled out the name "seat" (it already means a player's seat). Answered 2026-11-08: standing at a terminal (every chair taken, or none) **also** shows Focused. Opening the terminal's window (`access`) takes the spot; **closing the window ends it** (so a private action elsewhere can't give anything away: the window is closed first), as do walking off and moving. If a seated person leaves while you stand there, you don't take the seat. Clicking a chair stays as it was (a `walk` with `sitting`), but someone sitting on a terminal's chair that way has it. Which chairs belong to which terminal: the bridge's three (Com center, Command, Astro), the lab's, and each turret room's seat; the sick bay's chairs stay plain chairs. The pilot's and the turrets' seats, under their consoles' footprints, are made sittable (owner, 2026-11-08): you climb into them from the nearest floor.
- **Guard and Guardian** (2026-11-06, owner). `guard` costs 1 AP, is aggressive, and grants the public `guardian` status. A guardian blocks everyone else in the room: they may only leave by the door they came in by; anyone who arrived another way (landing a patrol ship, waking from cryo) can use no door. The guardian leaves freely, and leaving, being moved or dying ends the status. `stop_guarding` is free. Several guardians in one room: owner said not applicable (each blocked person simply follows their own entry door).

- **Balance direction: food, Phagocytosis, Return to Sol and the List** (2026-11-04/05, owner; `docs/plans/balance.md`). Mush gain no AP from any consumable, no exceptions (rations, coffee, bananas; already how `consume` works). Rations, cooked or not, give humans 4 AP, 5 with Sirius (built 2026-11-05). Mush get the same full belly as humans so eating isn't a test (owner, separate change). Phagocytosis stays as built (0 AP and 1 spore for +4 AP, +4 HP). Return to Sol with a living Mush stays a Mush win, as the counterweight to a PILGRED rush: investigators keep PILGRED from being repaired while Mush may be alive. The List (Tracker) will be built as in eMush. Owner, 2026-11-05: rations running out is an intended late-game clock on humans (expeditions and plants will offset it later); someone who never takes food ought to raise suspicion, and Mush may eat rations to blend in (both by design); the stealth target is that passive Mush win clearly less often than active Mush; barring Phagocytosis AP from PILGRED is rejected for good. Eden as a human win with Mush alive is a proposal only (`balance.md`, open questions). The owner's preferred direction (2026-11-05, not rules): Eden as the final clock with non-combat sabotage points, space boarders, anti-passive research, and the PILGRED question for the sneaky Sol; PvE is not to be made harder as a fix for passive Mush (`balance.md`, "Preferred direction").
- **Design pillars from the balance Q&A** (2026-11-05, owner; `docs/plans/balance.md`). (1) No mechanic may prove someone human unless it is designed to: Chun, and a serum injection (the target is human afterwards); anything else that incidentally proves humanity, or Mushness, is a design bug. (2) Converts are fully Mush: they win when the Mush win and get Mush credit on the end screen and in stats. (3) Ghosts spectate only: never any interaction or communication with the living, and they may leave at any time (amends the Ghosts entry under Death). (4) Out-of-game coordination is against the rules, no exceptions. (5) The Mush time-of-day advantage is accepted. (6) Inactive players will be tradable to merchant ships, compensating the AFK penalty (details open, #143). (7) NERON kills everyone the moment living Mush strictly outnumber living humans (3 of 4, 3 of 5, 4 of 6; 2 of 4 does not), at any point in the game; it is a Mush win, like all humans dead. Not built.

- **Room log window, Tracker** (2026-11-05, owner; #365; eMushpedia "Traqueur"; built 2026-11-05, `log.ts`): a seat sees the room log for the last 8 cycles, counted in whole cycles from each entry's `cycle`, never to the minute. It is a number of cycles, not hours: a game with 1-hour cycles shows 8 hours (so not `cyclesPerDay`). The Tracker skill (Eleesha's; any character can hold it, since books teach any skill) sees 16 cycles. The window covers every room line, private ones (your own actions) included. Ship-wide lines (no `room`: cycle and day starts) are not windowed: they are NERON's lines, part of global chat. The window applies only to the room log: **chat has no window** (every message stays reachable, #355 stands). A replay's all-seeing mode shows every log line and message up to the step, with no window, paged. Tracker's other effects on the wiki (where people came from and went to, which ships took off and landed, the List, the expedition effect) are separate and not part of this decision. "8 cycles" is the current cycle plus the 7 before it (an entry shows while `entry.cycle > state.cycle - 8`); 16 likewise. **Pruning** (owner, 2026-11-05): the rules drop room lines older than the longest window any rule needs (16 cycles) and keep ship-wide lines, so the live state, the snapshot and each view stop growing with the game. Every line stays in the record (each input's history step) and so in the replay. This replaces storing the log outside the snapshot (#281 step 2, dropped). The client spots new lines from a per-viewer count of every line that seat has ever seen (owner, 2026-11-05).
- **Log line kind** (2026-11-05, owner; #366; built 2026-11-08, live UI 2026-11-08): each log entry will record its kind (public, private, secret, covert) and, for secret and covert, whether it leaked (reached anyone besides the actor), as part of the view. The live room log shows a badge per kind (built 2026-11-08); the replay viewer shows a badge for each of private, secret and covert. Live players see it too (owner, 2026-11-05): the kind of every line they see, so a witness learns that a line was covert but was made public by a camera. The UI will later give those a sense of danger (covert ones are usually malicious, secret ones sometimes innocent). Answered 2026-11-08 (owner): the kind comes from the log writer, not the action type; an Outcast's secret or covert line is leaked and nothing else (no warning level).

- **Fire Detectors project** (2026-11-02, user; eMushpedia "Détecteur d'incendies"): completing `FIRE_SENSOR` research reveals all burning rooms on the Daedalus in `PlayerView.burningRooms` to all living players, turning burning rooms red on the minimap even if nobody is inside; inspecting a burning room on the minimap displays a flame icon and an "On fire" indicator in the caption. Before completion, fires are not displayed on the minimap (even for your own room). Dead players receive no burning rooms. Marked "full" in `PROJECT_STATUS`.
- **Reports and the alert bar** (2026-11-14, owner; [#444](https://github.com/nearbear/mush2/issues/444), split from #264; built 2026-11-14). Players report fires and broken equipment in their own room: free (0 AP), instantaneous, always succeeds, Mush included. False reports are impossible (only a real, unreported problem can be reported). A report lasts until the problem is fixed, then clears itself; a relit fire or a re-broken piece starts unreported. Reports and detectors are one system: Fire detectors (`FIRE_SENSOR`) reports every fire and the Anomaly detector (`EQUIPMENT_SENSOR`) every broken piece of equipment, so nobody needs to report those once complete. The alert bar counts every fire and broken piece of equipment, reported or not, but locates only reported ones (eMush's way; silent sabotage shows as an unexplained +1, accepted). A reported breakdown names the equipment and the room. A player's report also posts a NERON line in global chat with the reporter and room (and equipment); detectors add no line. The minimap turns a room red for any reported fire, by a player or by Fire detectors; breakdowns show only on the alert bar. Items are not reportable. Doors became reportable on 2026-11-14 (see **Doors** below).
- **Doors** (2026-11-14, owner; [#330](https://github.com/nearbear/mush2/issues/330); slice 1, the door model and blocking, built 2026-11-14). A door is its own object joining two rooms, with a broken state; it isn't equipment of either room. A broken door blocks movement through it for everyone. Repair works on a door from either side: base chance 25% (also eMush's door config, `repair_percent_25`), with the usual wrench and Technician factors. Both rooms it joins see that it is broken, and it can be reported to the alert bar like broken equipment. **Doorman** (Mush skill; amended 2026-11-14, owner): a door sabotage that breaks a working door of the player's room, chosen by the player (eMush picks one at random). The first use each day is free, later ones cost 2 AP. Covert. Without Doorman, doors can't be sabotaged (eMush: the door's action list has repair but no sabotage). Only the Defective piston sensors project (`DOOR_SENSOR`) reports broken doors automatically; the Anomaly detector (`EQUIPMENT_SENSOR`) doesn't. Once `DOOR_SENSOR` is complete, the minimap shows broken doors in a danger yellow; before that it doesn't show them. Sensor support drones go to broken doors and repair them. Answered 2026-11-14 (owner): Doorman's door sabotage always succeeds. Before `DOOR_SENSOR`, the alert bar still counts an unreported broken door (an unexplained +1, like silent sabotage) and locates it only once reported. With `DOOR_SENSOR` complete, every living player aboard, human or Mush, sees broken doors in yellow on the minimap. Sensor drones repair doors with their usual roll at the door's 25%, and doors rank with broken equipment (nearest first). The stuck door incident, decided under **Incident points**, is part of the same work.

- **Hunters and space combat, first pass** (2026-10-24, owner, #208; numbers from eMush's source, `Api/src/Hunter/` and `Game/Service/DifficultyService.php`, and eMushpedia's *Chasse aux hunters*, *Tourelle* and *Armure et Bouclier*). With one, it rolls to hit: 80%, +10 after each miss, back to 80 after a hit. A hit does 2, 3 or 4 (equally likely) through `damageShip`, and the hunter then has to pick a target again, so a hunter hits at most every other cycle. Dodge isn't used, neither by hunters nor against them.

Anyone alive can shoot, Mush and dirty players included. The combat skills' effects are decided below (Combat skills, 2026-10-25). ## Phases

Each phase ends with typecheck and tests passing and a small commit. Phase headings note which open questions (now `rule-decision` issues) they wait on.

### Phase 1: rules core in `shared` (needs the infection, Sol, and death decisions)

- **Time as an input, not a clock read.** Add a `tick` that the server calls when a cycle boundary passes, for example `advanceCycles(state, n)`. The rules stay pure and tests can jump days instantly.
  - Tradeoff: the server owns real time and the rules only count cycles. That keeps rules deterministic, at the cost of the server having to compute how many cycles were missed after downtime.
- **Delete `ready`.** Cycles advance only on `tick`.
- **Player state additions:** HP, status effects (starting with `dirty`), spore count, and an inventory (minimal, only what the iTrackie needs).
- **Ship state:** spores extracted today (reset at each day boundary), the ship's position or Sol-return progress once the Sol trip is decided, and whether Mush have been selected yet.
- **Mush selection:** a separate step (`selectMush`, `shared/src/preselection.ts`, built 2026-10-24). It picks 1 or 2 Mush from the eligible players using the seeded RNG.
- **Actions:**
  - `extract_spore`: enforces the daily cap.
  - The infect action, once decided.
  - `hit`: decrements HP; at 0 HP the player dies.
  - The return-to-Sol action, once decided.
- **Win/end checks** after every action and tick. When the game ends, `phase: "ended"` records the winner.
- **Tests:**
  - Mush count is 1 vs 2 around the 8-player boundary.
  - The daily spore cap holds and resets on the day boundary.
  - Extracting a spore always applies `dirty`.
  - AP refills only on a tick, never by action.
  - Each win condition triggers correctly.
  - Determinism for a given seed.

### Phase 2: visibility and chat rules in `shared` (mostly built: global and private channels)

- **`viewFor`:**
  - A Mush sees the roles of the other Mush; everyone else still sees no roles.
  - Log entries get a scope: public, room, Mush-only, or private.
  - Tests check, for every seat, that a human's view has no roles except their own.
- **`say` action:** writes a room-scoped log entry and costs no AP (I'll assume no cost unless you say otherwise).
- **Global chat:** a separate message type allowed only for players holding an iTrackie.
- **Mush chat:** a channel filtered in `viewFor`, the same as the log scopes.

### Phase 3: server (needs the late-joiner and bot-seat decisions)

- **`GameRoom` timing:** use a Durable Object alarm for cycle ticks instead of `setTimeout`, so ticks survive restarts. On wake, apply any missed cycles.
- **Dev time scale:** an env var (for example `CYCLE_SECONDS=30` locally) so a "day" passes in minutes during testing.
- **Matchmaker:** 16 seats, plus the late-join behavior once decided.
- **Chat safety:**
  - A per-player chat rate limit.
  - A max message length.
  - A basic word-filter moderation hook, plain code with no new dependency to start.
  - A report/mute path deferred and noted.
- **Fix the known gap:** idle humans can no longer stall the game, because ticks ignore readiness.

### Phase 4: client

- Show HP, status effects, spores (Mush only), and the cycle countdown.
- A Mush chat tab, shown only to Mush.
- Still plain DOM, still driven only by `PlayerView`.

### Phase 5: local model bots

- **Recommendation:** run a local OpenAI-compatible server, either **Ollama** (easiest) or **llama.cpp's `llama-server`** (lighter, more control), with a ~4B instruct model at Q4 quantization.
  - On 8 GB VRAM that leaves room for long prompts.
  - An ~8B Q4 model also fits but is tight.
  - Check current model rankings when picking a specific model.
- **Bot interface:**
  - The model-backed bot speaks the OpenAI chat-completions format, with base URL, model name, and key in `.dev.vars`.
  - Switching later to a cheap hosted API, or to Triton (which also offers an OpenAI-compatible frontend), is then a config change, not a code change.
  - When you want a cheap hosted fallback, compare current per-token prices; I have no live pricing.
- **Fits the cycle structure:** cycles last hours, so bots can queue requests one at a time and the single GPU is never a bottleneck.
- **Safeguards:**
  - The bot must pick from the legal actions in its view (`legalIn(view)`). Any invalid output falls back to the scripted bot.
  - Player chat goes into the prompt marked as untrusted quoted text.
  - A per-game request cap.
  - The "hard spend cap" becomes a token/request budget, kept so it still works if you switch to a hosted API.
- **Dependency note:** Ollama or llama.cpp is a system install, not an npm package. I'll ask before installing either.
- **Public access later:** running everything on your machine is fine for development. When the game goes public, either deploy the game server to Cloudflare and keep only the model local, or expose your machine through a tunnel. Decide this at deploy time.
